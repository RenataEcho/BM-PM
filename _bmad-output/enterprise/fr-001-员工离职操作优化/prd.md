# Document Purpose
本次只适配企业号“员工离职操作优化”的需求交付 Demo。FR-1 等为本需求内部条目；全局号为 FR-001。主文件：fr-enterprise-001-leaving.html。来源为用户提供的 employee-management/messages.html#all；保留原离职交互与协议措辞。

# Vision
企业主有明确发起确认，员工主动确认或拒绝，双端均可查看处理结果。

# Target User
JTBD：企业主处理员工离职，员工了解关系解除的影响并表达意愿。
Non-Users：本 Demo 不覆盖平台管理员后台操作。
UJ：员工管理 → 权限管理 → 发起确认 → 员工消息 → 确认或拒绝 → 双端结果。

# Glossary
企业关联：当前员工与企业在平台内的关联。在职：待确认期间保持的现有状态。待确认：申请已发送、员工尚未处理。确认：员工主动同意解除关联。拒绝：申请结束、关联保留。

# Features
## FR-1 发起离职
关闭管理权限仅修改表单，保存后需勾选授权与协议。Consequences：未勾选不能发送，取消保持关联，发送后转待确认。
## FR-2 员工处理
风险已读与自愿确认双勾选后可确认；拒绝原因选填，最多 200 字。Consequences：确认成功后解除关联；拒绝或暂不处理不解绑。
## FR-3 双端通知
申请与处理结果分别通知企业主、员工，查看后标记已读。Consequences：两端能查看状态；旧通知不能处理新申请。
## FR-4 交付台
前端交互含 12 个可切换场景；需求规则以独立 overlay 抽屉分前端 / 后台；路径图置于业务流程 Tab。Consequences：总览与侧栏内嵌打开，深链 fe / flow 可用，不依赖外部演示站。
