# 附录：接口与同步方式

这些是用户在发现阶段直接说出的做法，留给后续架构和实现。PRD 正文只写后台办得到什么。

- 社群「同步飞书信息」：根据飞书机器人归属的群，用社群名称与现有社群一对一同步。
- 人员「批量入群」：通过接口，把还未拉进飞书群的人员拉进飞书群。
- 导师「同步飞书信息」：通过接口同步该导师在飞书的社群信息。
- 「飞书社群人数」是机器人同步回来的飞书社群成员数量。
- 「该导师群内身份」是机器人拉回来的群内身份，用户举例为群主、管理员。

名称怎么算配上、入群拉进哪一个飞书群、失败时保留上次结果，已定为 `prd.md` 第 4.1 至 4.3 节的规则。迭代页的管理后台页签按这三个模块列文案，不实现可点后台。

## 社群页画面参照

当前锁定验收页为 `demo/iteration/fr-coco-002-mentor-v1-2-fe.html`。产品文档、UX、外壳规则与后续维护均以该文件当前结构为准，不得用历史过程稿反向删除或重排已经定稿的模块。

- 用户视角默认从「我的社群」列表开始。列表不提供搜索和筛选；卡片展示已加入天数，以及负责人、所属导师团、绑定导师、绑定时间，不展示成员数、绑定状态和审核信息。审核进度只在申请记录查看。列表不提供解绑或换绑。换绑在社群详情底部发起。列表和社群详情都不展示成员数。
- 社群详情顶部为浅粉头图：居中图标与「免费」或「付费」角标、名称、已加入天数，以及标签「导师团服务中」「项目交流社区」。社群介绍写在标签下方并完整展示，可「展开全部介绍」补上其余正文，或「收起」。其下是社群负责导师、浅暖色「所属导师团」卡片、负责项目、社群战绩、收益荣誉榜和底部「换绑」「对接社群」。不展示成立时间、社群成员数和社群公告，不另起社群介绍分区。对接社群从底部打开二维码浮层。
- 所属导师团不放进单个导师卡片；列表卡片与详情里社群负责导师下方的卡片都进入同一导师团主页。
- 导师团主页保留深色 Hero、三个服务数据、可展开介绍、导师团负责人和分层成员。
- 项目与飞书在 Demo 中只打开说明浮层，不连接真实详情页或飞书；导师资料和导师团成员资料也以浮层演示。社群详情不提供公告入口和公告浮层。

## 2026-11-02 规则边界

- 正式实现中社群战绩与收益荣誉榜是两个模块，可由后端分别控制；锁定 Demo 固定展示两者的完整示例，不提供显隐切换。
- 收益荣誉榜在锁定 Demo 中展示「本月收益 TOP 5」，第一名重点展示，其余四名使用紧凑排行。
- 导师个人信息页支持修改头像和昵称；正式实现保存后由接口结果更新使用该导师资料的页面，锁定 Demo 不演示跨视角同步。

## 2026-11-06 导师团边界

- 「所属导师团」是社群级关系；一个社群同一时间最多关联一个当前有效导师团。
- 入口位于「我的社群」列表卡片的所属导师团字段，以及社群详情里社群负责导师下方，不位于导师卡片，也不从导师个人的其他组织归属推导。
- 导师团主页是成员侧只读页面。本次不设计导师团创建、编辑、删除、导师归属、社群关联或赛道配置后台。

## 静态 Demo 边界

- 锁定 Demo 只覆盖完整有数据示例，不承诺加载、失败、缺失、异常或空数据场景。
- 导师视角配置页演示头像预览、昵称与个人介绍编辑、保存中防重复和保存成功提示；不改写锁定的用户视角示例内容，不持久化。
- `reconcile-*`、`review-*`、`.memlog.md` 与 `plan-*` 只记录历史过程，不作为当前产品合同或发布资产。
