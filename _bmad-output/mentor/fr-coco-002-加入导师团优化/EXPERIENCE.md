# EXPERIENCE · 加入导师团优化

产品规则以 `prd.md` v2 为基线，视觉以同目录 `DESIGN.md` 为准。锁定验收页 `demo/iteration/fr-coco-002-mentor-v1-2-fe.html` 优先于本文件；如有差异，修改文档，不修改锁定页。

## Foundation

- **Form-factor**：桌面迭代页左侧展示规则，右侧嵌入移动端页面。
- **UI system**：手机沿用 `docs/design/移动端设计规范.md`。手机框外沿用 `docs/design/iteration-shell/`。
- 已加入成员称阿宁。后台规则的读者称林林。导师视角是导师本人编辑个人资料。用户视角、导师视角与管理后台三条路径不在同一张手机画面上交叉。
- 用户视角导航栈是「我的社群」列表 → 社群详情，以及列表 / 详情 → 导师团主页。
- 打开 `demo/iteration/fr-coco-002-mentor-v1-2.html?tab=fe` 默认是「我的社群」。顶部按场景切换「我的社群」「社群详情」「导师团」「申请记录」，并保留「导师视角」。切换后左侧规则和右侧页面一起变。`?tab=admin` 打开后台规则。`?tab=flow` 打开换绑流程图。

## Component Patterns

行为如下。样子见 `DESIGN.md` 同名组件。

### 我的社群列表

顶栏右侧「申请记录」进入申请记录页，返回后恢复列表位置。直接展示全部社群，不提供搜索和筛选。卡片不展示绑定状态和审核信息，审核进度只在申请记录查看。白色社群信息右侧有下钻箭头，点击进入原来的社群详情，返回后恢复列表位置。灰色导师卡只显示导师姓名，「绑定导师」紧跟姓名，赛道和项目在姓名右侧，没有箭头；点击后在当前列表上打开导师浮层。浮层展示头像、姓名、身份「绑定导师」、赛道和项目标签，以及导师介绍。关闭按钮、「我知道了」和遮罩都可以关掉浮层，列表位置不变。列表不放解绑或换绑。详情底部左侧按状态显示「换绑」「换绑审核中」或「已解绑」，只有「换绑」打开换绑页；右侧「对接社群」从底部打开运营二维码浮层，权重大于换绑。列表不展示成员数。收益显示为两位小数。

### 社群详情头部

返回回到「我的社群」并恢复列表滚动位置。公告入口打开公告浮层；成员数、公告入口和项目摘要位于白色信息卡。列表不展示成员数。详情这里的成员数等于虚拟成员加真实成员数。所属导师团在信息卡下方使用独立入口。

### 社群负责项目

项目横向排列。点项目图标或名称打开项目说明浮层；浮层中的模拟跳转按钮只显示 Toast，不连接真实项目详情页。

一行无法容纳全部项目时，可横向滑动。每个项目都有图标和名称，都能滑到可视范围。不会出现没有图标的项目。

### 社群介绍

社群介绍默认折叠为三行。点击分区标题右侧或卡片底部入口展开完整正文；展开后两个入口都切换为收起文案，再次点击恢复折叠。

### 社群负责导师

负责人使用主卡片展示，其他成员位于「导师团成员」区域并使用双列卡片。点任一导师打开资料浮层。导师卡片内不显示所属导师团。

### 导师浮层

盖在社群详情或导师团主页上，不离开当前页面。里面展示头像、昵称、身份 Tag、标签和完整介绍。可通过右上关闭、底部按钮或遮罩关闭。

### 所属导师团入口

这是社群级关系。列表卡片里它是「所属导师团」字段，详情头部是独立入口，都不在导师卡片或导师浮层内。点击前记录当前页面和滚动偏移，再进入导师团主页。

### 导师团主页导航

导师团主页提供返回操作。点击返回或使用浏览器历史返回时，回到进入前的列表或社群详情并恢复记录的滚动位置。

### 导师团基本信息

深色 Hero 展示导师团图标、名称、说明和全部负责赛道；Hero 下方三列展示服务社群数、导师团成员数和服务会员数。

### 导师团负责人

「导师团负责人」单独展示导师长，包含头像、昵称、职责与「导师长」标识；点击打开资料浮层。

### 导师团成员

成员区按专项导师、创业导师等层级分组，成员行展示头像、昵称、身份 Tag、职责和箭头；点击打开资料浮层。

### 服务数据

显示「服务社群数」「导师团成员数」「服务会员数」。锁定 Demo 固定展示完整示例值。

### 导师团介绍

介绍默认展示摘要，点击「查看完整介绍」展开，点击「收起介绍」恢复摘要；内容只读。

### 社群战绩

社群战绩展示社群本月总产出、活跃成员、本月新增成员和个人排行。收益荣誉榜固定展示本月收益 TOP 5，第一名使用重点卡片，其余四名使用紧凑排行。数据说明与榜单标题操作只显示 Demo Toast。

### 个人介绍配置

导师视角直接进入配置页。头像、昵称和个人介绍默认可编辑，不需要先点编辑图标；当前身份显示后台配置值，置灰且不可编辑。

- 点头像或「更换头像」进入头像选择；选择后先在当前页预览，等待统一保存。
- 昵称使用有明确标签的文本输入框，进入页面显示当前昵称。
- 个人介绍使用多行文本框。
- 点保存时统一提交头像、昵称和个人介绍。作为 UX 防重复提交策略，保存中按钮不可重复点击。
- 保存成功只提示「保存成功」，停留当前页，信息保持展开。
- Demo 不接真实上传和持久化，也不改写锁定的用户视角示例；刷新后恢复示例数据。

### 对接社群

点它从底部打开「联系平台运营」浮层。标题下写「了解」加当前社群名，底部写「截图或长按保存」。关闭按钮、遮罩都可以关掉。Demo 不打开真实社群。

### 管理后台规则

三块只列新增项，正文不可点。

1. 社群管理：按钮「同步飞书信息」；字段「飞书社群人员」。
2. 人员管理：操作「批量入群」「重新入群」；字段「入群状态」。
3. 导师管理：操作「同步飞书信息」；字段「飞书信息」；社群弹窗三列「是否已同步飞书信息」「飞书社群人数」「该导师群内身份」。

同步中、入群失败、对不上名称，都只写在规则文案里。这一页没有可切换的失败画面。

### 需求规则抽屉

盖在迭代页上。可通过右上角关闭按钮、点击遮罩或按 Esc 键关闭。当前页签是管理后台时打开「后台需求」；当前页签是前端交互或业务流程时打开「前端需求」。

前端需求写社群页 FR-8 至 FR-12、导师端 FR-13 至 FR-15、导师团主页 FR-16 至 FR-19。其中业务流程一节只写「见本页业务流程」。后台需求按上面三块列规则。

## State Patterns

| 状态 | 用户视角 |
|---|---|
| 打开 | 展示「我的社群」全部社群，没有筛选 |
| 无社群 | 显示「暂无社群」 |
| 换绑 | 未换绑时从社群详情底部进入换绑页；审核进度只在申请记录查看 |
| 社群详情 | 展示完整有数据示例 |
| 公告 / 项目 / 导师 / 飞书浮层 | 当前页面保留在遮罩下方 |
| 社群介绍 | 默认折叠，可展开和收起 |
| 从详情返回 | 恢复社群列表滚动位置 |
| 从导师团主页返回 | 恢复进入前的列表或详情及滚动位置 |

管理后台没有同步中、入群失败的页面状态。

| 状态 | 导师团主页 |
|---|---|
| 打开 | 展示深色 Hero、三个服务数据、介绍、负责人和分层成员 |
| 介绍折叠 | 默认只显示摘要 |
| 介绍展开 | 显示完整介绍并提供收起 |
| 成员资料浮层 | 当前主页保留在遮罩下方 |
| 其他状态 | 锁定 Demo 不演示加载、失败、缺失、异常或空数据 |

| 状态 | 个人介绍配置页 |
|---|---|
| 初始 | 当前头像、昵称、只读身份和个人介绍全部展开 |
| 已选择新头像 | 当前页预览新头像，尚未保存 |
| 有未保存修改 | 保留输入内容，等待统一保存 |

| 保存成功 | 提示「保存成功」，停留当前页；Demo 刷新后恢复示例 |

## Interaction Primitives

- 列表直接展示全部社群，不提供筛选。审核进度从「申请记录」查看。
- 点社群卡片主体进入详情；点列表卡片所属导师团直接进入导师团主页。
- 横滑社群负责项目；点项目打开项目说明浮层。
- 点详情公告打开公告浮层；点社群负责导师打开导师资料浮层。
- 点详情头部所属导师团进入导师团主页。
- 点导师团主页返回或使用浏览器历史返回，回到进入前页面并恢复滚动位置。
- 点社群介绍或导师团介绍的展开 / 收起入口，切换正文长度。
- 点导师团负责人或成员打开资料浮层。
- 点关闭按钮、底部确认按钮或遮罩关闭当前浮层。
- 点「对接社群」从底部打开运营二维码浮层；未换绑时点「换绑」打开换绑页。
- 社群战绩与 TOP 5 只读；数据说明操作显示 Toast。
- 点头像或「更换头像」：选择头像并在当前页预览。
- 编辑昵称与个人介绍：直接输入；当前身份不可聚焦编辑。
- 点保存：统一保存头像、昵称和个人介绍；成功后只显示 Toast，不跳转。
- 迭代页上可点的还有业务线、左侧菜单、页签、场景切换和需求规则。管理后台的规则正文不可点。

## Accessibility Floor

- 社群卡片主体、所属导师团入口、项目、导师、返回和底部按钮的点按高度至少 44px。
- 项目名称作为该项的名称读出。每一项都有图标。
- 社群负责导师卡片按昵称、身份和职责读出；所属导师团作为社群级独立入口读出。
- 导师浮层是对话框，标题用这位导师的昵称。打开后焦点在浮层里，关闭后回到原触发项。
- 导师团主页进入后先播报页名与导师团名称；返回后焦点回到原「所属导师团」入口。恢复滚动不能只靠焦点跳转造成页面闪回顶部。
- 导师团成员按负责人、分组标题、成员行的视觉顺序进入无障碍树。
- 服务数据按标签和数值读出。
- 横滑区除手势外，还须提供可访问的操作方式，确保每一项均可到达。
- 展开 / 收起按钮暴露当前展开状态；弹窗关闭按钮有可读名称。
- 头像更换入口有可读名称「更换头像」；昵称输入框、个人介绍文本框都有可见标签；只读身份同时暴露只读状态。
- 金额使用 `{colors.brand-orange}`，并采用 `{typography.money}` 的字重。名次和人数用 `{colors.text-primary}` 加同样的字重。
- 社群头图名称使用白字配深色背景；导师团名称与正文使用 `{colors.text-primary}` 写在 `{colors.surface-card}` 上。正文和交互文案对比度至少 4.5:1。

## Key Flows

**UJ-4. 阿宁看社群页。**

1. 阿宁在「我的社群」列表选择一个社群。
2. 她进入社群详情，看到深色头图、公告、成员与项目摘要，以及独立的所属导师团入口。
3. 她向下浏览负责人和导师团成员，点击导师查看资料浮层；展开社群介绍；横滑并点击项目查看项目说明。
4. 她继续看到社群战绩、个人排行和本月收益 TOP 5。
5. 她点「对接社群」，从底部看到「联系平台运营」浮层。
6. 她点击返回，回到「我的社群」列表原位置。

**UJ-6. 阿宁查看导师团并回到原位置。**

1. 阿宁从列表卡片或社群详情头部点击社群级「所属导师团」入口。
2. 导师团主页展示深色 Hero、负责赛道和三个服务数据。
3. 她展开导师团介绍，查看负责人和专项导师、创业导师分组成员，并可打开成员资料浮层。
4. 高潮：她点击返回，回到进入前的列表或详情及原滚动位置。

锁定 Demo 只覆盖完整有数据路径，不演示加载、失败、缺失、异常或空数据。

**UJ-5. 导师修改个人资料。**

1. 导师切到导师视角，直接进入个人介绍配置页。
2. 导师点当前头像选择新头像，在当前页看到预览；接着修改昵称和个人介绍。当前身份保持置灰，不能修改。
3. 导师点保存。保存期间不能重复提交。
4. 高潮：页面提示「保存成功」，仍停留在当前编辑页，头像、昵称、身份和个人介绍保持展开。
5. 当前静态 Demo 不改写锁定的用户视角示例；刷新后恢复配置页示例数据。

**UJ-1. 林林核对社群管理规则。**

1. 林林打开这条需求的管理后台。
2. 社群管理一条写着「同步飞书信息」和「飞书社群人员」。
3. 高潮：这块文案和需求规则里的后台需求说的是同一件事。
4. 页上没有按钮可点。名称无法匹配时不新建、不删除；该规则只写在规则文案里。

**UJ-2. 林林核对人员管理规则。**

1. 同一页的人员管理写着「批量入群」「重新入群」和「入群状态」。
2. 高潮：入群失败要有失败原因、可以重新入群，这两句出现在规则里。
3. 页上没有勾选，也没有失败原因的弹出。

**UJ-3. 林林核对导师管理规则。**

1. 导师管理写着「同步飞书信息」「飞书信息」，以及社群弹窗的三列。
2. 高潮：三列的名字是「是否已同步飞书信息」「飞书社群人数」「该导师群内身份」。
3. 页上没有导师列表，也没有社群弹窗。

## Inspiration & Anti-patterns

用户侧保留锁定 Demo 的「我的社群」列表、社群公告、长页详情、收益 TOP 5 和导师团深色 Hero。所属导师团始终是社群级入口，不嵌入单个导师卡片。

不带进用户侧的：真实接口、登录、持久化、真实项目详情页、真实飞书、加入社群和「免费」。不带进导师团主页的：加入、退出、切换、编辑导师团及任何后台配置入口。

## Responsive & Platform

桌面迭代页负责规则与嵌入预览。用户视角内容最大宽 430px 并居中，不拉成桌面宽表；导师视角个人介绍页保持 375px 逻辑宽度。导师团服务数据保持三列等分。
