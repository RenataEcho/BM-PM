# PRD: 加入导师团优化

FR-CoCo-002 · 加入导师团优化 · v2 当前

## 0. 文档目的

本文件只覆盖导师商务这一条增量：全局编号 FR-CoCo-002，需求名「加入导师团优化」。正文里的 FR-1、FR-2 只表示本文件第几条能力，不另占全局号。

读者是产品、设计和研发人员。用词以第 3 节为准。管理后台的规则在第 4.1 至 4.3 节，社群页在第 4.4 节，每条带可验收的结果。还没定的收在第 6 节。

迭代页 `demo/iteration/fr-coco-002-mentor-v1-2.html` 的管理后台页签只列规则文案，不做可点的后台原型。前端交互页签默认展示「我的社群」列表，可进入社群详情和导师团主页；导师视角展示个人介绍配置页。锁定验收页是 `demo/iteration/fr-coco-002-mentor-v1-2-fe.html`，文档与外壳规则必须跟随它，不得反向修改该文件。接口和机器人同步方式见 `addendum.md`。

管理后台是 FR-1 至 FR-7；用户侧列表与社群详情是 FR-8 至 FR-12；导师端优化是 FR-13 至 FR-15；导师团主页是 FR-16 至 FR-19。2026-11-08 以锁定 Demo 统一最终页面合同：默认先展示「我的社群」列表；所属导师团是社群级独立入口，不放进单个导师卡片；社群公告、介绍展开、收益 TOP 5、导师团深色 Hero 与介绍展开均保留。

## 1. 要解决的事

导师商务的管理后台里，社群、人员和导师已经分开管理。这一版让三处和飞书对齐：现有社群能按名称匹配飞书机器人所在的群并查看成员；还没进群的人员能被拉进飞书群，失败时能查看原因并重试；导师能同步飞书昵称、飞书手机号和飞书ID，并查看已关联社群的同步状态、飞书社群人数和群内身份。

同一条增量里，已加入成员先在「我的社群」列表搜索和选择社群，也可从列表卡片直接进入所属导师团。社群详情保留既有深色头图、公告、成员和负责项目结构，并补充社群级所属导师团入口；导师、介绍、战绩和收益 TOP 5 继续在长页中展示。导师团主页展示深色 Hero、服务数据、可展开介绍、负责人和分层成员。

导师端同时补充服务记录成员识别信息、精简群管理操作，并允许导师修改头像、昵称和个人介绍。

这一版的完成标准是：第 4 节所述后台三个模块、社群页和导师端优化均可按对应的可验收结果核对。不另设数字指标。

## 2. 谁在用

### 2.1 要完成的事

- 林林在社群管理把现有社群和飞书群对上，并看到飞书社群人员。
- 林林在人员管理把还未入群的人拉进飞书群；失败时看到失败原因，并可以重新入群。
- 林林在导师管理看到一位导师的飞书信息，并在社群弹窗看到是否已同步、人数和群内身份。
- 阿宁在「我的社群」列表搜索和进入社群，也可直接进入该社群的所属导师团。
- 阿宁在社群详情查看公告、负责项目、社群负责导师、可展开介绍、社群战绩和收益 TOP 5。
- 阿宁点一个社群负责项目，在 Demo 中查看项目说明浮层；正式项目详情页不在本次静态 Demo 范围。
- 阿宁点社群负责导师列表里的一位导师，在导师浮层里看导师基础信息。
- 阿宁从列表卡片或社群详情的独立所属导师团入口进入导师团主页，查看深色 Hero、服务数据、介绍、负责人和分层成员。
- 阿宁点「进入社群飞书」，查看说明；静态 Demo 不连接真实飞书。
- 导师在个人介绍配置页修改头像、昵称和个人介绍并看到保存成功；静态 Demo 不改写锁定的用户视角示例。

### 2.2 这一版不给谁用

- 右豹主业务、企业号的使用者和后台不在本文件里。
- 还没加入该社群的人看不到这张社群页，也不能从这里加入。

### 2.3 关键路径

后台操作者称林林。能打开现有社群管理、人员管理、导师管理的账号就可以用下面的新操作，不另设角色。已加入成员称阿宁，和林林不是同一条路径。

**UJ-1.** 林林在社群管理点「同步飞书信息」，配上的社群显示出飞书社群人员。规则见第 4.1 节。

**UJ-2.** 林林在人员管理勾选人员，点「批量入群」；入群失败的人点「重新入群」。规则见第 4.2 节。

**UJ-3.** 林林在导师管理对一位导师点「同步飞书信息」，再打开社群弹窗核对三列。规则见第 4.3 节。

**UJ-4.** 阿宁从「我的社群」列表选择社群，进入保留原结构的社群详情；查看公告、项目、导师、介绍、战绩和收益 TOP 5，并通过独立的所属导师团入口进入导师团主页。规则见第 4.4 节。

**UJ-5.** 导师进入个人介绍配置页，修改头像、昵称或个人介绍并保存；页面提示保存成功并停留在当前页。当前静态 Demo 不改写用户视角示例。规则见 FR-15。

**UJ-6.** 阿宁从列表卡片或社群详情的社群级入口进入导师团主页；先看深色 Hero 和服务数据，再展开介绍、查看负责人和分层成员；点返回后回到进入前页面与滚动位置。规则见第 4.6 节。

## 3. 用词

后文只用这些叫法。

- **林林** — 使用管理后台这三处的人。
- **社群管理** — 现有的社群列表。本模块增加「同步飞书信息」和「飞书社群人员」。
- **人员管理** — 现有的人员列表。本模块增加「批量入群」「重新入群」和「入群状态」。
- **导师管理** — 现有的导师列表。本模块增加「同步飞书信息」「飞书信息」，并在已有的社群弹窗上增加三列。
- **社群** — 社群管理里的一条现有记录。本稿不新建社群，也不删除社群。
- **社群名称** — 一条社群用来和飞书群配对的名称。
- **飞书群** — 飞书机器人当前归属的一个群。配对时用飞书群的名称对社群名称。
- **飞书机器人** — 用来读取飞书群、飞书成员，并把人员拉进飞书群的机器人。做法见 `addendum.md`。
- **同步飞书信息** — 按钮上的字。在社群管理，是把现有社群和飞书群按社群名称一对一配对，并写下飞书社群人员。在导师管理，是同步这一位导师在飞书的社群信息，并写下飞书信息和社群弹窗三列。两处字样相同，对象不同。
- **飞书社群人员** — 社群上的字段。配上飞书群之后，显示该飞书群的成员。
- **人员** — 人员管理里的一条记录。
- **入群状态** — 人员上的字段，只有三个值：已入群、未入群、入群失败。
- **失败原因** — 入群状态为入群失败时，必须能读到的一段说明。已入群、未入群没有失败原因。
- **批量入群** — 把勾选中尚未入群的人员拉进飞书群。
- **重新入群** — 对入群失败的人员再拉一次飞书群。
- **飞书信息** — 导师上的一组字段，只包含飞书昵称、飞书手机号、飞书ID。
- **飞书昵称** — 飞书信息里的名称。
- **飞书手机号** — 飞书信息里的手机号。
- **飞书ID** — 飞书信息里的标识。
- **社群弹窗** — 导师现有关联数据里、列出已关联社群的弹窗。一行一个社群。
- **是否已同步飞书信息** — 社群弹窗里的一列，只有「是」或「否」。
- **飞书社群人数** — 社群弹窗里的一列。值是飞书机器人同步回来的该飞书群成员数量。
- **该导师群内身份** — 社群弹窗里的一列。值是飞书机器人拉回的、这位导师在该飞书群里的身份。
- **群内身份** — 一个人在一个飞书群里的身份。「该导师群内身份」是该字段在导师对应行中的名称。飞书社群人员里的成员也用群内身份这个词。群内身份不是社群页上的身份。
- **阿宁** — 已加入某个社群、使用社群页的成员。
- **我的社群** — 用户视角默认页。列表卡片展示名称、加入天数、成员数、社群负责人和所属导师团，并支持按社群名称、负责人或导师团搜索。
- **社群详情** — 从社群卡片进入的长页，保留深色头图、成员与公告信息、负责项目、社群级所属导师团入口、社群负责导师、社群介绍、社群战绩、收益荣誉榜和底部飞书入口。
- **所属导师团** — 社群级关系。入口位于列表卡片和社群详情头部白色信息卡下方，不属于单个导师卡片；显示导师团名称和负责赛道并进入导师团主页。
- **社群公告** — 社群详情头部的公告入口；点击后以浮层显示公告正文与更新时间。
- **社群负责项目** — 横向排列的项目卡片。点击后在静态 Demo 中显示项目说明与模拟跳转按钮，不连接真实项目详情页。
- **社群负责导师** — 社群详情中的导师分区，按负责人和导师团成员分组；导师卡片内不展示所属导师团。
- **导师资料浮层** — 点击社群负责导师、导师团负责人或成员后显示的资料浮层。
- **社群介绍** — 社群详情中的介绍卡片，默认折叠为三行，支持展开和收起。
- **社群战绩** — 展示社群本月总产出、活跃成员、本月新增成员以及用户排行与本月收益。
- **收益荣誉榜** — 展示本月收益 TOP 5，第一名使用重点卡片，其余四名使用紧凑排行。
- **导师团主页** — 从列表或详情页的所属导师团入口进入的只读全屏页；包含深色 Hero、负责赛道、三个服务数据、可展开介绍、负责人和分层成员。
- **服务社群数** — 导师团主页顶部的统计指标。
- **导师团成员数** — 导师团主页顶部的统计指标。
- **服务会员数** — 导师团主页顶部的统计指标。
- **导师团介绍** — 导师团主页中的可展开介绍。
- **导师团负责人** — 导师团主页独立展示的负责人卡片。
- **导师团成员** — 按专项导师、创业导师等层级分组展示的成员。
- **头像** — 社群负责导师、导师团成员和资料浮层中的导师图片。
- **昵称** — 导师个人介绍配置页可修改的名称。
- **职责** — 导师卡片和资料浮层中的职责说明。
- **进入社群飞书** — 社群详情底部按钮；静态 Demo 只显示说明浮层，不连接真实飞书。

## 4. 按模块列出的规则

管理后台只交付下面三块规则。迭代页照此写文案，不做可点原型。

### 4.1 社群管理

#### FR-1: 按社群名称一对一同步

林林点「同步飞书信息」后，每条现有社群最多配上一个飞书群，每个飞书群最多配上一条社群。实现 UJ-1。

**可验收结果：**

- 社群管理有按钮「同步飞书信息」。点它不离开社群管理。
- 由林林点按钮触发，不是定时任务。同一次同步未返回前，这个按钮不可再点。
- 配对只使用社群名称和飞书群名称。比较前去掉两侧名称的首尾空格，其余字符必须一致。
- 名称一致且在社群、飞书群两侧都只出现一次，算配上。配上的社群写下该飞书群的飞书社群人员。
- 社群里两条同名，或飞书侧两个飞书群同名时，这些同名项本次均不写入新的同步结果，结果里说明「名称不唯一，未同步」。
- 对不上的社群不新建、不删除、不改社群名称。从未同步过的，飞书社群人员为空。已经有飞书社群人员、这次没配上的，保留上次内容，结果里说明这次未配上。
- 同步失败时停留在社群管理，说明失败，不覆盖上一次已经写下的飞书社群人员。
- 同步结束时，林林能看出配上几条、名称不唯一几条、未配上几条。

**本条不覆盖：** 不因飞书多出一个群就新建社群。不在这里修改人员的入群状态。

#### FR-2: 查看飞书社群人员

配上的社群能查看飞书社群人员。实现 UJ-1。

**可验收结果：**

- 社群上有字段「飞书社群人员」。
- 配上之后，列出的人是该飞书群的成员，人数与飞书社群人数使用同一次同步结果。
- 每一名成员显示飞书昵称、飞书ID、群内身份。飞书社群人员里不显示飞书手机号。
- 未配上、或从未同步时，飞书社群人员为空，不显示成 0 人。
- 成员列表只读。不能在飞书社群人员里把人移出飞书群。

### 4.2 人员管理

#### FR-3: 批量入群

林林勾选人员后点「批量入群」，把其中还未入群的人拉进飞书群。实现 UJ-2。

**可验收结果：**

- 人员管理有操作「批量入群」。
- 只处理林林勾选的人员。一条都没勾选时，不能点批量入群，也不会把列表里全部未入群的人一并拉群。
- 勾选项中，对入群状态为未入群或入群失败的人员发起入群；跳过入群状态为已入群的人员，并说明其已入群、未再次拉群。
- 目标飞书群是该人员已关联社群所配上的那个飞书群。人员没有关联社群，或该社群还没有匹配飞书群时，该人员的入群状态变为入群失败，失败原因写「没有可加入的飞书群」。
- 同一次批量入群未返回前，批量入群不可再点。
- 结束后林林仍在人员管理。每条被处理的人员要么变为已入群，要么变为入群失败并带有失败原因。

#### FR-4: 显示入群状态和失败原因

人员管理能看出一个人是否已进入飞书群。实现 UJ-2。

**可验收结果：**

- 人员有字段「入群状态」，值只有已入群、未入群、入群失败。
- 还没执行过入群的人员，入群状态是未入群。
- 入群失败时，同一行能读到失败原因。失败原因来自这次入群的结果，不改写成别的固定文案；仅「没有可加入的飞书群」是本文件规定的原因。
- 已入群、未入群不显示失败原因。
- 入群成功只更新该人员的入群状态。飞书社群人员不在这一步改写，要等社群管理再次同步飞书信息才更新。

#### FR-5: 重新入群

入群失败的人员可以再拉一次。实现 UJ-2。

**可验收结果：**

- 入群状态为入群失败时，该人员有操作「重新入群」。已入群、未入群没有这个操作。
- 点重新入群，只处理这一条人员，目标飞书群与 FR-3 相同。
- 成功则入群状态变为已入群，失败原因清掉。
- 再失败则入群状态仍为入群失败，失败原因换成这一次的结果。
- 这一次未返回前，这条的重新入群不可再点。

### 4.3 导师管理

#### FR-6: 同步并展示飞书信息

导师管理能看到该导师的飞书昵称、飞书手机号和飞书ID。实现 UJ-3。

**可验收结果：**

- 导师管理对一位导师有操作「同步飞书信息」。一次只同步这一位，不提供全表一起同步。
- 同步成功后，飞书信息展示飞书昵称、飞书手机号、飞书ID。某个值这次没有返回，该格为空，不编一个值。
- 飞书手机号按同步结果原样显示，不打码。
- 同步失败时停留在导师管理，说明失败，不覆盖上一次已经写下的飞书信息。
- 未同步过的导师，飞书昵称、飞书手机号、飞书ID 都为空。

#### FR-7: 社群弹窗显示同步结果、人数和身份

导师现有的社群弹窗增加三列。实现 UJ-3。

**可验收结果：**

- 社群弹窗仍是现有关联数据的弹窗，一行一个已关联社群。本稿不增加、不删除关联。
- 每行有「是否已同步飞书信息」，值只有「是」或「否」。
- 每行有「飞书社群人数」。它是飞书机器人同步回来的该飞书群成员数量。
- 每行有「该导师群内身份」。它是飞书机器人拉回的、这位导师在该飞书群的群内身份。
- 群主、管理员只是群内身份的举例。该列按返回原文显示，不限于这两种身份。一次返回多个群内身份时，都显示。
- 该导师的飞书信息同步成功，且该行社群的社群名称与飞书群名称按 FR-1 的规则配上时，是否已同步飞书信息为「是」，并写下飞书社群人数和该导师群内身份。
- 社群未配上飞书群，或该导师尚未同步飞书信息时，是否已同步飞书信息为「否」，飞书社群人数和该导师群内身份为空。已同步且成员数量为 0 时，飞书社群人数显示 0，不留空。
- 飞书社群人数与该社群的飞书社群人员，来自同一飞书群的同一次成员同步结果。

### 4.4 我的社群与社群详情

已加入成员默认进入「我的社群」列表，搜索并进入社群详情，也可从列表卡片直接进入所属导师团。社群详情保持锁定 Demo 的原有长页结构。实现 UJ-4。

#### FR-8: 从我的社群列表进入社群详情

阿宁能搜索和选择已加入的社群，并在详情中确认社群身份、公告与所属导师团。实现 UJ-4。

#### FR-9: 展示社群负责项目

- 没有项目名称的项不占位。

**本条不覆盖：** 不规定项目详情页里的字段、按钮和空态。

#### FR-10: 展示社群介绍

社群页显示这个社群的介绍。实现 UJ-4。

**可验收结果：**

- 社群介绍在长页中作为独立分区展示。
- 默认将正文折叠为三行，同时提供「展开介绍」和「查看完整介绍」入口。
- 展开后显示完整正文，入口切换为「收起介绍」；再次点击恢复折叠状态。
- 静态 Demo 只覆盖有正文的完整示例，不演示介绍缺失或媒体内容。

#### FR-11: 查看社群负责导师

阿宁在「社群负责导师」分区查看负责人和导师团成员，并打开导师资料浮层。所属导师团使用 FR-8 的社群级独立入口，不放进导师卡片。实现 UJ-4。

**可验收结果：**

- 「社群负责导师」分区始终在。不会出现一位负责导师都没有的情况。
- 负责人使用主卡片展示头像、昵称、职责和身份 Tag；其余成员位于「导师团成员」区域。
- 每位成员展示头像、昵称和职责摘要；点击任一导师打开资料浮层。
- 导师卡片内不展示所属导师团，不承担导师团主页导航。
- 导师浮层盖在社群页上，不把社群页挤窄，也不离开社群页。
- 导师浮层显示头像、昵称、身份、标签和完整导师介绍；可通过关闭按钮、底部按钮或遮罩关闭。

**本条不覆盖：** 不在导师浮层里改身份、职责或导师团归属。

#### FR-12: 展示社群战绩

社群详情展示社群战绩和本月收益 TOP 5。实现 UJ-4。

**可验收结果：**

- 个人排行展示「你的社群排行」、名次、本月收益和一条团队成员收益。
- 收益荣誉榜标题为「本月收益 TOP 5」，第一名使用重点卡片，其余四名使用紧凑列表。
- 排行按示例收益降序展示，字段只读；「数据说明」与榜单标题操作只显示 Demo 提示。
- 静态 Demo 只覆盖完整有数据状态，不提供显隐、空值、零值或失败状态切换。

**本条不覆盖：** 不解释金额怎么累加、活跃怎么判定、名次按哪一个金额排序。口径见第 6 节。

### 4.5 导师端优化（2026-10-27 补充）

本节在 V1.2 已完成功能上迭代，使用者为导师端的导师，与管理后台操作者及社群页成员区分。

#### FR-13: 服务记录成员列表增加识别信息

导师在现有服务记录页面的成员列表中，能看到每位成员的「右豹ID」「飞书手机号」。

**可验收结果：**

- 服务记录页面的成员列表增加「右豹ID」「飞书手机号」两项显示。
- 两项信息对应所在行的成员，不得显示为当前导师的信息。
- 飞书手机号的展示口径确认前，不沿用管理后台导师手机号原样显示的规则。

#### FR-14: 移除导师端群管理的两个按钮

导师端「导师管理的群」去掉「新建群」「群规模」按钮。

**可验收结果：**

- 导师打开现有管理群的页面时，不再显示「新建群」「群规模」按钮。
- 本条只移除这两个按钮，不据此删除已有群或改写群数据。

#### FR-15: 调整个人信息配置，支持编辑头像、昵称和个人介绍

导师从个人信息页面进入「个人介绍」，配置头像、昵称和个人介绍。

**可验收结果：**

- 导师个人信息页面移除「团队角色」配置项。
- 导师个人信息页面增加「个人介绍」配置入口；点击进入独立的个人介绍信息配置页面。
- 配置页包含「头像」「昵称」「当前身份」「个人介绍」四项。
- 头像支持修改。导师选择新头像后，页面显示待保存的新头像。
- 昵称支持修改，使用文本输入框。
- 「当前身份」默认显示后台配置的身份名称，置灰显示，不支持导师修改。
- 「个人介绍」使用文本输入框，进入页面默认可编辑，无需点击编辑图标。
- 点击保存时，一并保存头像、昵称和个人介绍。保存成功后仅提示「保存成功」，停留当前编辑页面，所有信息保持展开，不提供预览操作。
- 正式开发保存后应以接口结果更新使用该导师资料的页面；当前静态 Demo 只演示配置页保存反馈，不改写锁定的用户视角示例内容。

**待确认：** 头像文件格式、大小和裁剪规则；昵称与个人介绍的必填、字数及字符限制。未确认前不推定校验值。

### 4.6 导师团主页

导师团主页由「我的社群」列表卡片或社群详情头部的社群级「所属导师团」入口进入。页面只读，不提供创建、编辑、加入或退出导师团的操作。实现 UJ-6。

#### FR-16: 展示导师团基本信息并支持返回

阿宁进入导师团主页后，能确认正在查看哪个导师团及其负责赛道。

**可验收结果：**

- 页面使用深色 Hero，展示导师团图标、导师团名称、说明和全部负责赛道。
- Hero 下方展示服务社群数、导师团成员数和服务会员数。
- 页面提供返回操作。点返回后回到进入前的列表或社群详情，并恢复进入前的滚动位置。
- 静态 Demo 只覆盖完整有数据状态，不演示加载、失败、缺失或失效状态。
- 本轮静态 Demo 不接真实接口、路由权限或持久化。

#### FR-17: 展示导师长和分层成员

阿宁能区分导师团负责人和其他成员，并按后台层级理解导师团组成。

**可验收结果：**

- 「导师团负责人」单独展示负责人，标识写「导师长」，并展示职责。
- 「导师团成员」展示负责人以外的成员，负责人不在成员列表重复出现。
- 成员按专项导师、创业导师等身份分组，并按页面示例顺序展示。
- 每名导师在一个导师团内只有一个用于分层展示的当前主身份。同一分组内严格采用后端返回数组顺序；缺少主身份的成员由后端归入最后一组「其他」。
- 成员列表按导师 ID 去重。导师长若同时出现在普通成员集合中，应从普通成员集合中剔除；普通成员重复时只展示一次。一名导师同时属于多个导师团时，只要其与当前导师团的归属关系有效，就在当前主页出现。
- 点击负责人或任一成员打开资料浮层。
- 静态 Demo 不演示负责人或成员缺失、重复及字段异常状态。

#### FR-18: 展示当前导师团数据

阿宁能看到该导师团当前服务范围与人员规模。

**可验收结果：**

- 页面展示「服务社群数」「导师团成员数」「服务会员数」三个指标，分别带单位「个」「人」「人」。
- 三个指标以打开导师团主页时返回的数据为准。
- 服务社群数按当前有效服务关联的社群 ID 去重统计。一个社群同一时间只关联一个有效导师团；历史已解除关联的社群不计入。
- 导师团成员数按当前有效归属关系中的导师 ID 去重统计，包含导师长；已退出或已失效的导师不计入，并与 FR-17 成员列表使用同一快照。
- 服务会员数取该导师团当前服务社群内尚未退出或移除的有效会员，按会员 ID 跨社群去重；在导师管理中存在当前有效导师记录的会员 ID 不计入。同一会员出现在多个服务社群时只计一次。
- 三个指标由后端返回，前端不根据页面列表自行推算；静态 Demo 固定展示完整示例值。
- 验收样例：导师团 G1 当前服务 C1、C2，历史服务 C3 已解除；当前有效导师为导师长 M0、成员 M1；C1 有会员 U1、U2，C2 有会员 U1 和导师 M1。结果应为服务社群数 2、导师团成员数 2、服务会员数 2。

#### FR-19: 展示导师团介绍

阿宁能阅读导师团的完整介绍。

**可验收结果：**

- 页面有独立分区「导师团介绍」，默认展示摘要。
- 点击「查看完整介绍」展开剩余正文，按钮切换为「收起介绍」；再次点击恢复摘要。
- 介绍只读，不提供编辑、图片、视频或外链；静态 Demo 不演示介绍为空。

## 5. 非目标

- 管理后台不做可点的后台原型。管理后台页签只列规则文案。
- 不提供未加入时的「加入社群」，不定义「免费」角标。
- 迭代 Demo 不连接真实项目详情页；项目点击只打开本地说明浮层。
- 不在社群页编辑社群资料、项目、介绍或导师。
- 不新建社群，不删除社群，不改社群名称。
- 不把飞书侧多出来的群自动收成新社群。
- 不做定时同步。社群和导师的同步飞书信息都由林林点按钮触发。
- 不在人员管理展示飞书昵称、飞书手机号、飞书ID。
- 不在飞书社群人员里展示飞书手机号，也不在那里把成员移出飞书群。
- 不新增后台角色。
- 不把右豹主业务、企业号写进本文件。
- 接口和机器人归属的做法留在 `addendum.md`。本文件不另写一套。
- 不设计导师团的创建、编辑、删除、导师归属配置、社群关联配置或赛道配置后台；本次只定义成员侧只读导师团主页。
- 不提供申请加入、退出或切换导师团的成员侧操作。

## 6. 假设与待决

已确认规则及验收边界以第 4 节为准；本节只保留尚未决定的口径。

待决：

1. 社群战绩的生产口径：本月从哪一天起、活跃成员和新增成员怎么算、排行按哪一个金额。负责人：产品与数据；真实战绩接口联调前确认，不阻断锁定的静态 Demo。

2. 导师端服务记录成员列表：飞书手机号显示完整号码还是脱敏号码；两项新增信息缺失时如何显示。负责人：产品与安全；FR-13 真实开发前确认，当前静态 Demo 不覆盖该页面。

3. 导师个人介绍配置页：头像文件格式、大小和裁剪规则，昵称与个人介绍的必填、字数及字符限制，以及正式开发保存后哪些页面实时刷新。负责人：产品与设计；真实上传和表单校验开发前确认，不阻断静态 Demo。

4. 一名人员能否同时关联多个社群；如果可以，批量入群如何选择或逐个处理目标飞书群。负责人：产品与后端；FR-3 真实开发前确认，不阻断静态 Demo。

5. 社群名称本次失配但保留上次同步结果时，旧飞书群映射是否仍可用于批量入群。负责人：产品与后端；FR-3 真实开发前确认，不阻断静态 Demo。

6. 社群管理与导师管理各自同步时，飞书社群人员和飞书社群人数如何引用同一次成员结果，以及快照过期后的显示规则。负责人：产品与后端；FR-7 真实开发前确认，不阻断静态 Demo。
