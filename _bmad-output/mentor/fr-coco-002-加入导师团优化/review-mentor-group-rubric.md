# 导师团需求质量评审

## 1. 评审结论

**结论：有条件通过静态 Demo 评审，暂不建议作为真实开发与验收的最终基线。**

本轮 FR-11、FR-16 至 FR-19 已形成可理解的页面主链路：从社群负责导师卡片进入对应导师团主页，展示基本信息、唯一导师长、分层成员、三个统计指标和介绍，再返回原社群页与原滚动位置。FR-1 至 FR-19 编号连续且唯一；“社群负责导师”与“导师团成员”已分开，社群页不再沿用导师团层级排序，这些部分没有发现编号断裂或直接冲突。

“一名导师可属于多个导师团”与“一个社群同一时间只关联一个当前有效导师团”在数据基数上可以同时成立，但当前 PRD 没有定义二者与“社群负责导师”的连接约束。FR-11 又要求在导师卡片展示该导师的全部导师团，因此可能从一个社群进入与该社群无服务关系的导师团。加上排序来源、唯一导师长、统计中的“当前有效”仍不可客观复算，目前尚不能稳定写出无歧义的端到端验收用例。

严重度汇总：

- critical：0
- high：5
- medium：5
- low：3

## 2. 范围与依据

- 主评审对象：`prd.md` 最新草稿，重点为 FR-11、FR-16、FR-17、FR-18、FR-19。
- 交叉核对：第 0 至第 6 节、UJ-4 至 UJ-6、FR-15，以及 `.memlog.md` 最后 8 条。
- 评审维度：需求一致性、可验收性、冲突、关系基数、排序、成员层级、统计口径、空态、入口与返回、FR 编号和术语。
- 不评审视觉完成度、接口实现方案或现有 Demo 代码。

## 3. 关系模型判断

当前稿已经明确：

1. 一名导师可以同时属于多个当前有效导师团。
2. 一个社群同一时间只关联一个当前有效导师团。
3. 一个导师团可服务多个社群。
4. 一个导师团的成员包含导师长；主页展示时导师长单列，不在普通成员区重复。
5. 社群负责导师列表独立于导师团层级，采用配置或后端顺序。

这些基数本身不矛盾，但还缺少三条决定行为的约束：

- 社群负责导师是否必须属于该社群当前关联的导师团。
- 导师卡片展示全部所属导师团，还是只展示与当前社群有关的导师团。
- 社群没有当前有效导师团、导师没有导师团、关联在浏览期间失效时，入口如何处理。

因此，当前状态应判断为：**模型可成立，但关系没有闭环，不能判定为完全自洽。**

## 4. Findings

### Critical

无。

### High

#### H1. 社群、负责导师和所属导师团之间缺少关联约束

**位置：** 用词“社群负责导师”“所属导师团”“导师团”；FR-11；FR-16。

PRD 同时规定一个社群只关联一个当前有效导师团、一名导师可属于多个导师团、导师卡片展示其全部当前有效导师团。它没有说明：

- 社群负责导师是否必须属于该社群当前关联的导师团；
- 卡片是否允许展示与当前社群无服务关系的其他导师团；
- 若允许，用户为何能从当前社群进入无关导师团，是否有可见性或权限边界；
- 若不允许，FR-11 的“展示全部当前有效导师团”就与社群单导师团约束不一致。

这会使同一组数据产生两种都符合文字的实现，并可能把用户带到与当前社群无关的导师团主页。

**明确修复建议：**

先选择并写死一种产品语义：

- 方案 A：卡片只展示该导师与“当前社群当前有效导师团”相交的导师团，正常情况下至多一个；
- 方案 B：卡片展示导师全部导师团，但明确它是导师个人组织归属导航，不代表这些导师团服务当前社群；同时定义可见性、当前服务导师团标记及无权访问处理。

再补一条关系约束：社群负责导师是否必须是当前服务导师团成员。增加固定验收样例：导师 M1 属于 G1、G2，社群 C1 当前关联 G1，明确 C1 的 M1 卡片应显示哪些项、点击后可进入哪些主页。

#### H2. 社群负责导师与导师团成员的排序契约不可客观验收

**位置：** 用词“社群负责导师列表”“身份”；FR-11；FR-17。

FR-11 使用“后台配置或后端返回顺序”，这是两个可能不一致的来源，测试无法判断哪个是权威结果。FR-17 规定按身份层级分组、同层采用后端顺序，但没有定义层级字段、同优先级的不同身份如何排序、身份缺少优先级时放在哪里，也没有说明一名导师是否可能有多个身份标签。

**明确修复建议：**

- 社群负责导师只保留一个排序真源，例如后端返回 `mentor_order`，前端严格按该值升序；补充重复、缺失排序值的兜底。
- 导师团成员定义后端成品排序契约，至少包含 `identity_name`、`identity_level` 或 `identity_order`、`member_order`。
- 明确同优先级不同身份的组顺序、同组成员顺序、缺失层级的固定位置。
- 明确导师只能有一个用于导师团分层的当前身份，或给多身份指定唯一主身份。

#### H3. “唯一导师长”实际只约束了至多一位，零导师长状态与业务定义冲突

**位置：** 用词“导师团”“导师团负责人（导师长）”；UJ-6；FR-17。

“导师团由一位导师长组成”和“唯一导师长”表达的是恰好一位；FR-17 只规定“不能出现两位”，同时允许“导师长数据未返回时显示暂无”。这把“合法空导师长”“接口漏字段”“非法数据”混成同一个页面状态，无法验收导师团是否满足业务不变量。

**明确修复建议：**

- 若导师团必须恰好一位有效导师长：写明无导师长时导师团不能成为当前有效状态；接口异常缺失时显示数据异常态，不把它当正常空态。
- 若允许交接期零导师长：把定义改为“至多一位”，补充交接状态、持续时间及此时导师团是否可服务社群。
- 明确导师长仍计入 FR-18 的成员数，但只在负责人区展示一次。

#### H4. FR-18 的“当前有效”仍不足以复算三个统计指标

**位置：** 用词“服务社群数”“导师团成员数”“服务会员数”；FR-18。

去重键与 0/缺失值已经明确，这是优点；但“当前有效服务关联”“当前有效归属关系”“有效会员”“具有导师身份的账号”没有判定标准。“身份”在本文又是导师后台标签，无法确认“具有导师身份”是账号角色、身份标签还是导师表记录。三个指标虽要求来自同一快照，却没有快照时点、时区或版本标识，也没有要求与 FR-17 成员数据采用同一快照。

**明确修复建议：**

- 定义统计时点，例如按请求时的后端快照，返回 `snapshot_at` 或 `snapshot_id`。
- 对每个集合列出纳入和排除状态，不只写“有效”。
- 将“具有导师身份的账号”改成明确的数据判断，例如“在导师表存在当前有效导师记录的 user_id”。
- 明确 FR-17 成员列表与 FR-18 成员数是否必须来自同一快照。
- 增加可手算验收数据：重复社群、同一会员跨社群、导师兼会员、已退出导师、历史关联各一例，并给出三个期望值。

#### H5. UJ-5 与 FR-11、FR-15 对个人介绍的展示位置冲突

**位置：** UJ-5；FR-11；FR-15。

UJ-5 表述为阿宁在“社群负责导师列表和导师浮层”看到更新后的头像、昵称和个人介绍，容易被验收为列表也展示个人介绍；FR-11 的卡片字段只有头像、昵称、职责、身份和所属导师团；FR-15 则明确只有导师浮层展示最新个人介绍。

**明确修复建议：**

将 UJ-5 改成唯一口径：“社群负责导师列表更新头像和昵称；导师浮层更新头像、昵称和个人介绍。”如果确实要在卡片显示个人介绍，则应同步改 FR-11 字段清单，并说明与“职责”的区别。

### Medium

#### M1. 空态、异常态和业务不变量混在一起

**位置：** FR-11、FR-16、FR-17、FR-18、FR-19。

当前已覆盖部分字段缺失、无普通成员、统计 0 与未返回、介绍为空，但仍缺少统一状态矩阵：

- FR-11 声明不会没有负责导师，却没有定义后端实际返回空列表时如何处理；
- FR-16 没有定义导师团不存在、已失效或整页请求失败；
- FR-17 的无导师长既可能是非法业务数据，也可能是接口缺失；
- 成员头像、昵称、身份、职责等单字段缺失没有兜底；
- 没有加载中和加载失败状态。

**明确修复建议：**

按“加载中 / 成功有数据 / 成功空数据 / 实体不存在或已失效 / 请求失败 / 字段缺失”建立页面状态表。对业务声称“不可能为空”的数据，返回空时应定义为异常态并可观测，不应悄悄显示普通“暂无”。

#### M2. 入口与返回对静态 Demo 闭环，对真实页面只闭合了一半

**位置：** UJ-6；FR-16；第 5 节。

卡片中的具体导师团项进入正确主页、页面返回到原社群页并恢复滚动位置，足以验收静态 Demo。但系统返回手势/浏览器返回、刷新或直接打开导师团 URL、入口导师团在浏览期间失效、返回时原社群已不可用均未定义。

**明确修复建议：**

把 Demo 与真实开发分开写：

- Demo：现有“进入 + 页面返回 + 恢复滚动位置”即可。
- 真实开发：明确页面返回与系统返回行为一致；记录来源社群 ID 和滚动锚点；无来源时返回约定的兜底页；导师团失效时显示不可用态并提供返回。

#### M3. 成员列表缺少去重和关系冲突规则

**位置：** FR-17；FR-18。

FR-18 的成员数按导师 ID 去重，但 FR-17 没有要求成员展示去重。若后端存在重复归属记录、导师长同时以普通成员关系返回，列表可能重复而指标不重复。当前只禁止导师长在成员区重复，未覆盖普通成员重复或同一导师被分到多个身份组。

**明确修复建议：**

规定主页成员按导师 ID 唯一；导师长优先从普通成员集合剔除；同一导师多条有效归属或多身份时由后端选定唯一主归属/主身份，或将其判为数据错误。

#### M4. 全局编号格式与仓库稳定编号规则不一致

**位置：** frontmatter、第 0 节及全篇。

正文 FR-1 至 FR-19 连续、唯一，本轮新增 FR-16 至 FR-19 也没有复用旧号，局部编号稳定。但文档把 `FR-CoCo-002` 声明为全局编号，而仓库规则要求全局编号为 `FR-0xx`。这会影响跨文档登记、自动检索和后续迁移。

**明确修复建议：**

先确认 `FR-CoCo-002` 是否为获批的历史例外。若不是，分配规范全局号，并把 `FR-CoCo-002` 保留为旧编号/别名；一次性统一 README、总览、目录、Demo 和文档引用，避免只改 PRD 造成断链。正文 FR-1 至 FR-19 不应重排。

#### M5. “当前有效”的时间边界未形成跨 FR 的统一术语

**位置：** FR-11、FR-16、FR-17、FR-18。

多个条目都依赖“当前有效”，但术语表没有定义“当前”的基准时间，也没有说明页面停留期间数据变化后是保持进入快照还是重新刷新。FR-16 要求打开点击项对应主页，FR-18 又要求同一快照，二者的生命周期未连接。

**明确修复建议：**

在术语表增加“当前有效快照”：定义生成时点、有效状态来源、页面刷新规则和是否贯穿基本信息、成员列表、统计与介绍。至少要求同一次导师团主页响应中的 FR-16 至 FR-19 使用同一导师团 ID；成员与统计使用同一快照。

### Low

#### L1. 第 0 节的历史摘要仍使用容易误读的旧排序表述

**位置：** 第 0 节。

“导师团按身份上下级排序且导师长固定首位”没有说明该规则只适用于导师团主页，读者可能误套到 FR-11；后文虽然已明确社群负责导师不按该规则排序，但摘要仍增加理解成本。

**明确修复建议：**

把摘要改成“导师团主页中导师长单列，其余成员按身份层级排序；社群负责导师列表保持后端成品顺序”。

#### L2. `icon` 与“图标”混用，影响字段命名稳定性

**位置：** “导师团 icon”、FR-16；“项目图标”、FR-9。

当前含义可理解，但同一中文 PRD 对图形字段同时使用 `icon` 和“图标”，接口、设计稿和验收用例可能出现不同字段名。

**明确修复建议：**

统一为“导师团图标”，如需保留接口名，在首次出现处写“导师团图标（icon）”。

#### L3. “导师团负责人（导师长）”、分区标题和标签存在三种表述

**位置：** 用词；FR-17。

术语是“导师团负责人（导师长）”，分区标题是“导师团负责人”，标识是“导师长”。当前不构成逻辑冲突，但下游容易把“负责人”和“导师长”误建为两个角色。

**明确修复建议：**

保留一个规范角色名“导师长”，并明确“导师团负责人”仅是页面分区标题，不是另一种身份。

## 5. 可验收性检查

### 已具备明确验收条件

- FR-11：卡片与所属导师团点击区域互斥；多导师团逐项进入；无导师团显示“暂无”；导师浮层关闭后保持滚动位置。
- FR-16：显示图标、名称、全部赛道；字段缺失有兜底；从具体项进入正确导师团；返回原社群页并恢复位置。
- FR-17：导师长单列；普通成员不重复导师长；无普通成员显示“暂无成员”。
- FR-18：三个指标、单位、去重键、0 与缺失值区分、前端不自行推算。
- FR-19：介绍全文、只读、空介绍文案明确。

### 尚不能稳定验收

- 社群 C 关联 G1、导师 M 同属 G1/G2 时，M 的卡片到底展示 G1 还是 G1/G2。
- 社群负责导师排序到底以后台配置表还是接口返回数组为准。
- 身份层级相同但身份名称不同、身份层级缺失或导师多身份时的分组结果。
- 零导师长是合法空态、过渡态还是数据错误。
- 三个统计指标的“有效”数据集和统计时点。
- 导师团整页失效、请求失败、直接打开和无来源返回。

## 6. 建议补充的最小验收样例

1. **多导师团与单社群导师团：** C1 当前关联 G1；M1 属于 G1、G2；M1 是 C1 负责导师。写出卡片展示项、可点击主页和当前服务标记的唯一期望。
2. **成员层级：** G1 有导师长 M0；身份 A 优先级 10 有 M1/M2；身份 B 优先级 20 有 M3；另有缺失优先级 M4。写出完整分组与顺序。
3. **关系去重：** M1 有两条重复有效归属；M0 同时出现在负责人和成员数据中。写出列表与成员数的唯一结果。
4. **统计口径：** 两个服务社群有同一会员；一名导师兼会员；一条历史社群关联、一名已退出导师。写出三个指标期望值和快照时间。
5. **异常与返回：** 进入后导师团失效；返回时原社群仍存在。写出错误态、返回目标和滚动恢复行为。

## 7. 修复顺序

1. 先修 H1，确定社群、负责导师、导师团三者的关系和卡片展示范围。
2. 再修 H2、H3，冻结排序字段与“恰好一位导师长”的不变量。
3. 修 H4，以可手算样例冻结统计口径及快照。
4. 修 H5 和 M1，消除跨章节展示冲突并补齐状态矩阵。
5. 最后处理真实路由返回、全局编号迁移和低优先级术语统一。

完成 H1 至 H5 后，FR-11、FR-16 至 FR-19 才适合作为真实开发和端到端验收基线；M、L 项可按是否仅交付静态 Demo 分批收口。
