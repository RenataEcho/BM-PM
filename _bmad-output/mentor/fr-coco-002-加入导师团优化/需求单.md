# 需求单

编号：FR-CoCo-002

工作标签：FR-CoCo-002

业务线：导师商务

需求名：加入导师团优化

照着哪条现有需求做：未说明。本仓没有已写的社群管理、人员管理、导师管理页面。

谁在用：管理后台操作的人称林林。社群页的已加入成员称阿宁。

从哪个入口进来：管理后台的社群管理、人员管理、导师管理；用户视角默认从「我的社群」列表进入社群详情或所属导师团。

接着怎么点：

1. 社群管理：点「同步飞书信息」。按飞书机器人归属的群，用社群名称和现有社群一对一同步。社群增加「飞书社群人员」，显示该社群在飞书的成员信息。
2. 人员管理：对还未拉进飞书群的人员做「批量入群」，通过接口拉进飞书群。人员增加「入群状态」：已入群、未入群、入群失败。入群失败要显示失败原因，并支持「重新入群」。
3. 导师管理：点「同步飞书信息」，通过接口同步该导师在飞书的社群信息。导师增加「飞书信息」，聚合显示飞书昵称、飞书手机号、飞书 ID。现有关联数据里的社群弹窗增加：是否已同步飞书信息（是、否）、飞书社群人数（机器人同步的飞书社群成员数量）、该导师群内身份（机器人拉回的群内身份，例如群主、管理员）。
4. 用户视角：默认展示「我的社群」列表，不提供搜索；列表卡片可进入社群详情或所属导师团。社群详情保留公告、负责项目、导师、可展开介绍、战绩、收益 TOP 5，底部是「换绑」和「对接社群」。点项目打开说明浮层，点「对接社群」从底部打开运营二维码浮层。

后台要看什么：

- 表：社群、人员、导师，以及导师关联数据里的社群弹窗。
- 字段：飞书社群人员；入群状态（已入群、未入群、入群失败）和失败原因；飞书信息（飞书昵称、飞书手机号、飞书 ID）；社群弹窗上的是否已同步飞书信息、飞书社群人数、该导师群内身份。

哪些情况不允许：还没说。已说到的失败表现是入群失败要显示失败原因。

这次不做的：管理后台不做可点原型；用户侧不提供加入社群，不定义「免费」角标；静态 Demo 不连接真实项目详情页或飞书。

还没定的：社群战绩的统计口径。页面先按返回的数原样显示。

2. 导师管理的群去掉「新建群」「群规模」按钮。

待确认：飞书手机号是否脱敏；新增信息缺失时如何显示。对应 PRD 的 FR-13、FR-14。

3. 导师个人信息页面去掉「团队角色」配置，增加「个人介绍」配置入口。点击进入个人介绍信息配置页面，包含头像、昵称、当前身份、个人介绍。头像和昵称支持修改；当前身份默认显示后台配置的身份名称，不支持修改、置灰显示；个人介绍使用文本输入框。对应 FR-15。

已确认：导师端配置的「个人介绍」与社群页导师浮层展示的「导师介绍」使用同一份内容。

## 2026-11-02 规则补充

1. 导师视角：个人介绍配置页的头像和昵称都支持修改。静态 Demo 演示预览、保存中和保存成功，不改写锁定的用户视角示例。
2. 用户视角：锁定 Demo 固定展示社群战绩和本月收益 TOP 5 完整示例，不提供显隐或空数据切换。
3. 导师团主页：负责人单独展示；其余成员按专项导师、创业导师等层级分组展示。

待确认：头像文件格式、大小和裁剪规则；昵称与个人介绍的必填、字数及字符限制。

## 2026-11-06 页面结构覆盖

用户视角默认进入「我的社群」列表。社群详情不使用「社群介绍 / 社群导师 / 社区战绩」三 Tab，保留深色头图、成员与公告信息、独立所属导师团入口、导师、可展开介绍、项目、战绩、收益 TOP 5，底部是「换绑」和「对接社群」。

锁定 Demo 只覆盖完整有数据状态；社群介绍和导师团介绍均支持展开、收起。此前三 Tab 及其切换口径全部失效，不得恢复。

## 2026-11-06 导师团需求补充

1. 社群详情导师分区固定为「社群负责导师」，按负责人和导师团成员分组展示。
2. 「所属导师团」是社群级独立入口，位于「我的社群」列表卡片及社群详情头部，不放进单个导师卡片。
3. 一个社群同一时间最多关联一个当前有效导师团；一个导师团可服务多个社群；一名导师可同时属于多个导师团。同一社群的负责导师应为当前服务导师团的有效成员。
4. 导师团主页展示深色 Hero、导师团图标、名称、全部负责赛道、服务社群数、导师团成员数、服务会员数、可展开介绍、负责人和分层成员。
5. 导师团数据按打开或刷新主页时的当前有效快照统计。服务社群按社群 ID 去重；成员按导师 ID 去重且包含导师长；服务会员按会员 ID 跨服务社群去重并排除当前有效导师账号。
6. 锁定 Demo 不演示字段缺失、空数据、失败或结构异常。
7. 本轮静态 Demo 实现从列表或详情页的所属导师团进入主页及返回；返回后恢复进入前页面与滚动位置。

## 2026-11-09 现有后台优化

继续并入 FR-CoCo-002，不另占号。不新开后台模块。

在已有社群管理增加需求分组「现有后台优化」：

1. 社群负责人：从导师中选择 1 人写入，一个社群同一时间只能有 1 个。再选一名导师并保存，替换原来的那位。
2. 虚拟成员：后台可编辑，范围含 200 和 500。还没有这个数时，不改数就保存，会在范围内随机定一个；改过再保存，写入所填的数。保存后再次打开不重新随机。超出范围不能保存。
3. 社群详情上的成员数等于虚拟成员加真实成员数。页面只展示这一个数。「我的社群」列表不展示成员数。

管理后台仍只列规则文案，不做可点原型。
