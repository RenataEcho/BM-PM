# 导师团需求最终复核

## 1. Verdict

**PASS — 本轮 FR-11、FR-16 至 FR-19 已达到一致、可验收、无 critical/high 冲突的状态。**

上次 H1 至 H5 均已解决。用户最终覆盖已经形成单一口径：

- 所属导师团只显示当前社群正在关联的导师团，不展示导师的其他组织归属；
- 一个社群同一时间最多关联一个当前有效导师团；
- 导师团允许没有导师长，此时隐藏负责人分区并正常展示其他成员；
- 社群负责导师和导师团成员都采用后端返回的成品顺序，前端不二次排序；
- 当前有效快照已定义，并贯穿基本信息、成员、统计与介绍。

当前没有尚存的 critical 或 high 问题。仍有少量 medium/low 级文档治理项，但不阻断本轮静态 Demo，也不影响 FR-11、FR-16 至 FR-19 按现有口径进入开发验收。

## 2. 上次 H1-H5 复核

### H1 社群、负责导师和所属导师团关系未闭环

**状态：已解决。**

证据：

- 术语“所属导师团”明确只展示当前社群正在关联的导师团，不展示导师同时归属但未服务当前社群的其他导师团。
- 术语“导师团”明确一个社群同一时间最多关联一个当前有效导师团。
- FR-11 明确有关联时，社群负责导师应当是该导师团的当前有效成员。
- 没有有效导师团或导师不属于该团时显示“暂无”且不提供入口。
- 后端异常返回多个当前有效导师团时，前端不自行选择，显示明确异常文案。
- FR-16 要求按当前社群的所属导师团项打开对应导师团，不能因导师的其他归属打开错误主页。

判断：多导师团导师与单社群导师团的关系已经自洽，正常态、无关联态、成员关系不匹配和多关联异常态都有唯一行为。

### H2 排序契约不可客观验收

**状态：已解决。**

证据：

- 社群负责导师：后端按后台配置生成唯一成品顺序，前端严格按返回数组展示。
- 导师团成员：后端返回身份分组的成品顺序，前端不硬编码身份和先后。
- 同一分组内严格按后端返回数组顺序。
- 每名导师只有一个用于分层展示的当前主身份。
- 缺少主身份的成员由后端归入最后一组“其他”。

判断：排序真源唯一，分组、组内排序、多身份和缺失身份均可验收。

### H3 唯一导师长与零导师长状态冲突

**状态：已解决，且属于最终产品口径覆盖旧假设。**

证据：

- “导师团”定义为由零或一位导师长和若干分层导师组成。
- “导师团负责人（导师长）”明确允许暂未配置，配置时最多一位。
- FR-17 明确无导师长时不显示负责人分区，其他导师正常展示。
- 后端返回两位及以上当前有效导师长时，前端不自行选择，负责人区显示“导师长信息异常”。

判断：合法基数是 0..1，不再使用“必须恰好一位”的旧假设；正常空态与多导师长异常态已分开。

### H4 当前有效与三个统计指标不可复算

**状态：已解决。**

证据：

- 术语“当前有效快照”定义了生成时点、同一主页响应、同一导师团 ID、成员与成员数同快照，以及停留期间不混入新快照。
- FR-18 明确只有在快照时点已生效且尚未退出、解除、过期或失效的关系才计入。
- 服务社群数、导师团成员数、服务会员数分别给出去重主键。
- “具有导师身份”已具体化为“在导师管理中存在当前有效导师记录的会员 ID”。
- FR-18 给出包含跨社群重复会员、历史社群和导师兼会员的可手算样例及期望值。

判断：三个指标已经可以用固定数据集复算，0 与缺失值也有不同展示规则。

### H5 UJ-5 与 FR-11、FR-15 的个人介绍展示冲突

**状态：已解决。**

证据：

- UJ-5 已明确：社群负责导师列表更新头像和昵称；导师浮层更新头像、昵称和个人介绍。
- FR-11 卡片字段仍为头像、昵称、职责、身份和所属导师团，不包含个人介绍。
- FR-15 明确导师浮层展示最新个人介绍，并与“个人介绍”使用同一份内容。

判断：列表与浮层的展示边界一致，无重复解释。

## 3. 上次 M1-M5 复核

### M1 空态、异常态和业务不变量混合

**状态：基本解决；剩余为 low 级异常防御项。**

已补齐：

- FR-11：无导师团、导师不属于当前团、多导师团异常。
- FR-16：加载中、导师团不存在、已失效、请求失败，以及禁止展示上一导师团缓存。
- FR-17：无导师长、多导师长异常、无普通成员、成员字段缺失。
- FR-18：0 与未返回。
- FR-19：空介绍。

剩余：FR-11 仍以“不会没有负责导师”为业务不变量，没有规定接口异常返回空负责导师列表时的错误态。该缺口不影响本轮已确认的正常业务验收，降为 low。

### M2 入口与返回只闭合静态 Demo

**状态：部分解决；剩余为 medium。**

已补齐：

- 从当前社群的唯一导师团项进入正确主页；
- 页面返回到原社群页并恢复原滚动位置；
- 导师团不存在、失效或请求失败时保留返回操作；
- 静态 Demo 的范围边界明确。

尚未定义：

- 系统返回手势或浏览器返回是否与页面返回一致；
- 直接打开导师团地址时的无来源返回目标；
- 刷新后的来源社群和滚动位置恢复策略。

建议：真实路由开发前补一条统一导航契约。该项不构成 critical/high，也不阻断当前静态 Demo。

### M3 成员列表缺少去重和关系冲突规则

**状态：已解决。**

FR-17 已明确按导师 ID 去重、导师长优先从普通成员集合剔除、普通成员重复只展示一次，并通过唯一当前主身份避免同一导师跨组重复。

### M4 全局编号格式与仓库规则不一致

**状态：未解决，保持 medium。**

正文 FR-1 至 FR-19 连续、唯一且没有重排，本轮局部编号稳定；但 `FR-CoCo-002` 仍被声明为全局编号，与仓库要求的 `FR-0xx` 格式不一致。

建议：将其作为跨 README、总览、目录和 Demo 的编号治理任务单独处理，不应只改本 PRD，也不应重排正文 FR-1 至 FR-19。

### M5 当前有效的跨 FR 时间边界未定义

**状态：已解决。**

“当前有效快照”已经定义生成时点、页面停留与主动刷新规则、同一导师团 ID，以及成员列表和成员数同快照。FR-18 进一步定义关系生效与失效边界，并提供验收样例。

## 4. 最终一致性与可验收性检查

### 关系与基数

- 导师可属于多个导师团：成立。
- 社群最多关联一个当前有效导师团：成立。
- 社群卡片只展示当前社群关联团：成立。
- 当前负责导师不属于该团时不提供入口：成立。
- 导师团允许零或一位导师长：成立。
- 导师长计入成员数，但不在普通成员区重复：成立。

### 排序与层级

- 社群负责导师：后端唯一成品顺序。
- 导师团身份分组：后端成品顺序。
- 组内成员：后端数组顺序。
- 缺少主身份：最后一组“其他”。
- 前端不按导师长、身份名或层级二次排序。

### 统计

- 三项指标来自同一当前有效快照。
- 服务社群按社群 ID 去重。
- 导师成员按导师 ID 去重并包含导师长。
- 服务会员按会员 ID 跨社群去重并排除当前有效导师记录。
- 0、缺失值和历史失效关系均有明确处理。

### 空态与异常

- 无社群关联团：显示“暂无”，无入口。
- 多社群关联团异常：显示明确错误，不自行挑选。
- 无导师长：隐藏负责人分区，其他成员正常展示。
- 多导师长异常：负责人区显示错误。
- 无普通成员：显示“暂无成员”。
- 导师团不可用或请求失败：不展示旧缓存，保留返回。

### 入口与返回

- 静态 Demo 闭环完整：社群卡片进入正确导师团，返回原社群页和原滚动位置。
- 真实路由的系统返回、直接访问和刷新恢复仍建议在开发前补充，但严重度为 medium。

### 编号与术语

- FR-1 至 FR-19 连续、唯一、稳定。
- “社群负责导师”“所属导师团”“导师团成员”“导师长”“导师团图标”使用一致。
- `icon` 已统一为首次出现的“导师团图标（icon）”，正文使用“导师团图标”。
- 全局编号 `FR-CoCo-002` 与仓库编号格式仍有 medium 级治理差异。
