# PRD: 导师迭代V1.2

FR-CoCo-002 · 导师迭代V1.2 · v1 当前

## 0. 文档目的

本文件只覆盖导师商务这一条增量：全局编号 FR-CoCo-002，需求名导师迭代V1.2。正文里的 FR-1、FR-2 只表示本文件第几条能力，不另占全局号。

读者是产品、设计和后续写合同的人。用词以第 3 节为准。管理后台的规则在第 4.1 至 4.3 节，社群页在第 4.4 节，每条带可验收的结果。还没定的收在第 6 节。

迭代页 `demo/iteration/fr-coco-002-mentor-v1-2.html` 的管理后台页签只列规则文案，不做可点的后台原型。前端交互页签做社群页 Demo，手机画面嵌在页内。社群负责项目在开发规则里点击打开对应的项目详情页；这个 Demo 不实现这次跳转，也不做项目详情页。视觉沿用迭代外壳和 `docs/design/移动端设计规范.md`，不另起配色。接口和机器人同步方式、社群页的画面参照，都在 `addendum.md`。

管理后台是 FR-1 至 FR-7。社群页是 FR-8 至 FR-12。2026-10-27 补充的导师端优化是 FR-13 至 FR-15。2026-11-02 进一步确认导师可修改头像和昵称、社群战绩与收益荣誉榜由后端分别控制，以及导师团按身份上下级排序且导师长固定首位。

## 1. 要解决的事

导师商务的管理后台里，社群、人员和导师已经分开管理。这一版让三处和飞书对齐：现有社群能按名称对上飞书机器人所在的群并看到成员；还没进群的人员能被拉进飞书群，失败能看到原因并再试；一位导师能同步出飞书昵称、飞书手机号、飞书ID，以及已关联社群上的同步结果、人数和群内身份。

同一条增量里，已加入社群的成员有一张社群页。这一页在现有社群页上补信息和调整层次：看到这个社群负责的项目、社群介绍、社群导师列表、社群战绩和收益荣誉榜，点开一位导师看导师基础信息，并从这一页进入该社群的飞书群。

导师端同时补充服务记录成员识别信息、精简群管理操作，并允许导师修改头像、昵称和个人介绍。

这一版算做成，是第 4 节后台三个模块、社群页和导师端优化都能按可验收结果核对。不另设数字指标。

## 2. 谁在用

### 2.1 要完成的事

- 林林在社群管理把现有社群和飞书群对上，并看到飞书社群人员。
- 林林在人员管理把还未入群的人拉进飞书群；失败时看到失败原因，并可以重新入群。
- 林林在导师管理看到一位导师的飞书信息，并在社群弹窗看到是否已同步、人数和群内身份。
- 阿宁在社群页看到社群负责项目、社群介绍和社群战绩。
- 阿宁点一个社群负责项目，打开对应的项目详情页。
- 阿宁点社群导师列表里的一位导师，在导师浮层里看导师基础信息。
- 阿宁点「进入社区飞书」，去这个社群的飞书群。
- 导师在个人介绍配置页修改头像、昵称和个人介绍；保存后，用户视角的社群导师列表与导师浮层使用最新信息。

### 2.2 这一版不给谁用

- 右豹主业务、企业号的使用者和后台不在本文件里。
- 还没加入该社群的人看不到这张社群页，也不能从这里加入。
- 林林不在社群页上做同步飞书信息、批量入群或导师同步。
- 本需求不要求飞书群成员登录管理后台。

### 2.3 关键路径

后台操作者称林林。能打开现有社群管理、人员管理、导师管理的账号就可以用下面的新操作，不另设角色。已加入成员称阿宁，和林林不是同一条路径。

**UJ-1.** 林林在社群管理点「同步飞书信息」，配上的社群显示出飞书社群人员。规则见第 4.1 节。

**UJ-2.** 林林在人员管理勾选人员，点「批量入群」；入群失败的人点「重新入群」。规则见第 4.2 节。

**UJ-3.** 林林在导师管理对一位导师点「同步飞书信息」，再打开社群弹窗核对三列。规则见第 4.3 节。

**UJ-4.** 阿宁在社群页看到社群负责项目、社群介绍、社群导师列表、社群战绩和收益荣誉榜；点一个项目打开对应的项目详情页；点社群导师列表里的一位导师，导师浮层给出导师基础信息；再点「进入社区飞书」。不写上一级页面。规则见第 4.4 节。

**UJ-5.** 导师进入个人介绍配置页，修改头像、昵称或个人介绍并保存；页面提示保存成功并停留在当前页。阿宁之后在社群导师列表和导师浮层看到更新后的头像、昵称和个人介绍。规则见 FR-15。

## 3. 用词

后文只用这些叫法。

- **林林** — 使用管理后台这三处的人。
- **社群管理** — 现有的社群列表。本模块增加「同步飞书信息」和「飞书社群人员」。
- **人员管理** — 现有的人员列表。本模块增加「批量入群」「重新入群」和「入群状态」。
- **导师管理** — 现有的导师列表。本模块增加「同步飞书信息」「飞书信息」，并在已有的社群弹窗上增加三列。
- **社群** — 社群管理里的一条现有记录。本稿不新建社群，也不删除社群。
- **社群名称** — 一条社群用来和飞书群配对的名称。
- **飞书群** — 飞书机器人当前归属的一个群。配对时用飞书群的名称对社群名称。
- **飞书机器人** — 用来读取飞书群、飞书成员，并把人员拉进飞书群的机器人。做法见 `addendum.md`。
- **同步飞书信息** — 按钮上的字。在社群管理，是把现有社群和飞书群按社群名称一对一配对，并写下飞书社群人员。在导师管理，是同步这一位导师在飞书的社群信息，并写下飞书信息和社群弹窗三列。两处字样相同，对象不同。
- **飞书社群人员** — 社群上的字段。配上飞书群之后，显示该飞书群的成员。
- **人员** — 人员管理里的一条记录。
- **入群状态** — 人员上的字段，只有三个值：已入群、未入群、入群失败。
- **失败原因** — 入群状态为入群失败时，必须能读到的一段说明。已入群、未入群没有失败原因。
- **批量入群** — 把勾选中尚未入群的人员拉进飞书群。
- **重新入群** — 对入群失败的人员再拉一次飞书群。
- **飞书信息** — 导师上的一组字段，只包含飞书昵称、飞书手机号、飞书ID。
- **飞书昵称** — 飞书信息里的名称。
- **飞书手机号** — 飞书信息里的手机号。
- **飞书ID** — 飞书信息里的标识。
- **社群弹窗** — 导师现有关联数据里、列出已关联社群的弹窗。一行一个社群。
- **是否已同步飞书信息** — 社群弹窗里的一列，只有「是」或「否」。
- **飞书社群人数** — 社群弹窗里的一列。值是飞书机器人同步回来的该飞书群成员数量。
- **该导师群内身份** — 社群弹窗里的一列。值是飞书机器人拉回的、这位导师在该飞书群里的身份。
- **群内身份** — 一个人在一个飞书群里的身份。该导师群内身份是群内身份用在导师这一行上的字段名。飞书社群人员里的成员也用群内身份这个词。群内身份不是社群页上的身份。
- **阿宁** — 已加入某个社群、使用社群页的成员。
- **社群页** — 阿宁已加入后看到的那一张社群画面。页上有社群头像、社群名称、已加入天数、社群负责项目，以及「社群介绍」「社群导师」「社区战绩」三个 Tab，和按钮「进入社区飞书」。
- **社群头像** — 社群页头图上的社群图片。
- **已加入天数** — 社群页上显示的、从加入到打开这天的天数。
- **社群负责项目** — 这个社群负责的项目，在社群页上排成一行。每一项有项目图标和项目名称。点一项打开对应的项目详情页。
- **项目图标** — 社群负责项目里一项的图形。
- **项目名称** — 社群负责项目里一项的名称。
- **项目详情页** — 点社群负责项目的一项之后打开的那一页。本文件只规定可以打开对应的那一页，不规定页里有什么。迭代 Demo 不实现这次打开。
- **社群介绍** — 社群页上的介绍正文。配了图片或视频时，和正文一起显示。
- **社群导师** — 社群页上列出该社群全部导师的 Tab，页上写「社群导师」。
- **社群导师列表** — 「社群导师」Tab 内的导师集合。
- **身份** — 导师后台配置的标签。身份之间有后台配置的上下级优先级，社群页按这个优先级从高到低展示。
- **导师团负责人（导师长）** — 导师团的负责人。无论其他身份优先级如何，社群导师列表都把导师长放在第一位。
- **创业导师** — 身份写成创业导师的导师。
- **助理导师** — 身份写成助理导师的导师。可以有多位。
- **头像** — 社群导师列表和导师基础信息里的导师图片。不是社群头像。
- **昵称** — 导师可以在个人介绍配置页修改的名称。社群导师列表和导师浮层里的名字使用这份昵称；不是飞书昵称。
- **职责** — 导师组卡片和导师浮层里的一句说明，按原文显示。
- **导师介绍** — 导师浮层里比职责更完整的一段说明，按原文显示。卡片上不重复这一段。
- **导师基础信息** — 导师浮层里的内容：头像、昵称、身份、职责。
- **导师浮层** — 点社群导师列表里的一位导师后，盖在社群页上的浮层。不离开社群页。
- **社群战绩** — 社群页上的成绩模块。包含社区本月总产出、活跃成员、你的社区排行、本月收益，以及一条团队成员收益。是否展示由后端独立控制。
- **收益荣誉榜** — 社群页上的成员收益排名模块，即原成员TOP-10。每行显示头像、脱敏昵称和收益，是否展示由后端独立控制。
- **社区本月总产出** — 社群战绩里的一个金额。页上标题用这六个字。
- **活跃成员** — 社群战绩里的一对人数：活跃人数 / 社群成员总数。
- **你的社区排行** — 阿宁在该社群本月收益上的名次。页上标题用这六个字。
- **本月收益** — 你的社区排行旁边，阿宁在该社群的本月收益金额。
- **团队成员收益** — 社群战绩底部的一条摘录。一条里有成员名字、项目名称、该成员在该项目的单月收益。
- **进入社区飞书** — 社群页底部按钮上的字。点它去这个社群的飞书群。

## 4. 按模块列出的规则

管理后台只交付下面三块规则。迭代页照此写文案，不做可点原型。

### 4.1 社群管理

#### FR-1: 按社群名称一对一同步

林林点「同步飞书信息」后，每条现有社群最多配上一个飞书群，每个飞书群最多配上一条社群。实现 UJ-1。

**可验收结果：**

- 社群管理有按钮「同步飞书信息」。点它不离开社群管理。
- 由林林点按钮触发，不是定时任务。同一次同步未返回前，这个按钮不可再点。
- 配对只使用社群名称和飞书群名称。比较前去掉两侧名称的首尾空格，其余字符必须一致。
- 名称一致且在社群、飞书群两侧都只出现一次，算配上。配上的社群写下该飞书群的飞书社群人员。
- 社群里两条同名，或飞书侧两个飞书群同名时，这些同名项本次均不写入新的同步结果，结果里说明「名称不唯一，未同步」。
- 对不上的社群不新建、不删除、不改社群名称。从未同步过的，飞书社群人员为空。已经有飞书社群人员、这次没配上的，保留上次内容，结果里说明这次未配上。
- 同步失败时停留在社群管理，说明失败，不覆盖上一次已经写下的飞书社群人员。
- 同步结束时，林林能看出配上几条、名称不唯一几条、未配上几条。

**本条不覆盖：** 不因飞书多出一个群就新建社群。不在这里修改人员的入群状态。

#### FR-2: 查看飞书社群人员

配上的社群能查看飞书社群人员。实现 UJ-1。

**可验收结果：**

- 社群上有字段「飞书社群人员」。
- 配上之后，列出的人是该飞书群的成员，人数与飞书社群人数使用同一次同步结果。
- 每一名成员显示飞书昵称、飞书ID、群内身份。飞书社群人员里不显示飞书手机号。
- 未配上、或从未同步时，飞书社群人员为空，不显示成 0 人。
- 成员列表只读。不能在飞书社群人员里把人移出飞书群。

### 4.2 人员管理

#### FR-3: 批量入群

林林勾选人员后点「批量入群」，把其中还未入群的人拉进飞书群。实现 UJ-2。

**可验收结果：**

- 人员管理有操作「批量入群」。
- 只处理林林勾选的人员。一条都没勾选时，不能点批量入群，也不会把列表里全部未入群的人一并拉群。
- 勾选项中，入群状态为未入群或入群失败的人员发起入群；入群状态为已入群的人员跳过，并说明已入群、未再次拉群。
- 目标飞书群是该人员已关联社群所配上的那个飞书群。人员没有关联社群，或该社群还没有配上飞书群时，这条变为入群失败，失败原因写「没有可加入的飞书群」。
- 同一次批量入群未返回前，批量入群不可再点。
- 结束后林林仍在人员管理。每条被处理的人员要么变为已入群，要么变为入群失败并带有失败原因。

#### FR-4: 显示入群状态和失败原因

人员管理能看出一个人是否已进入飞书群。实现 UJ-2。

**可验收结果：**

- 人员有字段「入群状态」，值只有已入群、未入群、入群失败。
- 还没执行过入群的人员，入群状态是未入群。
- 入群失败时，同一行能读到失败原因。失败原因来自这次入群的结果，不改写成别的固定文案；仅「没有可加入的飞书群」是本文件规定的原因。
- 已入群、未入群不显示失败原因。
- 入群成功只更新该人员的入群状态。飞书社群人员不在这一步改写，要等社群管理再次同步飞书信息才更新。

#### FR-5: 重新入群

入群失败的人员可以再拉一次。实现 UJ-2。

**可验收结果：**

- 入群状态为入群失败时，该人员有操作「重新入群」。已入群、未入群没有这个操作。
- 点重新入群，只处理这一条人员，目标飞书群与 FR-3 相同。
- 成功则入群状态变为已入群，失败原因清掉。
- 再失败则入群状态仍为入群失败，失败原因换成这一次的结果。
- 这一次未返回前，这条的重新入群不可再点。

### 4.3 导师管理

#### FR-6: 同步并展示飞书信息

导师管理能看到该导师的飞书昵称、飞书手机号和飞书ID。实现 UJ-3。

**可验收结果：**

- 导师管理对一位导师有操作「同步飞书信息」。一次只同步这一位，不提供全表一起同步。
- 同步成功后，飞书信息展示飞书昵称、飞书手机号、飞书ID。某个值这次没有返回，该格为空，不编一个值。
- 飞书手机号按同步结果原样显示，不打码。
- 同步失败时停留在导师管理，说明失败，不覆盖上一次已经写下的飞书信息。
- 未同步过的导师，飞书昵称、飞书手机号、飞书ID 都为空。

#### FR-7: 社群弹窗显示同步结果、人数和身份

导师现有的社群弹窗增加三列。实现 UJ-3。

**可验收结果：**

- 社群弹窗仍是现有关联数据的弹窗，一行一个已关联社群。本稿不增加、不删除关联。
- 每行有「是否已同步飞书信息」，值只有「是」或「否」。
- 每行有「飞书社群人数」。它是飞书机器人同步回来的该飞书群成员数量。
- 每行有「该导师群内身份」。它是飞书机器人拉回的、这位导师在该飞书群的群内身份。
- 群主、管理员只是群内身份的举例。该列按返回原文显示，不限于这两种身份。一次返回多个群内身份时，都显示。
- 该导师的飞书信息同步成功，且该行社群的社群名称与飞书群名称按 FR-1 的规则配上时，是否已同步飞书信息为「是」，并写下飞书社群人数和该导师群内身份。

#### FR-11: 社群导师点开导师浮层

阿宁在「社群导师」里点一位导师，导师浮层显示导师基础信息。实现 UJ-4。

**可验收结果：**

- 「社群导师」这个 Tab 始终在。不会出现一位导师都没有的情况。
- 导师团负责人（导师长）固定展示在第一位。其余导师按后台配置的身份上下级优先级从高到低展示；同一身份层级有多人时，采用后端返回顺序。后台如配置同级顺序，应由后端按配置顺序返回。前端不能把身份顺序硬编码为创业导师优先、助理导师随后。
- 每张导师卡片左侧显示头像、昵称和职责，右侧用标签显示身份。身份显示导师后台配置的标签。职责按原文显示。
- 点任一导师的卡片，打开导师浮层。浮层盖在社群页上，不把社群页挤窄，也不离开社群页。
- 导师浮层显示头像、昵称、身份、职责，以及导师介绍。导师介绍按原文显示，比卡片上的职责更完整。不显示手机号、飞书昵称、飞书手机号、飞书ID、收益，也没有编辑或进入飞书的按钮。浮层里没有「关闭」按钮。
- 点遮罩空白处关闭导师浮层，回到原来的社群页，滚动位置保持。点浮层里的内容不关闭。

**本条不覆盖：** 不在导师浮层里改身份或职责。不把导师组写成飞书群成员列表。

#### FR-12: 展示社群战绩

社群页根据后端控制分别显示社群战绩和收益荣誉榜。实现 UJ-4。

**可验收结果：**

- 「社区战绩」是一个 Tab。Tab 内有「社群战绩」和「收益荣誉榜」两个独立模块，两者的展示状态分别由后端控制，前端不写死为始终展示。
- 后端关闭社群战绩时，不显示社区本月总产出、活跃成员、你的社区排行、本月收益和团队成员收益；关闭收益荣誉榜时，不显示成员TOP-10。关闭其中一个不影响另一个。
- 后端同时关闭两个模块时，不出现「社区战绩」这个 Tab。后端开启某个模块但该模块没有可展示数据时，仍按本条后续的无数据规则处理。
- 社区本月总产出和活跃成员在同一行。你的社区排行和本月收益在下一行。
- 社区本月总产出是一个金额。活跃成员显示为「活跃人数 / 社群成员总数」。你的社区排行是名次。本月收益是金额，紧挨名次。每条团队成员收益显示成员名字、项目名称，以及该成员在该项目的单月收益。
- 数字按返回结果原样显示。某个数这次没有返回，该格为空，不编一个数，也不显示成 0。返回的数就是 0 时，显示 0。
- 收益荣誉榜沿用成员TOP-10规则，按收益从高到低。每一行显示头像、脱敏昵称、收益。脱敏昵称按返回原样显示。收益是金额。
- 后端开启社群战绩但五项都没有返回时，不显示社群战绩模块。后端开启收益荣誉榜但榜单没有返回成员时，不显示收益荣誉榜模块。两个模块最终都没有内容时，不出现「社区战绩」这个 Tab。
- 页上仍用现有标题「社区本月总产出」「你的社区排行」。需求里这一区叫社群战绩。不改这两个标题。
- 社群战绩和收益荣誉榜只读。点金额、名次、团队成员收益或收益荣誉榜成员不打开另一页。

**本条不覆盖：** 不解释金额怎么累加、活跃怎么判定、名次按哪一个金额排序。口径见第 6 节。
