## Component Patterns

行为如下。样子见 `DESIGN.md` 同名组件。

### 头图

只显示社群头像、社群名称、已加入天数。阿宁不能改这三项。

### 社群负责项目

该区域始终显示，且至少有一个负责项目。点项目图标或项目名称，是同一个目标：打开对应的项目详情页。迭代 Demo 不实现这次打开，点完仍停在社群页，不用提示假装已经打开。

一行无法容纳全部项目时，可横向滑动。每个项目都有图标和名称，都能滑到可视范围。不会出现没有图标的项目。

### 社群介绍

和社群导师、社区战绩用 Tab 切换，一次只看一块。有正文时显示全文，不折叠为需要点击「展开」的摘要。仅在已配置图片或视频时显示相应媒体，并将其放在正文之后。没有正文、也没有图片或视频时，「社群介绍」这个 Tab 不出现。

### 社群导师

该 Tab 始终显示，且至少有一位导师。列表先展示「导师团负责人」，导师长固定第一；再展示「导师团成员」，其余导师按后台配置的身份上下级从高到低排列，同一身份层级采用后端返回顺序。前端不硬编码创业导师、助理导师等具体身份的先后。

每张导师卡片显示头像、昵称、职责和身份标签。点任一行打开导师浮层。行上和浮层上的身份，都显示导师后台配置的同一个标签。

### 导师浮层

盖在社群页上，不离开社群页，也不把页面挤窄。里面是头像、昵称、身份、职责，以及一段比职责更完整的导师介绍。没有「关闭」按钮。点遮罩空白处关闭，点浮层里的内容不关闭。关掉后回到原来的滚动位置。

### 社群战绩

和社群介绍、社群导师用 Tab 切换。Tab 内有「社群战绩」和「收益荣誉榜」两个独立模块，后端分别控制是否展示。关闭一个只隐藏对应模块；两个都关闭时隐藏整个「社区战绩」Tab。

社群战绩里，社区本月总产出和活跃成员在同一行，你的社区排行和本月收益在下一行，下面是团队成员收益。收益荣誉榜沿用成员TOP-10规则，每行是头像、脱敏昵称、收益，按收益从高到低。

数字按后端返回值原样显示。某一格未返回值时，该格留空，不写成 0；返回值是 0 则显示 0。社群战绩五项都没有返回时隐藏社群战绩模块；收益荣誉榜没有成员时隐藏收益荣誉榜模块。两个模块最终都没有内容时隐藏「社区战绩」Tab。点金额、名次、团队成员收益或榜单成员不打开另一页。

社区本月总产出、你的社区排行这两个标题不改。本月统计周期从哪一天开始、活跃成员如何计算、名次按哪个金额计算，见 `prd.md` 第 6 节。口径补上之前不改画面。

### 个人介绍配置

导师视角直接进入配置页。头像、昵称和个人介绍默认可编辑，不需要先点编辑图标；当前身份显示后台配置值，置灰且不可编辑。

- 点头像或「更换头像」进入头像选择；选择后先在当前页预览，等待统一保存。
- 昵称使用有明确标签的文本输入框，进入页面显示当前昵称。
- 个人介绍使用多行文本框，与用户视角导师浮层里的导师介绍是同一份内容。
- 点保存时统一提交头像、昵称和个人介绍。作为 UX 防重复提交策略，保存中按钮不可重复点击。
- 保存成功只提示「保存成功」，停留当前页，信息保持展开；用户视角的社群导师列表与导师浮层展示最新头像、昵称和个人介绍。
- Demo 不接真实上传和持久化，刷新后恢复示例数据。头像文件限制和字段校验值未确认时不自行拦截。

### 进入社区飞书

点它离开社群页，去这个社群的飞书群。飞书群里的画面不在本文件。Demo 不打开飞书，按钮仍在。

### 场景切换器

用户视角用这些场景驱动手机里的社群页。导师视角固定展示个人介绍配置页。

| 场景 | 手机里 |
|---|---|
| 已加入 | 头图、至少两个负责项目、带图片或视频的介绍、导师长和多层级导师、社群战绩与收益荣誉榜都有数据、底部按钮 |
| 项目横滑 | 负责项目超过一屏，可滑到最后一项 |
| 导师浮层 | 浮层打开，里面有导师介绍。点空白处关闭，下面的社群页还在 |
| 介绍只有正文 | 介绍区没有图片和视频 |
| 没有社群介绍 | 「社群介绍」Tab 不出现 |
| 导师层级 | 导师长固定第一；其余导师按身份上下级和后端顺序展示 |
| 仅社群战绩 | 后端关闭收益荣誉榜，只显示社群战绩模块 |
| 仅收益荣誉榜 | 后端关闭社群战绩，只显示收益荣誉榜模块 |
| 两项都关闭 | 「社区战绩」Tab 不出现 |
| 战绩空格与零 | 有的格为空，有的格是 0，战绩区仍在 |

### 管理后台规则

三块只列新增项，正文不可点。

1. 社群管理：按钮「同步飞书信息」；字段「飞书社群人员」。
2. 人员管理：操作「批量入群」「重新入群」；字段「入群状态」。
3. 导师管理：操作「同步飞书信息」；字段「飞书信息」；社群弹窗三列「是否已同步飞书信息」「飞书社群人数」「该导师群内身份」。

同步中、入群失败、对不上名称，都只写在规则文案里。这一页没有可切换的失败画面。

### 需求规则抽屉

盖在迭代页上。可通过右上角关闭按钮、点击遮罩或按 Esc 键关闭。当前页签是管理后台时打开「后台需求」；当前页签是前端交互或业务流程时打开「前端需求」。

前端需求写社群页 FR-8 至 FR-12。其中业务流程一节，有图时只写「见本页业务流程」；这次还没有图，就写尚未写入。后台需求按上面三块列规则。

## State Patterns

| 状态 | 社群页 |
|---|---|
| 打开 | Demo 直接是当前场景的示例。不设加载中，不设加载失败 |
| 某一区没有数据 | 社群介绍没有数据时对应 Tab 不出现。社群负责项目和社群导师始终在 |
| 两个战绩模块都关闭 | 「社区战绩」Tab 不出现 |
| 只关闭一个战绩模块 | 保留「社区战绩」Tab，只显示后端开启且有内容的模块 |
| 战绩部分返回 | 社群战绩模块仍在。没返回的格为空，返回 0 的格写 0 |
| 社群战绩五项都没有 | 只隐藏社群战绩模块，不影响收益荣誉榜 |
| 收益荣誉榜没有成员 | 只隐藏收益荣誉榜，不影响社群战绩 |
| 导师浮层打开 | 社群页留在下面，滚动位置不动 |
| 导师浮层关闭 | 回到打开前的位置 |
| 未加入 | 没有这张页，也没有无权限提示 |
| 离线 | Demo 不表现 |

管理后台没有同步中、入群失败的页面状态。

| 状态 | 个人介绍配置页 |
|---|---|
| 初始 | 当前头像、昵称、只读身份和个人介绍全部展开 |
| 已选择新头像 | 当前页预览新头像，尚未保存 |
| 有未保存修改 | 保留输入内容，等待统一保存 |
| 保存中 | 保存按钮不可重复点击 |
| 保存成功 | 提示「保存成功」，停留当前页；Demo 刷新后恢复示例 |

## Interaction Primitives

- 横滑社群负责项目。
- 点一个项目：开发规则是打开对应的项目详情页。Demo 不离开社群页。
- 点「社群介绍」「社群导师」「社区战绩」：只显示对应的一块。
- 点社群导师的一行：打开导师浮层。
- 点遮罩空白处：关掉导师浮层。点浮层里的内容不关闭。
- 点「进入社区飞书」：离开社群页去飞书群。Demo 不画出飞书。
- 社群战绩与收益荣誉榜只读；两者是否存在由后端分别控制。
- 介绍随社群页滚动，没有「展开」。
- 点头像或「更换头像」：选择头像并在当前页预览。
- 编辑昵称与个人介绍：直接输入；当前身份不可聚焦编辑。
- 点保存：统一保存头像、昵称和个人介绍；成功后只显示 Toast，不跳转。
- 迭代页上可点的还有业务线、左侧菜单、页签、场景切换器和需求规则。管理后台的规则正文不可点。

## Accessibility Floor

- 项目一项、导师一行、底部按钮的点按高度至少 44px。
- 项目名称作为该项的名称读出。每一项都有图标。
- 导师行按昵称、职责、身份的顺序读出。身份是行右侧的标签；导师长排第一不能成为唯一的身份表达。
- 导师浮层是对话框，标题用这位导师的昵称。打开后焦点在浮层里。关掉后焦点回到点开的那一行。
- 横滑区除手势外，还须提供可访问的操作方式，确保每一项均可到达。
- 战绩空白单元格读作“空”；仅当返回值为 0 时读出“0”。
- 后端关闭的社群战绩或收益荣誉榜不进入无障碍树；保留的模块标题可被读出。
- 头像更换入口有可读名称「更换头像」；昵称输入框、个人介绍文本框都有可见标签；只读身份同时暴露只读状态。
- 金额使用 `{colors.brand-orange}`，并采用 `{typography.money}` 的字重。名次和人数用 `{colors.text-primary}` 加同样的字重。
- 社群名称用 `{colors.text-primary}` 写在 `{colors.surface-card}` 上。

## Key Flows

**UJ-4. 阿宁看社群页。**

阿宁已经加入这个社群。这一页不写她从哪进来。

1. 她看到社群头像、社群名称和已加入天数，以及社群负责项目。下面用 Tab 看社群介绍、社群导师、社区战绩。社群负责项目和社群导师始终在。没有社群介绍时对应 Tab 不出现；社群战绩和收益荣誉榜最终都不展示时，「社区战绩」Tab 不出现。
2. 负责项目超过一行时，她滑到想看的那一项。
3. 她点一个项目。开发规则是打开对应的项目详情页。项目详情页不在这次设计里。迭代 Demo 点完仍停在社群页。
4. 她点「社群导师」，先看到导师团负责人（导师长），再看到按身份上下级排列的其余导师。她点其中一位导师。
5. 高潮：导师浮层盖在这一页上，头像、昵称、身份、职责和刚才那一行相同，下面还有一段更完整的导师介绍。没有手机号、飞书信息和关闭按钮。她点遮罩空白处，页还在原来的位置。
6. 她点「进入社区飞书」，离开社群页，去这个社群的飞书群。飞书里的画面不在这里。

后端只开启一个战绩模块时，她只看到对应模块；两个都关闭时，她看不到「社区战绩」Tab，仍然可以进飞书。某个数没有返回时，那一格是空的，不显示成 0。

**UJ-5. 导师修改个人资料。**

1. 导师切到导师视角，直接进入个人介绍配置页。
2. 导师点当前头像选择新头像，在当前页看到预览；接着修改昵称和个人介绍。当前身份保持置灰，不能修改。
3. 导师点保存。保存期间不能重复提交。
4. 高潮：页面提示「保存成功」，仍停留在当前编辑页，头像、昵称、身份和个人介绍保持展开。
5. 阿宁回到用户视角后，在社群导师列表与导师浮层里看到最新头像和昵称，浮层里同时看到最新个人介绍。Demo 刷新后恢复示例数据。

**UJ-1. 林林核对社群管理规则。**

1. 林林打开这条需求的管理后台。
2. 社群管理一条写着「同步飞书信息」和「飞书社群人员」。
3. 高潮：这块文案和需求规则里的后台需求说的是同一件事。
4. 页上没有按钮可点。名称无法匹配时不新建、不删除；该规则只写在规则文案里。

**UJ-2. 林林核对人员管理规则。**

1. 同一页的人员管理写着「批量入群」「重新入群」和「入群状态」。
2. 高潮：入群失败要有失败原因、可以重新入群，这两句出现在规则里。
3. 页上没有勾选，也没有失败原因的弹出。

**UJ-3. 林林核对导师管理规则。**

1. 导师管理写着「同步飞书信息」「飞书信息」，以及社群弹窗的三列。
2. 高潮：三列的名字是「是否已同步飞书信息」「飞书社群人数」「该导师群内身份」。
3. 页上没有导师列表，也没有社群弹窗。

## Inspiration & Anti-patterns

层次参照品牌社群页：头图在上，下面是项目图标条和介绍。已加入社群页上原有的社群导师列表和「进入社区飞书」留下。战绩区标题仍是「社区战绩」，内部的社群战绩与收益荣誉榜按后端状态独立显隐。

不带进这一页的：社群公告、月收益排行榜、专精项目、社群案例、底部「加入社群」、参照画面上的「免费」。

## Responsive & Platform

桌面迭代页负责场景和规则。社群页只画在手机框里，不拉成桌面宽表。迭代壳窄于 1024px 时，场景和手机上下堆叠，沿用迭代外壳，本文件不另定断点。
