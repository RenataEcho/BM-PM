## Component Patterns

行为如下。样子见 `DESIGN.md` 同名组件。

### 头图

只显示社群头像、社群名称、已加入天数。阿宁不能改这三项。

### 社群负责项目

这一区始终在。不会出现没有负责项目。点项目图标或项目名称，是同一个目标：打开对应的项目详情页。迭代 Demo 不实现这次打开，点完仍停在社群页，不用提示假装已经打开。

一行放不下时横向滑。每个项目都有图标和名称，都能滑到可视范围。不会出现没有图标的项目。

### 社群介绍

和社群导师、社区战绩用 Tab 切换，一次只看一块。有正文就显示全文，不收成必须点「展开」的摘要。配了图片或视频才和正文一起显示，接在正文后面。没有正文、也没有图片或视频时，「社群介绍」这个 Tab 不出现。

### 社群导师

这个 Tab 始终在。不会出现没有导师。没有助理导师时不写人数那一行。标签是创业导师的排在前面，每人一行，身份在行的右侧。标签是助理导师的排在后面，并写出人数。点任一行打开导师浮层。行上和浮层上的身份，都显示导师后台配置的那个标签。

### 导师浮层

盖在社群页上，不离开社群页，也不把页面挤窄。里面是头像、名字、身份、职责，以及一段比职责更完整的导师介绍。没有「关闭」按钮。点遮罩空白处关闭，点浮层里的内容不关闭。关掉后回到原来的滚动位置。

### 社群战绩

和社群介绍、社群导师用 Tab 切换。五项至少有一项返回才出现这个 Tab。社区本月总产出和活跃成员在同一行。你的社区排行和本月收益在下一行。下面是团队成员收益，再下面是成员TOP-10。TOP-10 每行是头像、脱敏昵称、收益，按收益从高到低。数字按返回原样显示。某一格没有返回则该格为空，不写成 0。返回值是 0 则显示 0。点金额、名次、团队成员收益或 TOP-10 不打开另一页。没有战绩时，成员TOP-10 不单独出现。

社区本月总产出、你的社区排行这两个标题不改。本月从哪一天起、活跃怎么算、名次按哪一个金额，见 `prd.md` 第 6 节。口径补上之前不改画面。

### 进入社区飞书

点它离开社群页，去这个社群的飞书群。飞书群里的画面不在本文件。Demo 不打开飞书，按钮仍在。

### 场景切换器

前端交互用这些场景驱动手机。每个场景只改手机里的社群页。

| 场景 | 手机里 |
|---|---|
| 已加入 | 头图、至少两个负责项目、带图片或视频的介绍、两位创业导师和四位助理导师、五项战绩都有数、底部按钮 |
| 项目横滑 | 负责项目超过一屏，可滑到最后一项 |
| 导师浮层 | 浮层打开，里面有导师介绍。点空白处关闭，下面的社群页还在 |
| 介绍只有正文 | 介绍区没有图片和视频 |
| 没有社群介绍 | 「社群介绍」Tab 不出现 |
| 没有社群战绩 | 「社区战绩」Tab 不出现，成员TOP-10 也不出现 |
| 战绩空格与零 | 有的格为空，有的格是 0，战绩区仍在 |

### 管理后台规则

三块只列新增项，正文不可点。

1. 社群管理：按钮「同步飞书信息」；字段「飞书社群人员」。
2. 人员管理：操作「批量入群」「重新入群」；字段「入群状态」。
3. 导师管理：操作「同步飞书信息」；字段「飞书信息」；社群弹窗三列「是否已同步飞书信息」「飞书社群人数」「该导师群内身份」。

同步中、入群失败、对不上名称，都只写在规则文案里。这一页没有可切换的失败画面。

### 需求规则抽屉

盖在迭代页上。关闭用右上角、点遮罩或 Esc。当前页签是管理后台时打开「后台需求」；当前页签是前端交互或业务流程时打开「前端需求」。

前端需求写社群页 FR-8 至 FR-12。其中业务流程一节，有图时只写「见本页业务流程」；这次还没有图，就写尚未写入。后台需求按上面三块列规则。

## State Patterns

| 状态 | 社群页 |
|---|---|
| 打开 | Demo 直接是当前场景的示例。不设加载中，不设加载失败 |
| 某一区没有数据 | 社群介绍或社群战绩没有数据时，对应 Tab 不出现。社群负责项目和社群导师始终在 |
| 战绩部分返回 | 区仍在。没返回的格为空，返回 0 的格写 0 |
| 战绩五项都没有 | 战绩区不出现 |
| 导师浮层打开 | 社群页留在下面，滚动位置不动 |
| 导师浮层关闭 | 回到打开前的位置 |
| 未加入 | 没有这张页，也没有无权限提示 |
| 离线 | Demo 不表现 |

管理后台没有同步中、入群失败的页面状态。

## Interaction Primitives

- 横滑社群负责项目。
- 点一个项目：开发规则是打开对应的项目详情页。Demo 不离开社群页。
- 点「社群介绍」「社群导师」「社区战绩」：只显示对应的一块。
- 点社群导师的一行：打开导师浮层。
- 点遮罩空白处：关掉导师浮层。点浮层里的内容不关闭。
- 点「进入社区飞书」：离开社群页去飞书群。Demo 不画出飞书。
- 战绩只读。
- 介绍随社群页滚动，没有「展开」。
- 迭代页上可点的还有业务线、左侧菜单、页签、场景切换器和需求规则。管理后台的规则正文不可点。

## Accessibility Floor

- 项目一项、导师一行、底部按钮的点按高度至少 44px。
- 项目名称作为该项的名称读出。每一项都有图标。
- 导师行按名字、职责、身份的顺序读出。身份是行右侧的标签。
- 导师浮层是对话框，标题用这位导师的名字。打开后焦点在浮层里。关掉后焦点回到点开的那一行。
- 横滑区可以滑到每一项，不只有手势。
- 战绩空格读出为空。读出的 0 只出现在返回值就是 0 的时候。
- 金额除了 `{colors.brand-orange}`，还有 `{typography.money}` 的字重。名次和人数用 `{colors.text-primary}` 加同样的字重。
- 社群名称用 `{colors.text-primary}` 写在 `{colors.surface-card}` 上。

## Key Flows

**UJ-4. 阿宁看社群页。**

阿宁已经加入这个社群。这一页不写她从哪进来。

1. 她看到社群头像、社群名称和已加入天数，以及社群负责项目。下面用 Tab 看社群介绍、社群导师、社区战绩。社群负责项目和社群导师始终在。没有社群介绍或没有社群战绩时，对应 Tab 不出现。
2. 负责项目超过一行时，她滑到想看的那一项。
3. 她点一个项目。开发规则是打开对应的项目详情页。项目详情页不在这次设计里。迭代 Demo 点完仍停在社群页。
4. 她点「社群导师」，再点其中一位导师。
5. 高潮：导师浮层盖在这一页上，头像、名字、身份、职责和刚才那一行相同，下面还有一段更完整的导师介绍。没有手机号、飞书信息和关闭按钮。她点遮罩空白处，页还在原来的位置。
6. 她点「进入社区飞书」，离开社群页，去这个社群的飞书群。飞书里的画面不在这里。

战绩五项都没有返回时，她看不到战绩区，仍然可以进飞书。某个数没有返回时，那一格是空的，不显示成 0。

**UJ-1. 林林核对社群管理规则。**

1. 林林打开这条需求的管理后台。
2. 社群管理一条写着「同步飞书信息」和「飞书社群人员」。
3. 高潮：这块文案和需求规则里的后台需求说的是同一件事。
4. 页上没有按钮可点。对不上名称、不新建不删除，只写在规则里。

**UJ-2. 林林核对人员管理规则。**

1. 同一页的人员管理写着「批量入群」「重新入群」和「入群状态」。
2. 高潮：入群失败要有失败原因、可以重新入群，这两句出现在规则里。
3. 页上没有勾选，也没有失败原因的弹出。

**UJ-3. 林林核对导师管理规则。**

1. 导师管理写着「同步飞书信息」「飞书信息」，以及社群弹窗的三列。
2. 高潮：三列的名字是「是否已同步飞书信息」「飞书社群人数」「该导师群内身份」。
3. 页上没有导师列表，也没有社群弹窗。

## Inspiration & Anti-patterns

层次参照品牌社群页：头图在上，下面是项目图标条和介绍。已加入社群页上原有的导师组和「进入社区飞书」留下。战绩区标题仍是「社区战绩」。

不带进这一页的：社群公告、月收益排行榜、专精项目、社群案例、底部「加入社群」、参照画面上的「免费」。

## Responsive & Platform

桌面迭代页负责场景和规则。社群页只画在手机框里，不拉成桌面宽表。迭代壳窄于 1024px 时，场景和手机上下堆叠，沿用迭代外壳，本文件不另定断点。

## 2026-10-27 个人介绍 Demo 补充

个人信息页移除团队角色，点击个人介绍进入配置页。身份只读。演示中保存介绍后仅提示「保存成功」，停留编辑页且信息保持展开，无预览操作；返回放弃未保存编辑，刷新恢复示例。[ASSUMPTION] 保存按钮与返回放弃仅为 Demo 行为，头像和名称暂只展示；字数及必填口径待确认。

个人介绍整合回原 V1.2 迭代入口：前端交互左侧提供「用户视角 / 导师视角」，默认用户社群页；导师视角从个人信息页进入个人介绍配置。独立个人介绍入口跳转至原入口导师视角。

2026-10-27 优化：用户视角、导师视角使用前端交互顶部 Tab 切换；参考 AI 申词，左侧常驻展开当前视角的前端需求规则。导师视角直接进入个人介绍配置页，介绍默认可编辑，无需编辑图标。当前身份仍置灰只读。

2026-10-27 保存行为确认：保存后仅提示「保存成功」，保持当前编辑页和信息展开状态，不跳转、不提供预览操作。此规则替代此前保存返回和预览的演示行为。
