# PRD: 登录成功后才能看总览和需求内容

## 0. Document Purpose

本文件只覆盖「演示门」这一刀：预览在登录成功之前不展示总览和需求内容。读者是产品、后续 UX 与实现。正文 `FR-n` 是本增量里的序号。全局编号 `FR-0xx` 写在 front matter 的 `iteration_id`，目前未分配，不要把 `FR-1` 当成全局号。

本增量不归入「右豹主业务」「导师商务」「企业号」。它拦的是整份预览，不是某一条业务线里的功能。

已有页面：`demo/iteration/framework-shell.html`（总览）、`demo/iteration/index.html`（进入总览）、以及 `demo/iteration/` 下各需求页。本文件不改写其他迭代 PRD。尚无本增量自己的 `fr-*.html`。

## 1. Vision

团队要一起看需求演示，仓库保持公开，方便直接查看文件。预览本身加一道演示门：登录成功之前，总览和需求内容都不出现。

凭据只有一个写死账号。不接真实账号、接口和权限。门挡住的是预览画面；能读仓库的人仍能看到文件，也能看到写在页面里的口令。

## 2. Target User

### 2.1 Jobs To Be Done

- 同事打开预览时，先经过同一道演示门，再看总览和需求内容。
- 仓库继续公开，查文件不必先登录。
- 记住一个写死账号就能进入，不必申请账号、不必接公司登录。

### 2.2 Non-Users (v1)

- 右豹、导师商务、企业号产品里的终端用户。演示门不出现在那些产品画面里。
- 只在仓库里看文件、不打开预览的人。

### 2.3 Key User Journeys

**UJ-1. 林可打开公开预览，登录后看总览。**

- **Persona + context：** 林可是团队里要看需求演示的同事。仓库她可以直接看，预览她要先登录。
- **Entry state：** 未登录。她打开公开预览或本地预览的总览。
- **Path：** 画面只有演示门。她输入写死账号。校验通过。
- **Climax：** 总览出现，可以点进需求内容。
- **Resolution：** 她在这个浏览器里刷新，总览仍在，演示门不再出现。
- **Edge case：** 账号或密码不对时，仍停在演示门，并提示失败，总览不出现。

**UJ-2. 林可把一条需求链接发给同事，对方直接打开。**

- **Persona + context：** 同事手里是某一条需求页的地址，不是从总览点进去的。
- **Entry state：** 该浏览器未登录。
- **Path：** 打开链接，先看到演示门，看不到这条需求内容。登录成功。
- **Climax：** 出现的是这条需求页，含原来的 `?tab=`。
- **Resolution：** 刷新后仍是这条需求页。
- **Edge case：** 该浏览器已经登录时，再打开同一链接，直接看到需求内容，不再显示演示门。

## 3. Glossary

- **演示门** — 预览在展示总览或需求内容之前的登录检查。未通过时只显示登录，不显示总览，也不显示需求内容。
- **预览** — 两处都算：本地 `http://127.0.0.1:19889/`（目录 `demo/iteration`），以及公开 `https://renataecho.github.io/BM-PM/`。
- **总览** — `framework-shell.html`。`index.html` 进入总览，同样先过演示门。
- **需求内容** — 预览里除演示门以外的页面与画面，包括从总览点进去的需求页、直接打开的需求页、页内 Tab（`?tab=fe|admin|flow`）、组件规范。
- **写死账号** — 唯一凭据。账号 `admin`，密码 `bm@2026#Secure!`。写在预览页面中。大小写必须一致。
- **登录态** — 该浏览器已经用写死账号通过演示门。刷新不清除。
- **仓库** — 公开的 Git 文件。不经过演示门。

## 4. Features

### 4.1 演示门

**Description：** 任意预览地址在展示总览或需求内容之前都先过演示门。通过条件只有写死账号完全匹配。通过后进入这次要打开的地址。失败则留在演示门并提示失败。登录态在该浏览器内保留，刷新不需要再登录。实现 UJ-1、UJ-2。

#### FR-1: 未登录不展示总览和需求内容

访问者打开预览上的任一地址时，若该浏览器没有登录态，只能看到演示门。

**Consequences (testable):**
- 未登录打开总览、`index.html`、任一需求页、组件规范，画面中都没有总览导航、需求列表和需求正文。
- 本地 `19889` 与公开 `https://renataecho.github.io/BM-PM/` 行为相同。
- 地址栏里的路径和 `?tab=` 在登录成功前不被拿来渲染需求内容。

#### FR-2: 写死账号通过后进入原地址

访问者提交的账号与密码和写死账号完全一致时，演示门通过，并显示这次要打开的预览地址。

**Consequences (testable):**
- 账号 `admin`、密码 `bm@2026#Secure!` 通过。多一个空格、大小写不同，都不通过。
- 从总览入口登录成功，看到总览。
- 直接打开某条需求页并登录成功，看到该页；`?tab=fe`、`?tab=admin`、`?tab=flow` 仍按该地址打开。
- 已有登录态时再打开预览地址，直接显示该地址的总览或需求内容，不重复出现演示门。

#### FR-3: 失败时留在演示门并提示

提交与写死账号不一致时，登录不成功。

**Consequences (testable):**
- 账号错、密码错、任一为空，都留在演示门。
- 画面出现失败提示，文案为「账号或密码不正确」。
- 失败之后仍然看不到总览和需求内容。
- 不锁定、不延迟、不出现第二次验证。

#### FR-4: 刷新保持登录态

登录成功后，在同一浏览器刷新当前预览页，不需要再次登录。

**Consequences (testable):**
- 登录成功后刷新总览，总览仍在。
- 登录成功后刷新需求页，该页仍在，`?tab=` 仍在。
- 同一浏览器的新标签打开预览，也直接进入对应地址。[ASSUMPTION: 用户只明确「刷新不需要重新登录」。新标签共享登录态按此推广。]
- 清除该站点数据，或换一个浏览器，再次打开预览时回到演示门。

**Out of Scope:**
- 退出登录。
- 多账号、改密、找回密码。
- 把仓库改为私有，或让读文件的人看不到写死账号。

**Feature-specific NFRs:**
- 演示门先于总览和需求内容出现。未通过时，这些内容不出现在画面上。

**Notes:**
- [ASSUMPTION: 失败文案统一为「账号或密码不正确」，不区分是账号错还是密码错。]
- [ASSUMPTION: 登录成功后进入这次请求的地址，而不是一律送回总览。]

## 5. Non-Goals (Explicit)

- 不把仓库改成私有。公开仓库仍可直接查看文件。
- 不接真实登录、权限、接口或服务端会话。
- 不在产品 Demo 画面里加业务登录，也不在总览顶栏加头像、退出或通知。
- 不提供退出、注册、改密、找回、锁定。
- 不把本增量登记进某一条业务线。
- 不承诺对能阅读仓库或页面源码的人保密。写死账号就在预览页面里。

## 6. MVP Scope

### 6.1 In Scope

- 本地预览与公开预览都先过演示门。
- 一个写死账号。
- 失败提示。
- 刷新后仍保持登录态。
- 直接打开需求页时，通过后进入该页。

### 6.2 Out of Scope for MVP

- 全局编号 `FR-0xx` 的占号与总览登记。等产品给号再做。
- 视觉稿。演示门的样子留给后续 UX。
- 退出与多账号。

## 7. Success Metrics

**Primary**

- **SM-1**：未登录打开预览，看不到总览和需求内容；写死账号通过后能看到；刷新仍在。验收看 FR-1、FR-2、FR-4。

**Counter-metrics (do not optimize)**

- **SM-C1**：不要为了把门做严而把仓库改私有，或接上真实账号体系。那会偏离「仓库公开、只拦预览」。
