# FR-003「代发上融合任务」— Experience Spine

## 2026-10-22 二次评审：独立任务接取与稿件领取校验

此节为最新确认，覆盖此前将获取二维码与抖音号选择绑定的描述。

- **独立接取融合任务**：任务详情点击「获取二维码」直接生成当前用户专属任务二维码并标记当前融合任务已接取；后续可刷新二维码。不校验报名状态、不选择或绑定抖音号，不创建稿件领取记录。
- **领取稿件的校验顺序**：稿件详情点击「立即领取」先检查报名状态；未报名沿用报名提示和入口。已报名再检查当前稿件关联的融合任务是否已接取；未接取弹窗提示「您尚未接取当前稿件关联的融合任务，请先接取任务后再领取稿件。」，按钮「去接取任务」跳转融合任务详情。报名且已接取关联任务后，才选择本人合格抖音号并领取稿件。其他任务的已接取状态不能替代当前关联任务。
- **申请记录**：报名页底部左侧增加图标加「申请记录」入口，右侧保留提交报名。记录页提供全部、待审核、审核通过、已驳回筛选；卡片展示申请时间、审核状态、抖音昵称、抖音号、五项资质截图及已有审核意见。返回报名保留未提交的填写内容。Demo 提交生成本地待审核记录，不调用服务或持久化。
- **删除不合格抖音号**：选择领取抖音号浮层中，仅不合格账号右侧显示垃圾桶图标。点击弹出确认删除提示，取消保留原账号，确认后从本地可选账号列表移除；合格账号、待审核账号不显示此删除图标。删除不影响历史申请记录或已领取稿件关联信息。
- **演示边界**：二维码为不可用于真实扫码的本地示意；截图仅保留当前页面会话内的本地文件引用。复用现有组件样式与浮层，无真实接口、登录、权限或持久化。
- 业务流程：见本页业务流程。

## 2026-10-22 浏览器评审确认

以下为最新确认口径，替代旧版冲突描述。

- 融合项目仅使用任务协作，隐藏账号运营；移除账号运营、待审核、驳回修改的重复演示。
- PC 完整填写项沿用 FR-001：书籍名称、书籍 ID、书籍类型、书籍链接、剪辑手提醒、发布技巧、文件夹/文件与成片。去掉检索星图任务、示例书籍和匹配状态提示；下一步拦截文案「书籍名称/ID未匹配到星图任务，请先检查修正。」，仅「知道了」关闭。
- 稿件详情保留立即领取；快捷提词改为接取任务，进入融合任务详情。获取用户专属二维码即接取融合任务成功。Demo 仅内存模拟，不生成真实任务凭证；结算周期与比例 [待确认]。
- 报名提示「为保障您正常接取融合任务，领取融合任务前，请先填写抖音号信息报名参与。」表单包含抖音昵称、抖音号、账号无违规截图、已实名且已成年截图、已设置提现截图、总粉丝量大于1000截图、有效粉丝数大于500截图，复用现有人工审核。
- 回填仅校验解析出的作品发布抖音号与领取稿件关联账号一致，不实时校验视频 ID。失败标题「提交失败」，正文「作品关联抖音号与领取稿件选择的抖音号不一致，请使用领取稿件选择的抖音号参与任务发布作品。」保留输入，本次失败不记违规。
- 运营后台定时拉取抖音任务数据。列表「实际参与信息」仅显示平台名/发布者昵称，如抖音/林林说漫；明细保留官方平台、昵称、链接与视频 ID，无匹配显示「-」。
- 超时记录「下载」「已超时」均置灰禁用，释放与停权沿用既有规则。
- 业务流程：见本页业务流程。

## Foundation

多端体验：创作者手机端、剪辑手 PC 客户端、运营既有管理后台。创作者端是领取与视频回填的主要表面；剪辑手在 PC 端供稿；运营沿用现有开白表单审核和稿件/领取记录管理。

不引入新的 UI 系统。各端分别继承右豹既有组件和行为规范。`DESIGN.md` 是本需求视觉合同，负责表达层级和外观；本文定义导航、状态、交互与边界。关键视觉 token 通过 `{colors.brand-orange}`、`{colors.brand-orange-soft}`、`{colors.text-primary}`、`{colors.text-secondary}`、`{colors.surface-page}`、`{colors.surface-card}` 引用。后台及迭代外壳分别继承 `docs/design/admin-ui-spec.md` 和 `docs/design/iteration-shell/EXPERIENCE.md`。

## Information Architecture

| 表面 | 到达方式 | 目的与职责 |
|---|---|---|
| PC 客户端稿件上传 | 剪辑手既有供稿入口 | 上传融合任务稿件，填写书籍名称、ID、类型、链接与成片，确认星图任务匹配并提交审核 |
| 一键代发广场 | 创作者既有入口 | 用项目筛选查看融合短剧、融合漫剧、融合故事稿件，进入领取流程 |
| 抖音号报名 | 无报名号时由领取提示进入；已有账号时由选择 Sheet 进入 | 复用现有开白表单提交报名信息和资质截图 |
| 抖音号选择 Sheet | 有已报名账号时点击「立即领取」 | 选择一个本人已审核通过且满足资质的报名抖音号；可进入既有表单添加其他账号 |
| 视频回填 | 已领取稿件后进入 | 显示领取时关联抖音号，填写视频链接并确认回填 |
| 既有运营后台 | 运营现有菜单 | 审核账号与稿件，查看领取记录、实际参与信息、违规标记和多条回填明细 |


## Voice and Tone

沿用右豹现有短句与操作文案。提示说明当前发生了什么、下一步可以怎么做；不把校验阻断称为违规，也不暗示用户已被处罚。

| 场景 | 建议用语/行为 |
|---|---|
| 书籍或任务匹配失败 | 说明书籍名称/ID 未匹配到星图任务，请检查后重试；不显示可继续提交的成功态 |
| 没有报名账号 | 提示需先报名，主操作「立即报名」进入现有表单 |
| 账号不满足领取条件 | 说明当前没有可用于领取的合格抖音号，并沿用账号审核/报名入口；具体状态文案复用既有页面 `[ASSUMPTION]` |
| 解析账号不一致 | 使用 PRD 确认原文：「提交失败」 |
| 官方内容暂无对应记录 | 后台对应字段显示「-」，不借用其他领取记录或创作者手填信息 |

避免使用会让用户误认为违规的即时校验文案。领取超过既有 24 小时未回填后的涉嫌违规状态仍按既有一键代发规则处理。

## Component Patterns

行为规范；视觉规格见 `DESIGN.md`。

| 组件/模式 | 行为 |
|---|---|
| 星图任务匹配字段 | 沿用 FR-001 完整填写项，点击下一步校验星图任务；未匹配弹窗阻断，只保留知道了，不增加检索按钮或状态行 |
| 稿件审核状态 | 使用既有「待审核 / 已通过 / 已驳回」；驳回结果返回剪辑手修改并再次提交。稿件状态仍使用「正常 / 已删除」，不得将「正常」视作审核通过 |
| 融合任务项目筛选 | 一键代发广场新增「融合短剧」「融合漫剧」「融合故事」筛选值，筛选对应稿件 |
| 无报名账号领取 | 点击领取时给出报名引导；「立即报名」跳转现有开白表单，完成后按既有审核流程处理 |
| 抖音号选择 Sheet | 展示本人已报名账号；只能选择审核通过且满足账号资质要求的合格抖音号；一次领取关联一个账号；「其他抖音号报名」进入既有表单 |
| 账号报名审核 | 复用现有开白表单、审核页面、状态和截图查看方式。运营核验无违规、已实名且成年、已设置提现、总粉丝量 >1000、有效粉丝量 >500，且有资质截图后方可通过；不新增表单字段、审核流程或页面 |
| 回填抖音号 | 显示本次领取关联的账号，只读。不能切换到用户的其他账号 |
| 视频链接回填 | 编辑链接时不提前形成有效回填或分账；只有用户点击「确认回填」后才解析账号和视频 ID。解析失败允许修改后重试 |
| 即时回填校验 | 按最新评审口径：融合仅任务协作，回填仅校验关联账号，官方数据定时拉取。 |
| 回填成功 | 按最新评审口径：融合仅任务协作，回填仅校验关联账号，官方数据定时拉取。 |
| 领取记录 | 每次领取单独形成一条记录；「实际参与信息」展示官方实际发布账号、视频 ID 和 URL。「涉嫌违规」取值是/否，来源和更新沿用一键代发现有规则 |
| 回填数量明细 | 按最新评审口径：融合仅任务协作，回填仅校验关联账号，官方数据定时拉取。 |

## State Patterns

### 回填明细容器与字段

「回填数量」点击后使用居中只读弹窗，保留 PRD 已确认的弹窗形式；不改成编辑表单或详情抽屉。多条记录在弹窗正文内滚动，标题标明当前稿件，关闭后回到触发数量链接，背景列表不被挤压。Demo 复用组件规范页的 `.modal-overlay` / `.modal`，内容区域尺寸适配既有容器；实际后台沿用现有只读弹窗能力。排序、分页和零条表现仍为待确认项。

| 每条记录分组 | 必须展示的字段 |
|---|---|
| 创作者信息 | 用户昵称、用户 ID |
| 回填信息 | 投稿平台（抖音 / 快手 / 小红书等）、昵称、视频链接、视频 ID、发布日期、作品类型（图文 / 视频 / 其他）、内容类型（如漫剧 / 真人演绎 / 解压 / 解说） |
| 实际参与信息 | 官方拉回的平台名称、昵称、视频链接、视频 ID；无法匹配时显示「-」 |

三组保持逐条对应，不能把所有创作者与所有视频分别汇总。视频链接可以查看对应内容；通用明细中的多平台字段不代表本次融合任务领取支持抖音之外的报名账号。

| 状态 | 表面 | 行为与反馈 |
|---|---|---|
| 匹配未完成/无匹配 | PC 上传表单 | 阻断下一步；指出需检查的书籍名称、书籍 ID 或匹配结果 |
| 待审核 | 稿件/报名审核 | 不进入可领取状态；显示既有待审核状态 |
| 已驳回 | 稿件/报名 | 允许按既有流程查看结果、修改后重新提交 |
| 报名账号审核通过且资质合格 | 抖音号选择 | 可以被选为本次领取账号，并可在后续任务复用 |
| 已报名但尚无合格账号 | 领取入口/选择 Sheet | 已接取关联融合任务后打开账号选择浮层；异常账号不可选、确认领取禁用，引导使用其他抖音号报名。 |
| 已领取、未回填 | 稿件领取/回填 | 关联账号固定；时限与超时释放/停权沿用一键代发现有规则 |
| 解析失败 | 回填页 | 不完成回填；保留链接供修正，不建立分账绑定 |
| 解析账号不一致 | 回填页 | 显示确认文案，允许重填；当前失败不记违规 |
| 校验通过 | 回填页/收益 | 标记回填成功并按一键代发规则形成分账绑定 |
| 官方实际参与信息未匹配 | 运营领取记录/回填明细 | 只在对应记录显示「-」，不串用其他记录；不因此记违规 |
| 零条回填记录 | 回填数量明细 | `[ASSUMPTION]` 空态样式与说明待核实现有能力；不得把未回填领取或仅关联/领取关键词计作回填 |
| 明细字段缺失 | 回填数量明细 | `[ASSUMPTION]` 缺字段表现待核实现有能力；已明确无官方匹配时显示「-」 |

回填数量的排序、分页方式 `[ASSUMPTION]` 待核对既有后台能力。所有未确认的展示方式不作为新增产品规则。

## Interaction Primitives

- 回填分两步：编辑链接，再由用户显式点击「确认回填」触发解析和校验。不能在输入时静默确认或显示已分账成功。
- 失败反馈不清空用户输入、不改写领取关联账号、不改变领取次数或违规累计。接口视频 ID 拉取失败沿用现有系统处理，不增加 FR-003 专属重试策略。
- 抖音号选择、提示遮罩与按钮遵循移动端既有手势。Demo 中只模拟反馈，不接接口、登录、权限或持久化。
- 后台操作沿用既有详情和表格交互；回填数量打开详情时作用域锁定当前稿件，不能混入其他稿件。

## Accessibility Floor

- 所有可选抖音号提供可读名称与选中状态；屏幕阅读器可辨别禁用项及禁用原因。
- 输入校验错误与状态均有文字，不只依靠颜色或图标。错误信息与对应输入关联，读屏焦点可到达首个错误项。
- 回填抖音号明确标注为只读/不可切换；不把看似可编辑的下拉控件用于只读值。
- Sheet/弹层有可访问名称，打开后焦点进入浮层，关闭后返回触发控件；键盘和辅助技术可完成操作。
- 后台新增信息列提供可读列名；视频 URL 可由键盘访问，链接的可访问名称能识别其为视频内容链接。
- 遵循移动端和管理后台规范的目标尺寸、键盘顺序、对比度与减少动态效果要求；本需求不降低既有无障碍底线。

## Key Flows

### Flow 1 — 剪辑手小林上传融合稿件

1. 小林从 PC 客户端既有供稿入口新建稿件，选择融合任务类型并填写书籍名称、书籍 ID。
3. 匹配成功后她提交审核，稿件进入既有运营审核。
4. 审核未通过时稿件返回修改；审核通过后进入一键代发稿件池。
5. **高潮：** 审核通过的稿件出现在可领取池中，稿件匹配关系和审核状态可追溯。

角色名称「小林」仅为流程叙述占位，不代表新增用户画像。

### Flow 2 — 创作者小周报名并领取

1. 小周在一键代发广场按「融合短剧 / 融合漫剧 / 融合故事」筛选任务稿件。
2. 她点领取；若没有报名抖音号，提示通过「立即报名」进入现有开白表单并提交资质截图。
3. 运营沿用既有流程核验账号资质。审核不通过时小周可修改并重新提交；通过后合格账号可复用。
4. 她再次点「立即领取」，在底部 Sheet 选择一个合格抖音号；如需新增账号，可转到「其他抖音号报名」。
5. 点击接取任务进入融合任务详情，获取用户专属二维码即为接取融合任务成功。
6. **高潮：** 领取记录固定关联本次选择的抖音号，后续回填沿用这个账号。

若已有报名记录但没有合格账号，阻止领取并提供已有报名审核入口；具体状态文案 `[ASSUMPTION]`。

### Flow 3 — 创作者小周回填并形成收益绑定

1. 小周进入已领取稿件的回填页面，看到领取时选择的抖音号；该账号只读。
2. 她填写视频链接，点击「确认回填」后系统才解析账号和视频 ID。
3. 解析账号与关联抖音号不一致时，页面提示「提交失败」；她修正链接重试，当前失败不记违规。
4. 账号一致即可提交，不进行同步视频 ID 比较；运营后台定时拉取抖音任务数据。

### Flow 4 — 运营核对稿件回填

1. 运营在既有稿件列表找到目标稿件，查看审核状态与稿件状态。
2. 打开领取记录，按记录核对领取关联账号、领取次数、实际参与信息及涉嫌违规状态。
3. 点击稿件的回填数量，逐条查看创作者信息、手工回填内容和官方参与任务内容。
5. **高潮：** 运营可将官方内容与创作者回填分组比对并定位具体领取记录；官方内容无法匹配时看到「-」，不会误用其他记录信息。

## Product-Specific Boundaries

- 账号资质条件为：无违规、已实名且成年、已设置提现、总粉丝量 >1000、有效粉丝量 >500，并上传资质截图。任何条件不满足都不能成为合格抖音号。
- 「已报名」不等于「审核通过」，审核通过也仍需满足完整资质条件。
- 领取时账号关联对后续回填锁定；不可在回填时改用其他已报名账号。
- 即时回填校验失败、官方实际参与信息无法匹配、回填数据与官方内容不再执行的事后比较均不新增违规。未回填超时等既有规则仍然有效。
