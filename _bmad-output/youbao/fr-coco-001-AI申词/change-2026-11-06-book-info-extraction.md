# Sprint Change Proposal：书籍录入与信息提取

## 1. Issue Summary

### 触发项

- 触发故事：FR-CoCo-001 / CAP-2「添加书籍」。
- 变更类型：开发中收到的新增产品要求。
- 当前状态：FR-CoCo-001 已有 PRD、DESIGN、EXPERIENCE、SPEC 和可操作 Demo；README 与总览状态为「开发中」，未发现独立 Epic/Story 文件。

### 问题

当前方案允许在一个输入框内以空格或逗号批量录入多个书籍 ID，并在输入时自动匹配；匹配失败后允许手填书名。新要求改为：

1. 每个输入框只接收一个书籍 ID，不解析逗号或其他分隔符。
2. 用户点击「添加」增加新的书籍 ID 输入行，逐行输入多本书；按 Enter 不执行添加。
3. 用户填完后统一点击「提取书籍信息」，由接口逐本提取书籍名称和书籍简介。
4. 提取失败显示「未提取到信息」。
5. 提取成功显示书籍名称；点击名称打开浮层，展示书籍 ID、名称、简介、封面和链接。

### 证据

- `prd.md`、`EXPERIENCE.md`、`SPEC.md` 和 `frontend-rules.json` 当前均写明“多个 ID 用空格或逗号分开”。
- 当前 Demo 在 `idInput` 的 `input` 事件中直接拆分 ID 并自动渲染书籍，没有「添加」或「提取书籍信息」动作。
- 当前合同规定书籍卡不展示简介；新要求将简介改为提取结果，并要求在详情浮层内查看。
- 当前失败口径是「未找到该本书」并手填书名；新要求指定失败文案为「未提取到信息」，没有继续保留手填书名的明确要求。

## 4. Detailed Change Proposals

### 4.1 PRD：关键路径与 Glossary

**OLD**

> 输入一个或多个书籍 ID，或在官方推荐里添加。在 fanqie_book_list 里对得上的书带出封面、名称、书籍 ID、链接。对不上的，页面写「未找到该本书」，小明自己填写书籍名称。

**NEW**

> 每个输入行填写一个书籍 ID；需要多本书时点击「添加」增加输入行。填完后统一点击「提取书籍信息」，系统通过书籍信息接口逐本提取名称和简介。提取成功后显示书籍名称，点击名称可在浮层查看书籍 ID、名称、简介、封面和链接；未提取到时显示「未提取到信息」。

**理由**

将录入、加入列表和信息提取拆成三个可验收动作，避免输入即请求及批量分隔解析。

### 4.2 PRD / SPEC：CAP-2

**OLD**

> 多个书籍 ID 用空格或逗号分开。对不上时留在申词页，文案是「未找到该本书」，并有书籍名称输入。

**NEW**

- 每个输入行只接受一个书籍 ID；含逗号、空格分隔的多个 ID 时不拆分，并提示逐本填写。
- 点击「添加」只增加一个新的空白 ID 输入行，不触发提取；按 Enter 不执行添加。
- 空白的附加输入行可移除；至少有一个非空 ID，且不存在格式错误或重复 ID 时，「提取书籍信息」才可点击。
- 重复 ID 标出并提示「书籍 ID 重复」，不发起提取。
- 点击统一的「提取书籍信息」后，系统按输入行逐本返回结果。
- 提取中「提取书籍信息」不可重复点击，并显示加载状态。
- 成功后显示书籍名称；点击名称打开浮层，展示书籍名称和书籍简介。
- 详情浮层展示书籍 ID、书籍名称、书籍简介、封面和链接。
- 失败或返回空结果时显示「未提取到信息」，支持对该项重新提取或移除，不提供手填书名。
- 存在待提取、提取中或提取失败项时不能 AI 申词；用户需提取成功或移除相应项。

**理由**

覆盖单条添加、重复校验、异步请求、成功详情与失败恢复，形成完整状态闭环。

### 4.3 DESIGN / EXPERIENCE：书籍组件与浮层

**OLD**

> 添加书籍有两个页签。输入页可一次填多个 ID，空格或逗号分开。每本对得上的书一张卡：封面、名称、书籍 ID、链接，可移除。卡片不放简介。

**NEW**

- 不设页签和官方推荐；采用动态输入行，每行只填一个 ID，「添加」放在当前输入行下方。
- 输入区下方提供统一的「提取书籍信息」按钮。
- 待提取：保留 ID 输入行，统一按钮可触发提取。
- 提取中：逐行显示加载反馈，统一按钮禁止重复触发。
- 提取成功：不生成独立卡片，只在对应输入框下显示紧凑的可点击书籍名称，不显示书籍 ID。
- 提取失败：在对应输入框下显示「未提取到信息」和文字按钮「重新提取」；输入行仍可移除。
- 点击成功项的书籍名称打开详情浮层；浮层展示书籍 ID、名称、简介、封面和链接，并支持明确关闭。
- 列表区不再展示独立书籍卡片，避免多本书时页面过长。

**理由**

让“添加”和“提取”两个动作可见，并将长简介放在按需查看的浮层中。

### 4.4 状态与申词门槛

**OLD**

> 至少一本可用的书即可 AI 申词；可用指在列表里对得上，或小明已经填写名称。

**NEW**

> 至少一本书提取成功，且本次不存在待提取、提取中或提取失败的书籍时，AI 申词才可点击。增加或修改 ID、移除书籍、重新提取或提取结果变化后，清空当前词和提交反馈。

**理由**

避免把缺少名称/简介的数据送入现有生成提示词；该门槛已经产品确认。

### 4.5 addendum：接口契约

新增“书籍信息提取接口”小节，至少记录：

- 请求：一组书籍 ID，或前端逐本请求，具体形式待接口方确认。
- 成功响应：逐本返回书籍 ID、书籍名称、书籍简介、封面和链接。
- 空结果：前端显示「未提取到信息」。
- 异常：保留已添加 ID，允许重新提取，不静默删除。
- 并发：统一提取进行中不重复请求；失败项重新提取时不影响成功项；移除后返回的旧请求结果不得重新插入列表。

接口地址、方法、字段名、超时时间和错误码在拿到接口文档前标 `[ASSUMPTION]`，Demo 不编造真实接口。

### 4.6 Demo 与研发规则

- 删除 ID 分隔解析和输入即自动渲染。
- 增加动态 ID 输入行、「添加」、统一的「提取书籍信息」、失败项「重新提取」及对应模拟状态；按 Enter 不执行添加。
- 至少提供一个提取成功示例和一个「未提取到信息」示例。
- 增加书籍信息浮层，展示 ID、名称、简介、封面和链接，并验证关闭后仍保留列表状态。
- 同步修改流程 SVG：逐行输入 ID / 点击添加增加输入行 → 统一提取 → 逐本判断是否成功 → 成功查看详情 / 失败重试或移除。
- 同步 `frontend-rules.json` 和规则抽屉，移除旧的逗号批量输入与手填书名规则。
- 官方推荐模块已在后续体验收敛中移除。
