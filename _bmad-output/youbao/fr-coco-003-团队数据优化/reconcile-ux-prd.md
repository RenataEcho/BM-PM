# FR-CoCo-003「团队数据优化」UX Spines × 产品输入对账

## 1. 范围与方法

本次只对账以下产品输入与 UX spines，不检查 Demo 实现，也不以视觉实现细节反向挑战产品规则：

- 产品输入：`prd.md`、`addendum.md`
- UX spines：`DESIGN.md`、`EXPERIENCE.md`

检查范围为全部产品 IA 表面、FR-1～FR-11 的可见或交互后果、页面状态、排名与筛选、逐层返回恢复、P01/P02/P03/P05/P06 边界，以及“不新增管理后台产品页”约束。

## 2. Verdict

**有条件通过，无新增产品口径阻塞。**

UX spines 已覆盖 S1 团队数据入口、S2 项目数据首页、S3 项目详情/成员排行榜、S4 成员奖励详情，以及作为评审载体而非产品 IA 的 D1 迭代外壳；FR-1～FR-11 的主要 UX 后果、状态、排名/筛选和返回恢复均已进入体验合同。P01/P02/P03/P05/P06 均被正确保留为“只传递待确认状态、不由 UX 或非负 Mock 代选方案”。本 FR 明确没有管理后台产品页，也不新增管理后台 Tab。

仍有 **2 个真实但非阻塞的文档缺口**：一个是产品与 UX 的冲突优先级表述歧义，一个是项目详情的项目 ID 字段与跨层一致性未显式落入 UX 合同。除这两项外，未发现会改变产品范围、统计口径或主要交互结果的遗漏或冲突。

## 3. 真实缺口

### G1｜优先级句子可能允许 UX 反向覆盖产品规则

- **位置：** `EXPERIENCE.md` Information Architecture 末段。
- **现状：** “双 spine 与 PRD 在冲突时优先”按当前语法可被理解为 DESIGN/EXPERIENCE 与 PRD 冲突时由双 spine 优先。
- **冲突：** `prd.md` 定义产品范围、统计、字段、状态和验收后果；`addendum.md` 也明确参考文件的 Mock 和内嵌规则不得覆盖 PRD。视觉与载体可以由双 spine 定义，但不能据此覆盖 FR-1～FR-11 的产品行为。
- **影响：** 后续实现者可能把 UX 视觉或旧行为当作覆盖产品口径的依据。
- **建议收口：** 将优先级限定为“DESIGN/EXPERIENCE 在视觉与体验载体上优先于 mock、截图和导入物；产品字段、统计、权限与验收结果以 PRD/addendum 为准”。这是文档消歧，不需要新增产品决策。
- **严重度：** Medium，非阻塞。

### G2｜S3 未显式承接项目 ID 字段和跨层一致性

- **位置：** `DESIGN.md` 的项目卡/详情组件描述；`EXPERIENCE.md` 的 S3 IA、奖励 Hero 与 Flow 2。
- **现状：** UX spines 使用“项目身份”“当前项目”等概括表述，但没有明确写出 S3 项目详情须承载项目 ID，也没有明确写出该 ID 与 S2 所选项目及 S3 成员榜查询项目保持一致。
- **产品要求：** FR-4 要求项目 ID 在项目列表与成员排行榜之间保持一致；FR-5 要求项目详情中的项目 ID、项目名称和金额与所选项目一致。
- **影响：** 项目名称相同、重名或名称变更时，仅凭名称不足以形成可验收的跨层身份合同。
- **建议收口：** 在 S3“项目身份”中显式列出项目 ID，并写明 S2 项目卡 → S3 详情/成员榜沿用同一项目 ID；无需要求 S2 项目卡额外显示项目 ID。
- **严重度：** Low，非阻塞。

## 6. 排名、筛选与返回恢复

### 排名与筛选

- 名次基于当前项目、时间范围和奖励归属筛选后的奖励金额降序计算。
- 同额采用竞赛排名 `1、2、2、4`，并按用户 ID 稳定展示。
- 昵称搜索只缩小可见集合，保留当前筛选榜单原始名次；分页/加载更多不局部重算。
- 奖励升序和昵称排序只改变 display order，不重算 rank。
- 未筛选归属时允许多个归属标签；筛选单一归属后只显示所选归属。
- 成员占比分母保持为同时间范围的项目奖励，不变成搜索结果、归属筛选或当前页成员小计。

**结论：无排名或筛选冲突。**

### 返回恢复

- S4→S3：恢复时间、自定义日期、搜索、归属、展示排序、原名次和滚动位置。
- S3→S2：恢复构成时间、项目排序和滚动位置。
- S2→S1 后再次进入 S2：恢复上次分析上下文。
- 用户主动刷新才允许建立新统计时点；静态 Demo 刷新回演示初始态不被误写为生产持久化。

**结论：逐层恢复覆盖完整，无冲突。**

## 7. 状态对账

已区分并承接以下状态，没有把它们合并成统一“暂无数据”：

- 首次加载骨架与首次加载失败 + 重试；
- 无项目；
- 图表当前范围无奖励；
- 项目无成员奖励；
- 搜索无结果；
- 成员无历史记录；
- 加载更多失败且保留已加载内容；
- 今日/昨日为 `0.00`；
- 停用项目历史仍可见。

P06 的负值、净额非正和正负抵消为 0 没有被错误归入普通空态。UX 未擅自隐藏负值、截断为 0、绘制负值环形图或选择其他生产展示方案。

## 9. 最终结论

- **Verdict：有条件通过。**
- **阻塞性：无新增阻塞；沿用 PRD 已登记的 P01/P02/P03/P05/P06 正式开发门禁。**
- **真实缺口：2 个。**
  1. UX 与 PRD 冲突时的优先级句子存在反向覆盖产品规则的歧义。
  2. S3 项目详情未显式列出项目 ID 及其与 S2/S3 查询上下文的一致性。
- **其余重点：** IA、FR-1～FR-11 的主要 UX 后果、状态、排名/筛选、返回恢复、P-ID 边界和“无管理后台页”均已对齐。
