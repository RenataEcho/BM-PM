# 批量传订单 · SPEC 草稿

## 数据合同

- 一份源表单对应一个批次 ID，具有原文件名、项目 ID、上传人、上传时间、处理状态和进度。
- 处理结果包含成功行、失败行、行号、失败原因、订单量与订单金额。
- 审核记录包含审核人、时间、结果、批次版本。
- 分发记录包含批次 ID、项目 ID、分发状态、时间和重试信息。
- 项目订单保存项目 ID、订单业务键、审核状态及来源批次。

## 状态合同

处理状态为处理中、处理完成、部分失败、处理失败。审核状态为未审核、已审核。分发状态为待分发、分发中、分发成功、分发失败。进度不代替状态。

## 行为合同

1. 前端按文件名映射项目，允许操作人员对单条表单从已有项目中单选覆盖。服务端须验证项目有效且用户有访问权限。
2. 一键处理对每个表单创建独立任务。进度由服务端返回，不由前端定时器作为业务事实。
3. 处理中表示订单仍在校验；部分失败、处理失败表示部分订单未上传成功，或订单与关键词归因关系校验异常。失败文件需包含失败原因。
4. 只有处理完成表单可一键审核并发起分发。审核成功后创建分发组记录，并由服务端按已确认的项目 ID 分发；服务端以批次状态、审核权限及版本做最终校验。
5. 分发列表每个审核成功的订单表单组记录一行。即使后续分发失败，也保留该组供查看和重传；审核状态与分发状态分别维护。
6. 分发成功行编辑为空；分发失败行可触发重传。若重传前校验发现审核未完成，前端二次确认，后端仍独立校验。
7. 失败表单重传与原批次关联，更新原批次状态及统计。合并策略和订单去重键由研发评审确定。

## 验收合同

- 文件类型、项目映射、单项目选择和未映射阻断符合需求。
- 每文件任务状态与进度正确，重传更新原行。
- 非处理完成状态无法审核；并发或重复审核由服务端安全处理。
- 审核结果产生项目分发记录；分发失败重传与未审核二次确认可验证。
- 成功分发编辑为空，订单审核与分发状态分别展示。

## 待研发评审

上传与下载接口、进度推送、审核 API、分发任务 API、幂等键、行级错误格式、重传版本控制、文件限制和失败重试策略。
