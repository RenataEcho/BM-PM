# FR-wen-003 · 支持团长留言给直属下级 · v2 当前

## 0. Document Purpose

本文件面向产品、运营、设计、研发与测试，仅定义「右豹主业务」本次增量：已开白团长通过团队成员列表，选择固定话术向直属下级发送留言，由系统通知承接阅读，并由运营后台管理开白、模板、限制规则和留言记录。

需求输入为同目录的 [需求单.md](需求单.md) 及 2026-10-30 用户补充决策；冲突处以本次补充决策为准。全局编号沿用已占用的 `FR-wen-003`，记录于 `iteration_id`；正文 `FR-1` 至 `FR-11` 仅为本增量内部功能编号，不占用全局编号，不合并其他迭代。截至本次编写，同目录尚无 DESIGN.md、EXPERIENCE.md、SPEC.md，未提供本需求已有 Demo。本步只交付 PRD，不创建设计或页面；后续若存在已定设计，按仓库约定保持一致。

正文中确定规则来自需求单及用户补充决策；原 A-1 至 A-12 已按补充决策确认或修订，决策摘要见第 8 节。仍未确认的推断保留 `[ASSUMPTION]` 标记，该标记不表示业务方已确认。

## 1. Vision

让已开白团长能够直接在团队成员列表向直属下级传达标准化信息。团长选择后台固定话术、预览变量替换后的内容并确认发送；直属下级通过现有系统通知列表与图文详情阅读，无需新增移动端留言记录入口。

本增量以「开白 + 直属关系 + 固定话术 + 全局发送限制」约束留言范围和频次。运营可配置话术及限制、查询发送结果，使每次成功通知都能追溯至团长、留言对象、模板和实际发送内容。

## 2. Target User

### 2.1 JTBD

| 使用者 | 场景与要完成的事 | 完成标志 |
|---|---|---|
| 已开白团长 | 在团队成员列表选定直属成员或直属团队长，用标准话术传递信息 | 预览后确认发送，获得成功或明确失败反馈 |
| 直属下级 | 在现有消息入口接收并查看团长留言 | 系统通知列表可见「团长留言」，点击可查看图文详情 |
| 管理后台操作人员 | 管理团长使用资格、话术与限制，并追查发送动作 | 四个模块可操作；记录可核对实际内容及发送结果 |

### 2.2 Non-Users

- 未开白团长不能作为发送者使用留言功能。
- 间属成员、间属团队长及其他非直属关系用户不能作为本功能的留言对象。
- 直属下级是本功能的接收者，本增量不提供回复会话能力。

### 2.3 UJ

以下为对需求单操作顺序的场景化整理；小周、小林、小陈均为示例称呼，不代表访谈对象。

- **UJ-1：团长小周给直属下级留言。** 小周已被后台开白，进入团队成员列表，在直属成员小林对应的留言入口选择一条启用的固定话术，核对替换后的昵称和联系方式，确认发送。成功时本次只生成一条站内通知；命中限制时提示原因，未生成通知。直属团队长作为留言对象时路径相同。
- **UJ-2：直属下级小林阅读留言。** 小林进入「消息通知 → 系统通知」，在列表看见标题为「团长留言」的通知及实际内容；点击后按现有交互进入图文详情。变量缺失的部分留空，二维码缺失时不出现破损图。
- **UJ-3：运营小陈管理并核查留言。** 小陈进入「用户-用户通知-团长留言」，在「留言开白」配置团长资格，在「话术模板」维护固定话术，在「规则配置」设置全局限制；发送后到「留言记录」核查发送者、对象、模板、实际内容、发送状态及失败原因。

## 3. Glossary

| 术语 | 本文定义 |
|---|---|
| 团长 | 发起留言的团队管理用户，其昵称、联系电话与联系方式取团长用户信息 |
| 直属下级／留言对象 | 与团长存在直属关系的直属成员或直属团队长；「留言对象」指本次选中的一个直属下级 |
| 间属 | 不属于团长直接下级的关系，不具备本功能的接收资格 |
| 留言开白 | 后台授予或关闭团长使用留言功能的资格；不改变团队关系 |
| 固定话术／话术模板 | 后台配置的可复用留言内容，包含允许的变量；团长只能选择，不能编辑正文 |
| 模板变量 | 留言对象昵称、团长昵称、团长联系电话、团长联系方式四类可替换信息 |
| 团长联系方式 | 团长用户信息中的微信号与二维码截图，二者作为一组、设置时均必填；每个用户最多设置 5 组，留言取第一组 |
| 实际内容 | 模板变量替换并应用缺失规则后的完整内容，包含文字和二维码图片 |
| 成功发送 | 成功生成一条发给留言对象的站内通知，不以对象已读为条件 |
| 系统通知 | 「消息通知 → 系统通知」下接收本次留言的现有消息分类 |
| 图文详情 | 点击系统通知后沿用现有消息交互进入的内容详情 |
| 留言记录 | 后台保存的团长留言动作及其发送结果、内容快照 |
| 全局限制 | 统一作用于所有已开白团长的次数、频率、重复发送规则；分别按规则定义的主体统计 |

## 4. Features

### 4.1 留言资格与入口（UJ-1、UJ-3）

#### FR-1：留言开白管理

管理后台在「用户-用户通知-团长留言」提供「留言开白」「话术模板」「留言记录」「规则配置」四个模块；在「留言开白」管理团长资格。

**Consequences（可验收）：**

- 留言开白展示团长用户 ID、团长昵称、开白状态、开白时间、操作人、操作时间、备注。
- 新增流程为「新增开白 → 输入团长用户右豹 ID → 开白状态设为开启 → 保存」，保存后开白管理列表增加该团长及其开白记录。
- 团长未开白时不显示留言按钮，直接尝试发起发送也不能成功。
- 开白后，仅对符合 FR-2 的留言对象显示留言按钮；关闭开白后，后续发送不被允许。
- 开白是针对同一个团长用户设置权限，同一团长仅有一条开白管理记录，不重复新增；已存在的团长在原记录上设置权限。「开白时间」表示最近一次由未开白变为已开白的时间，「操作时间」记录最近一次变更。

#### FR-2：按直属关系展示入口并复核资格

团长从团队成员列表中对单个直属成员或直属团队长发起留言。

**Consequences（可验收）：**

- 已开白团长查看直属成员、直属团队长时，可见对应留言按钮；查看间属成员、间属团队长时均不可见。
- 点击确认发送时重新核对开白资格、直属关系及模板可用性；不能仅依赖打开页面时的状态。
- 预览后开白被关闭、直属关系失效或模板不可用时，本次发送被拒绝，不生成通知、不增加成功次数。
- 上述资格变化时提示具体不可发送原因，并要求重新选择可用对象或模板；没有启用模板时显示无可用话术状态，不允许确认发送。具体文案由后续 UX 定稿。

### 4.2 固定话术、变量与预览（UJ-1、UJ-3）

#### FR-3：后台维护话术模板

运营可配置多条固定话术及启用状态、变量字段配置，供团长选择。

**Consequences（可验收）：**

- 后台展示模板 ID、模板名称、模板内容、启用状态、变量字段配置、创建人、创建时间、更新人、更新时间。
- 团长只能选择启用的模板，不能输入自定义留言或修改模板正文、变量取值。
- 可用变量仅为留言对象昵称、团长昵称、团长联系电话、团长联系方式；留言对象昵称取留言对象用户信息，其余取团长用户信息。
- 后台保存时校验模板名称和模板内容非空，拒绝未支持的变量；支持模板启用、停用及删除。字段长度及二维码资源规格沿用现有能力，实施前核实具体规格。
- 模板删除后不再可选；已打开该模板预览但尚未发送的操作在提交时按模板不可用拦截。删除不影响已发送留言在系统通知、图文详情中的显示，留言记录保留发送时的模板 ID／名称、模板内容及实际内容快照。

#### FR-4：替换变量、预览并确认发送

团长选择模板后先看到实际内容，确认后才发送。

**Consequences（可验收）：**

- 四类变量均有值时，预览使用相应用户信息，不展示变量占位符；同名用户按用户 ID 区分对象。
- 任一变量缺失时，对应内容为空，不阻止发送，不显示未替换的变量占位符。
- 用户设置联系方式时，微信号与二维码截图作为一组，两项均必填，不存在组内仅缺其中一项的有效联系方式；每个用户最多设置 5 组，留言变量只取第一组，不合并或选择其他组。
- 团长未设置任何联系方式时，整个联系方式变量为空，仍按变量缺失规则允许发送，不展示破损图片或占位图。
- 预览、最终系统通知、图文详情的实际内容一致；取消确认不会生成通知，也不计次。
- 预览后若模板内容或相关用户信息变化，提交前展示更新后的实际内容并要求再次确认，避免发送未经预览的内容；已生成通知及记录保留发送时快照，不因后续资料或模板修改、删除而变化。

### 4.3 系统通知与发送结果（UJ-1、UJ-2）

#### FR-5：通过现有系统通知承接阅读

成功发送后，留言对象通过「消息通知 → 系统通知」查看通知，并点击进入图文详情。

**Consequences（可验收）：**

- 每次成功发送仅向选定留言对象生成一条站内通知，标题固定为「团长留言」。
- 消息列表展示实际内容，图文详情沿用现有消息交互展示完整实际内容，变量及缺失处理与预览一致。
- 未成功生成通知不视为成功发送；接收者是否打开、是否已读不影响成功次数。
- 列表摘要长度、二维码在列表中的呈现和未读标识沿用现有系统通知能力；图文详情须能展示完整文字与已有二维码截图。若现有承载能力不足，实施前确认必要适配，不新增消息分类。

#### FR-6：反馈结果并防止重复发送

**Consequences（可验收）：**

- 成功生成通知后反馈成功；发送失败反馈失败，不增加成功次数，不更新频率或重复发送时间。
- 同一发送操作的重复点击或重试最多生成一条通知、累计一次成功次数；同一内容另行发起的新操作仍按 FR-9 校验。
- 并发发送不能突破已开启的限制；例如同一团长每日只剩一次额度时，多次并发请求最多一次成功。
- 结果暂时未知时显示处理中，核实结果后再反馈成功或失败；结果未明确前不将重试当作新发送操作。结果恢复方式由后续方案明确，不能以重新发送代替结果核实。

### 4.4 全局发送限制（UJ-1、UJ-3）

#### FR-7：次数上限与配置管理

「规则配置」统一适用于已开白团长，不提供单个团长的特殊规则。

**Consequences（可验收）：**

- 支持「每位团长每日发送总上限」和「每位团长对同一下级每日发送上限」，各有独立开关及正整数配置项。
- 初始两项均开启，分别为 100 条／日、3 条／日。
- 按北京时间自然日统计，每日 00:00 重置统计窗口；仅成功发送计次，失败、校验拦截、取消均不计次。
- 达到总上限时提示「今日留言次数已达上限，请明日再试」；达到同一下级上限时提示「今日给该下级的留言次数已达上限，请明日再试」。
- 例如总上限为 100 时，第 100 次成功被允许，此后当天新增发送被拦截；同一下级上限为 3 时，第 3 次成功被允许，第 4 次被拦截，前提是其他限制均通过。
- 所有限制开关、数值、适用范围／时间窗口、更新人、更新时间在后台可查看；关闭某项保留配置值且仅取消该项限制。
- 开启限制时，空值、0、负数、小数均不允许保存；保存成功后对后续发送立即生效，不清空已有成功记录。降低上限至已用额度以下时，后续发送立即被拦截。

#### FR-8：跨留言对象控制发送频率

**Consequences（可验收）：**

- 支持独立开关及「同一团长两次成功发送的最小间隔（秒）」正整数配置。
- 初始开启，间隔 3 秒；同一团长上一次成功发送后未满 3 秒时拦截，达到 3 秒时本项通过。
- 同一团长更换留言对象仍受间隔约束；其他团长的发送不占用该团长的间隔。
- 未到间隔时不发送，提示「操作过于频繁，请在 {剩余秒数} 秒后重试」；达到间隔后本项通过，失败或拦截不延长间隔。
- 剩余秒数向上取整，避免仍受限时展示 0 秒；频率和重复限制的跨日窗口不因自然日切换清空。

#### FR-9：按实际内容限制重复发送

**Consequences（可验收）：**

- 支持独立开关及「同一团长对同一下级发送相同内容的限制时长（小时）」正整数配置。
- 初始开启，时长 24 小时；从最近一次对该下级成功发送相同实际内容起滚动计算。
- 相同内容按变量替换后的完整文字与二维码图片判断；不同模板产生相同实际内容时仍受限，不能仅按模板 ID 判断。
- 同一团长对不同下级发送相同内容不命中本项，但仍校验次数及频率限制；不同团长分别统计。
- 窗口内提示「已向该下级发送过相同内容，请在 {可再次发送时间} 后重试」；达到窗口结束时本项通过。失败或拦截不延长窗口。
- 实际文字精确比较，不忽略空格、换行；二维码按图片内容判同，不因同一图片的资源地址变化而视为不同。可再次发送时间展示北京时间并包含日期，具体图片判同方式由后续方案明确。

#### FR-10：统一校验顺序与规则生效

**Consequences（可验收）：**

- 发送时先复核开白资格、直属关系和所选模板是否可用，再按「每日总上限 → 同一下级每日上限 → 发送间隔 → 重复内容」依次校验。
- 已开启限制须全部通过；同时触发多项时仅展示按上述顺序遇到的第一项提示。
- 例如总上限与发送间隔同时不满足时，展示总上限提示；总上限关闭后才继续判断后面的开启项。
- 修改开关或数值后，后续发送使用新配置及已有成功记录统计；重新开启限制后，仍按已有成功记录计算额度和时间窗口。

### 4.5 留言动作可追溯（UJ-3）

#### FR-11：后台查看留言记录

**Consequences（可验收）：**

- 「留言记录」展示记录 ID、团长用户 ID／昵称、留言对象用户 ID／昵称、关系类型、选用模板 ID／名称、发送前模板内容、实际内容、发送状态、发送时间、失败原因（如有）。
- 关系类型能区分直属成员与直属团队长；原始模板内容与实际内容分别保留，便于核对变量替换结果。
- 成功记录可与生成的通知核对内容及对象；失败记录有失败原因，不能将失败展示为成功。
- 记录提交发送后的成功与失败动作；取消、仅预览、校验拦截不作为发送记录，不额外记录拦截动作。同一发送操作重复点击或重试不新增重复动作记录；失败记录的「发送时间」指本次提交时间。
- 支持按团长用户 ID／昵称、留言对象用户 ID／昵称、选用模板 ID／名称、发送状态筛选留言记录；按这些条件查询时，只展示符合所选条件的记录。
- 暂不支持导出。留言记录暂定永久保留，按当前决策不自动到期清理；「暂定」不表示本期仍需等待确认，后续如调整保留策略须另行决策。

## 5. 非目标

- 不新增移动端团长留言记录页面。
- 不支持自定义留言内容、编辑变量取值或向间属用户留言。
- 不提供批量发送、群发、回复会话、撤回或通知内容编辑；需求单只描述单个对象的选择与发送。
- 不按团长单独配置发送限制，不新增消息分类或其他通知渠道。
- 暂不支持留言记录导出，不额外记录校验拦截动作。
- 不把其他 FR 的能力并入本文，不在本步骤制作设计、Demo、接口或数据实现。
- 后续静态 Demo 仍遵守仓库约定：使用示例数据，不接真实接口、登录、权限或持久化。本文的业务资格与可靠性验收用于产品实现要求，不代表 Demo 必须连接真实能力。

## 6. 非功能与一致性要求

- **资格边界：** 未开白或非直属关系的发送成功数必须为 0；按钮隐藏与发送时复核同时成立（FR-1、FR-2）。
- **内容一致：** 对同一次发送，预览、通知、图文详情、留言记录的实际内容一致；变量占位符泄露数和缺失二维码破损图数均为 0（FR-4、FR-5、FR-11）。内容变化按 FR-4 再次确认；模板删除不影响历史留言展示。
- **发送一致：** 重复点击、重试和并发场景下，不重复通知、不重复计次、不超限（FR-6 至 FR-10）。不指定接口、存储或锁机制，由后续技术方案满足业务结果。
- **追溯完整：** 成功和失败记录均具备 FR-11 的字段；失败原因只对后台用于排查，不将内部错误细节直接作为团长提示。
- 留言记录按当前决策暂定永久保留。响应时长与峰值发送量尚未确定，本 PRD 不编造性能指标，实施前确认项见 A-13。

## 7. 验收与效果判断

本阶段以闭环及限制正确性验收，不将「发送量越高」作为成功目标。验收至少覆盖新增开白与同一团长记录唯一性、直属成员与直属团队长成功路径、未开白与间属拦截、变量缺失、联系方式整组必填及最多 5 组且取第一组、模板删除后历史留言可读及未发送操作拦截、四项限制的边界（含 3 秒间隔）、跨日与滚动窗口、重复点击／重试／并发，以及后台快照、各筛选字段与记录保留规则核对。

| 指标 | 口径与验收目标 | 对应要求 |
|---|---|---|
| 闭环完成 | 在通过全部校验的受控用例中，一次成功发送生成一条通知，留言对象可阅读，后台有对应成功记录；全部通过 | FR-4、FR-5、FR-6、FR-11 |
| 反向约束：误发与超限 | 未开白、非直属或命中开启限制的受控用例中，成功通知数为 0 | FR-1、FR-2、FR-7 至 FR-10 |
| 反向约束：重复与内容偏差 | 同一发送操作重复通知数为 0；预览与通知、详情及记录的实际内容偏差数为 0 | FR-4、FR-5、FR-6、FR-11 |

以上是验收目标，不是线上成功率承诺。[ASSUMPTION] A-13：上线后的观测周期、送达／阅读效果及性能容量目标由产品、运营与研发在上线评审前确认；本次不新增阅读统计看板或埋点方案。
