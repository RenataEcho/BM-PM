# FR-wen-003 · 支持团长留言给直属下级

> 本 SPEC 与 `companions` 三份文件共同构成实现和验收合同，均须阅读。视觉和行为以已定 DESIGN.md、EXPERIENCE.md 优先，业务规则采用 prd.md v2；需求单中旧 10 秒间隔及联系方式拆项口径已被后续决策替代。字段、提示文案、状态、无障碍和页面细节保留在对应附件，不在本文重复展开。

## Why

已开白团长需要在团队成员列表向直属成员或直属团队长传达标准化信息。通过固定话术、实际内容预览与确认、现有系统通知阅读及后台追溯，完成单对象留言闭环；以开白资格、直属关系及全局限制约束误发和过度发送。

## Capabilities

- **CAP-1：留言资格与开白**
  - **intent:** 运营可管理团长留言资格，已开白团长可向单个直属下级发起留言。
  - **success:** 按右豹 ID 新增并核对昵称，同一团长只有一条开白记录，可在原记录关闭或重新开启；仅已开白团长的直属成员、直属团队长行显示入口，未开白或间属均隐藏。发送时复核资格、关系及模板，失效不生成通知、不计次，并按原因恢复操作。字段及时间口径见 PRD FR-1、FR-2，UX M1、A1。

- **CAP-2：固定话术维护**
  - **intent:** 运营可维护团长能选择的固定话术及启用状态。
  - **success:** 名称和正文必填，仅允许留言对象昵称、团长昵称、团长联系电话、团长联系方式四类变量；可新增、编辑、查看、启停及确认删除。团长仅能选择启用模板；停用或删除使未发送操作失效，历史通知和记录仍保留原模板及实际内容快照。字段与校验见 PRD FR-3，UX A2。

- **CAP-3：实际内容预览与确认**
  - **intent:** 团长可核对目标对象及完整实际内容，明确确认后发送。
  - **success:** 单对象、单模板，先选择再预览，不默认选中、不允许编辑正文或变量；对象昵称与 ID 始终明确。缺变量替换为空，不泄露占位符、不阻止发送；联系方式沿用既有设置能力，微信号与二维码整组必填、最多 5 组、只取第一组，无组则整个变量为空。已有二维码加载失败须重试，不能冒充资料缺失。提交前内容变化须更新全文并再次确认；通知、详情与记录采用最终确认的发送快照。见 PRD FR-4，UX M2、M3。

- **CAP-4：系统通知阅读**
  - **intent:** 直属下级可在现有消息入口阅读团长留言。
  - **success:** 每次成功只向选定对象生成一条标题为「团长留言」的站内通知；从「消息通知 → 系统通知」进入原图文详情，完整展示发送时文字与已有二维码。列表仅按现有摘要规则截断，不改变量取值；资料变化或模板删除不改历史，无二维码不渲染占位图，是否已读不影响发送计数。见 PRD FR-5，UX M4、M5。

- **CAP-5：结果反馈与防重**
  - **intent:** 团长可明确发送结果，并在失败或结果未知时安全恢复原操作。
  - **success:** 只有成功生成通知才反馈「留言已发送」并计次；同一操作双击、重试最多一条通知、一次成功计数及一条动作记录，并发不突破限制。确定失败保留预览可重试原操作；未知结果或提交后断网持续核实，查询失败仍未知，不以新发送代替查询。失败、取消、校验拦截不更新次数、间隔或重复窗口。具体查询及跨页面恢复交互保留 UX-A1 假设。见 PRD FR-6，UX 状态模式。

- **CAP-6：全局限制配置**
  - **intent:** 运营可统一配置已开白团长的发送次数、频率和重复内容限制。
  - **success:** 四项独立开关默认全开：每团长 100 条／日、对同一下级 3 条／日、跨对象成功发送间隔 3 秒、同一下级相同实际内容 24 小时。开启项仅接受正整数；关闭项保留数值。统一保存成功后后续发送立即采用新配置及已有成功记录，修改或重新开启不清空历史；降低至已用额度以下即拦截后续发送。保存失败保留编辑且旧配置继续生效。见 PRD FR-7～FR-10，UX A4。

- **CAP-7：按顺序校验并守住边界**
  - **intent:** 系统可按统一顺序解释不可发送原因，并准确执行当前开启的规则。
  - **success:** 按「开白资格 → 直属关系 → 模板可用 → 内容必要时重新确认 → 每日总上限 → 同一下级每日上限 → 发送间隔 → 重复内容」复核，仅提示首个失败项。每日次数按北京时间自然日 00:00 重置；第 100／3 次可通过对应次数项，第 101／4 次拦截；达到 3 秒／24 小时边界通过对应时间项，滚动窗口跨日不清空。间隔剩余秒数向上取整；重复按完整实际文字（含空格、换行）及图片内容判断，不按模板 ID 或图片 URL 判断，提示含日期的北京时间。不同团长分别统计，同一下级及跨对象作用范围按各项规则执行；全部开启项通过才允许成功。精确文案及边界见 PRD FR-7～FR-10、UX「全局限制展示与发送复核」。

- **CAP-8：后台追溯**
  - **intent:** 运营可查询发送动作并核对对象、模板、实际内容与结果。
  - **success:** 在「用户 → 用户通知 → 团长留言 → 留言记录」组合团长、对象、模板的 ID／昵称或名称及发送状态筛选，查看只读详情。保留发送前模板和实际内容快照，成功可核对通知；失败显示原因且发送时间为提交时间。只记录提交后的成功／失败，预览、取消、校验拦截不记，同一操作不重复记；关系区分直属成员和直属团队长。不导出，当前暂定永久保留、不自动清理。完整字段及筛选语义见 PRD FR-11、UX A3。

## Constraints

- 本需求沿用已占号 FR-wen-003，目录为 `youbao/fr-wen-003-支持团长留言给直属下级/`；CAP 编号仅为本合同能力编号，不占用全局 FR。
- 移动端复用团队成员列表、系统通知和图文详情；联系方式只读取既有用户信息，不新增设置入口。后台四个平级模块为留言开白、话术模板、留言记录、规则配置。
- 视觉、组件、具体文案、交互状态与无障碍均按 DESIGN.md、EXPERIENCE.md 及其引用的既有规范；手机用同一 Sheet 切换选择／预览，后台详情用抽屉、编辑用弹窗、删除先确认，不另起配色或组件体系。
- 必读对象、实际内容及错误使用深色文字；状态不能只靠颜色。键盘、焦点管理、触控热区、读屏、长内容和图片失败行为遵守 UX；不可将暖橙白字小字 CTA 声称为已满足 AA。
- 业务失败和未知结果在当前表面保留原因与恢复动作；内部异常只供后台排查，不向团长暴露内部错误细节。关闭浮层不等于取消已提交操作。
- 不指定接口、存储、锁、轮询时长或图片比对算法；技术方案必须满足内容快照一致、原操作可核实、并发不超限及防重结果。
- 后续静态 Demo 只用示例数据，不接真实接口、登录、权限或持久化；沿用现有外壳、深链和组件 class，业务流程用页内手写 SVG，规则抽屉只写当前 FR 并指向流程 Tab。实现细节见两份 UX，本文不制作 Demo。

## Non-goals

- 自定义留言、修改变量取值、向间属或非直属关系留言、批量／群发、回复会话、撤回及编辑已发通知。
- 移动端留言记录页、新联系方式设置页、单团长特殊限制、新消息分类或其他通知渠道。
- 记录导出、额外记录校验拦截、阅读统计看板或新增埋点方案；不并入其他 FR。
- 本轮不交付页面、mockup、接口或数据实现，不拆故事；上游文档描述的历史产出阶段不限制本次 SPEC 交付。

## Success signal

- 受控验收中，直属成员与直属团队长两条路径均能完成「开白 → 选固定话术 → 预览确认 → 单条通知 → 图文阅读 → 后台记录」，最终确认内容与通知、详情、记录快照偏差为 0；模板修改或删除后历史仍可读。
- 未开白、非直属、资格失效、内容未重新确认及命中开启限制时成功通知数为 0；双击、重试、未知结果恢复、额度并发争用时重复通知和超限数为 0。覆盖缺变量与二维码状态、四项边界、跨日、开关重启、规则修改、组合筛选及失败记录；这些是验收目标，不是线上效果承诺。
