# FR-wen-003 · 支持团长留言给直属下级 · 行为设计

## 基础（Foundation）

业务线为「右豹主业务」，需求名沿用需求单原话。输入是 [prd.md](prd.md) v2，视觉见 [DESIGN.md](DESIGN.md)。移动端复用现有团队成员列表、消息通知、系统通知、图文详情；桌面运营后台复用现有管理系统。不得把产品中的资格判断当作要求静态 Demo 接入真实权限、接口或持久化。

本增量完成「已开白团长 → 单个直属下级 → 固定话术 → 预览确认 → 站内通知 → 后台追溯」。直属成员与直属团队长都可作为对象。无移动端留言记录页，无自定义留言、变量编辑、回复、批量发送、撤回、导出或新增通知渠道。联系方式设置仍在既有用户信息能力中，本需求只读取，不新建设置入口。

[ASSUMPTION] UX-A1：PRD 已确定未知结果必须核实、不能重发，但未定义具体恢复入口。本文建议「查询结果」按钮及收起／返回后恢复原操作的交互，相关文案、状态与旅程均为同一待实施方案确认的设计假设，不表示既有能力；任何替代方案仍须满足未知期间不新发和不重复通知的约束。

采用文档快速交付；本次不生成页面与 mockup。IA 中每个表面均以下表、状态表及用户旅程作为后续实现参考，不声称存在视觉稿。新增设计决策为下述具体布局、组件与提示文案；未落实的现有能力依赖见末节。

## 信息架构（Information Architecture）

| 表面编号／名称 | 入口与内容 | 去向／关联旅程 |
|---|---|---|
| M1 团队成员列表 | 原入口，符合资格的成员行出现「留言」；昵称、ID、直属关系明确 | M2；UJ-1 |
| M2 选择话术 | M1 的单个对象；只显示启用模板，单选；始终显示对象昵称及 ID | 下一步 M3；关闭返回 M1；UJ-1 |
| M3 留言预览 | M2 下一步；显示替换后的完整实际内容及二维码，确认前可返回选择 | 提交后显示发送中／结果，成功回 M1；UJ-1 |
| M4 系统通知列表 | 消息通知 → 系统通知；标题「团长留言」及实际内容摘要，沿用现有时间与未读行为 | M5；UJ-2 |
| M5 图文详情 | 点击 M4 通知；完整发送快照，无回复与重新发送入口 | 返回 M4；UJ-2 |
| A1 留言开白 | 用户 → 用户通知 → 团长留言 → 留言开白；开白列表及新增／编辑表单 | 资格保存返回列表；UJ-3 |
| A2 话术模板 | 同页话术模板 Tab；列表、新增／编辑、详情、删除确认 | 保存刷新、删除退出确认；UJ-3 |
| A3 留言记录 | 同页留言记录 Tab；筛选、结果列表、只读详情 | 关闭详情返回原查询；UJ-3 |
| A4 规则配置 | 同页规则配置 Tab；四项限制、开关、数值、范围、窗口、更新人／时间 | 保存留在当前页；UJ-3 |

手机在一个 `message-sheet` 内切换选择与预览，不叠多层弹窗。后台默认进入留言开白，四个模块平级；编辑开白和模板用 `edit-modal`，删除用 `confirm-modal`，查看模板／记录用 `detail-drawer`。规则配置在 Tab 主体直接编辑和保存。

## 文案与语气（Voice and Tone）

对象采用「昵称 + 右豹 ID」，避免同名误发；页面说「留言」，不称为聊天或私信。成功仅表示已生成站内通知，不写「对方已收到／已阅读」。固定标题、限制文案遵守 PRD，不能改成营销鼓励。

| 场景 | 展示文案／动作 |
|---|---|
| 选择阶段 | 「选择话术」「留言给：{对象昵称}（右豹 ID：{对象ID}）」「仅支持选择固定话术」；下一步 |
| 预览阶段 | 「留言预览」「请确认以下留言内容」；返回选择／确认发送 |
| 无启用模板 | 「暂无可用话术，请稍后再试」；关闭；不展示可发送按钮 |
| 开白关闭 | 「留言权限已关闭，暂时无法发送」；返回成员列表 |
| 关系失效 | 「该用户已不是你的直属下级，无法发送留言」；返回成员列表 |
| 模板失效 | 「该话术已不可用，请重新选择」；重新选择 |
| 预览内容变化 | 「留言内容已更新，请重新确认」；展示新实际内容，再次确认发送 |
| 发送中／未知结果 | 「发送中…」／「正在核实发送结果，请勿重复发送」；未知时提供「查询结果」，不提供新发送 |
| 确定成功 | 「留言已发送」；关闭 Sheet，返回原成员列表位置 |
| 确定失败 | 「留言发送失败，请重试」；保留对象、模板与预览，允许重试同一操作 |
| 总次数用尽 | 「今日留言次数已达上限，请明日再试」 |
| 同一下级次数用尽 | 「今日给该下级的留言次数已达上限，请明日再试」 |
| 间隔不足 | 「操作过于频繁，请在 {剩余秒数} 秒后重试」 |
| 重复内容 | 「已向该下级发送过相同内容，请在 {可再次发送时间} 后重试」；时间为含日期的北京时间，例如「2026-10-31 15:30:00（北京时间）」 |
| 模板删除确认 | 「确认删除该话术模板？」；「删除后团长将无法选择该模板，已发送留言及历史记录不受影响。」；取消／确认删除 |
| 后台校验错误 | 「请输入团长用户右豹 ID」「请输入模板名称」「请输入模板内容」「包含不支持的变量，请修改」「请输入大于 0 的整数」 |
| 后台空／查询空 | 「暂无开白记录」「暂无话术模板」「暂无留言记录」／「暂无符合条件的记录」；查询空时提供重置 |

业务失败原因持续显示在当前表面，使用 `{colors.mobile-text}` 或 `{colors.admin-text}`，而不是仅一闪而过的提示。内部异常原因仅在后台记录详情排查，不直接给团长展示原始错误码或内部堆栈。

## 组件行为（Component Patterns）

| 组件名 | 行为合同 |
|---|---|
| member-row | 只有团长已开白且对象为直属成员／直属团队长才显示留言；非直属、间属或未开白隐藏；点击留言锁定该对象 ID，且不触发整行原操作 |
| message-sheet | 打开时先加载话术，不默认选中、不自动进入预览。选择和预览共用一层；返回选择保留当前有效模板。提交前关闭不发送不计次；发送中／结果未知关闭只收起表面，不取消已提交动作，恢复后继续核实同一操作 |
| template-option | 单选启用模板；选择后「下一步」可用。只展示固定话术，团长不能编辑正文、变量取值或二维码；模板停用／删除即失效 |
| actual-content | 预览使用真实对象与团长信息替换；四类变量仅为留言对象昵称、团长昵称、团长联系电话、团长联系方式。无值替换为空，不输出占位符，不用「未填写」替换正文；不因缺失阻止发送。后台模板编辑态可以显示变量标记，发送快照不可以 |
| mobile-action | 未选模板、加载／提交中不可发送；点击确认后立即进入发送中，重复点击不另发操作。成功才反馈「已发送」；未知结果保持查询动作；重试不新建通知或重复计数 |
| notification-item | 标题固定「团长留言」；点击沿用现有系统通知交互到完整图文详情；未读标识、排序、摘要长度、列表二维码呈现沿用现有能力，不新增规则 |
| admin-panel | 四个模块只维护本 FR。切换 Tab 不触发保存；返回记录页保留原筛选。未保存规则离开时提示「修改尚未保存」，选择留在本页或放弃修改，不误报已生效 |
| admin-button | 查询／保存为主按钮，取消／重置次要，表格详情／编辑用文字链，删除为危险文字链并确认；请求期间防重复提交，成功才刷新状态 |
| admin-form | 开白右豹 ID 查询到对象后展示昵称以核对；模板正文通过四类允许变量插入，名称／正文必填，未知变量拒绝保存；开启的限制要求正整数，关闭则禁用输入但保留原值 |
| admin-table | 主表承载摘要，点击详情完整查看长字段；不要求点击整行。记录筛选组合生效；成功／失败不混淆；操作列依次详情、编辑、删除（仅出现本模块有的操作） |
| edit-modal | 新增／编辑时带标题，编辑预填；必填错误定位字段、不关闭，保存失败保留表单；保存成功关闭并刷新。取消、Esc、关闭、遮罩均不保存；有改动时提示放弃或继续编辑 |
| confirm-modal | 只在确认删除时删除模板；取消／Esc／关闭不删除；删除中禁用重复确认，失败留在弹窗并可重试；成功从可用列表移除，不改历史快照 |
| detail-drawer | 只读展示模板完整内容／记录完整快照；关闭保留列表状态。记录无修改／重发／撤回／导出入口。模板详情若需编辑，关闭详情后进入编辑，避免叠层 |
| status-tag | 始终显示中文状态；开白「开启／关闭」，模板「启用／停用」，记录「成功／失败」。未知结果在移动端用「处理中」，不得编造已成功记录 |
| feedback | 成功可轻提示；限制、失败及未知结果在当前表面持久展示，并提供对应恢复动作；离线不能当发送失败或成功推断，先区分是否已经提交 |
| rule-drawer | 仅后续 Demo 评审入口使用；独立 DOM，前端需求／后台需求两个内 Tab；规则只写本 FR，前端与流程页打开定位前端需求，后台页定位后台需求；关闭钮／遮罩／Esc／再点入口收起，背景不可操作 |
| flow-panel | 后续业务流程 Tab 用单张闭环 SVG 展示主路径、资格、内容再确认、限制、发送结果、通知与记录；失败返回可重试节点，未知结果返回核实节点，不能把未知分支连向新发送。能一图闭环就不拆多图 |

### 联系方式与快照

团长联系方式中的微信号和二维码截图是一组，两项均必填，每个用户最多设置 5 组，留言只取第一组；不拼接其他组、不提供切换。未设置任何组时整个联系方式变量为空；历史异常缺图或资源加载失败不能出现破损图，已有文字仍保留，处理见状态表。联系方式设置校验属于现有用户信息能力的依赖，不在本次新增编辑表单。

模板正文里普通文字与变量分开处理：只有变量值缺失时替换为空，不擅自删除固定文案。例如固定「联系电话：」仍保留，缺失的值为空。没有二维码资源时不渲染图片节点或占位图。

提交前复核模板和相关用户信息。实际内容有变化时展示更新后全文并要求再次确认；未再次确认不得发送。已成功通知及记录保留发送时模板 ID／名称、发送前模板正文、实际内容快照；后续资料变更、模板停用或删除不能改动历史。预览、通知详情与记录实际内容一致，通知列表可按既有摘要规则截断，但不得变更字词或变量取值。

### 后台四模块字段与动作

| 模块 | 列表／详情字段 | 本期动作与校验 |
|---|---|---|
| 留言开白（FR-1） | 团长用户 ID、团长昵称、开白状态、开白时间、操作人、操作时间、备注 | 新增开白 → 输入团长用户右豹 ID → 核对昵称 → 状态开启 → 保存；ID 为既有记录时提示「该团长已有开白记录，请在原记录上编辑」，不重复新增。编辑原记录可关闭／重新开启权限；关闭后后续发送受限。开白时间是最近一次从未开白转已开白，操作时间是最近变更 |
| 话术模板（FR-3） | 模板 ID、名称、完整正文、启用状态、变量字段配置、创建人／时间、更新人／时间 | 新增、编辑、详情、启用／停用、删除；名称和正文非空，变量只允许四类。启停通过编辑状态保存，删除单独确认；不增加排序、群发、导入。长度与图片资源规格沿用既有能力，实施前核实 |
| 留言记录（FR-11） | 记录 ID；团长用户 ID／昵称；对象用户 ID／昵称；关系类型；模板 ID／名称；发送前模板内容；变量替换后的实际内容；发送状态；发送时间；失败原因（如有） | 团长 ID／昵称、对象 ID／昵称、模板 ID／名称、发送状态筛选，查询与重置；详情只读。关系区分直属成员、直属团队长；成功记录可核对通知；失败有原因，失败的发送时间为提交时间。只记录提交发送后的成功／失败动作，取消、预览、校验拦截不记；同一操作重复点击／重试不重复增记录。不导出，暂定永久保留且不自动清理 |
| 规则配置（FR-7～FR-10） | 每项开关、数值、单位、适用范围／时间窗口；更新人、更新时间 | 四项独立开关、统一保存；开启时空值、0、负数、小数拒绝保存，关闭保留原值。保存成功后后续发送即时用新规则及既有成功记录，不清空计数或窗口；失败保留编辑，仍按旧已保存规则生效 |

留言记录的 ID 查询使用完整 ID；昵称／模板名称检索匹配方式若既有后台未统一，实施前核实，不能将未定的模糊检索行为写成产品承诺。后台开白 ID 无效或不属于可开白团长时不允许保存，并在字段处显示可理解的校验结果；不引入新角色或审批流程。

### 全局限制展示与发送复核

| 项目 | 默认值与范围 | 时间规则／边界 |
|---|---|---|
| 每位团长每日发送总上限 | 开启，100 条／日，单个团长全部对象合计 | 北京时间自然日 00:00 重置；第 100 次成功允许，之后拦截 |
| 每位团长对同一下级每日发送上限 | 开启，3 条／日，团长 + 同一下级 | 同上；第 3 次成功允许，第 4 次拦截 |
| 两次成功发送的最小间隔 | 开启，3 秒，同一团长跨对象 | 最近一次成功后未满 3 秒拦截，达到边界通过；剩余秒数向上取整，跨日不清空 |
| 相同内容限制时长 | 开启，24 小时，同一团长 + 同一下级 + 相同实际内容 | 从最近一次相同内容成功发送滚动计算，到期通过；跨日不清空 |

发送时先复核「开白资格 → 直属关系 → 模板可用性」，再检查内容是否需要重新预览确认，随后按「每日总上限 → 同一下级每日上限 → 发送间隔 → 重复内容」检查已开启项；同次只显示首个失败项，不能同时堆多条限制提示。关闭仅取消本项限制，其他项继续校验；多项必须全部通过才能提交成功。并发时即使页面显示有额度，也不能突破限制，结果以最终复核为准。

仅成功生成站内通知才计次、更新间隔与重复时间；取消、校验拦截、失败不计次、不延长窗口。更换对象仍受团长 3 秒间隔；换模板但实际内容相同仍受重复限制；不同团长分别统计。文字精确比较，保留空格和换行；二维码按图片内容判断，不按资源 URL 判断。更新规则不清除历史；降低至已用额度以下立即阻止后续发送，重新开启仍按既有记录计算。

## 状态模式（State Patterns）

| 表面 | 状态 | 呈现与恢复 |
|---|---|---|
| M1 成员列表 | 加载／失败／离线 | 沿用现有成员列表加载与重试；资格未明确前不显示可用留言按钮；加载失败不以「未开白」替代真实原因 |
| M1 成员列表 | 无成员／无资格 | 沿用列表空态；未开白或非直属隐藏留言入口，保持原列表其他行为 |
| M2 选择话术 | 加载／空／失败 | 加载期间下一步不可用；无启用模板用专用空态；获取失败显示重试，保留对象，不当成无模板 |
| M2 选择话术 | 未选／已选／失效 | 未选下一步禁用；已选有单选标记；停用／删除清除失效选择并提示重新选择 |
| M3 留言预览 | 内容加载／缺变量 | 实际内容加载完成才可确认；缺变量为空且允许发送，不展示占位符；无二维码不渲染图片 |
| M3 留言预览 | 有图片但加载失败 | 不展示破损图，以正文旁提示「图片加载失败，请重试」及重试动作；必须展示成功后才能声称完整预览。此加载失败不等同资料缺失，不静默删掉已存在的二维码后发送 |
| M3 留言预览 | 资料或模板正文变化 | 更新全文、提示再确认；本次不发送，等待用户对新内容明确确认 |
| M3 留言预览 | 权限／关系／模板失效 | 显示对应原因，停止发送；权限或关系失效返回列表，模板失效回选择；不生成通知不计次 |
| M3 留言预览 | 命中限制 | 就地显示首项原因；保留对象与模板，可关闭或按条件再尝试，不自动发送，不为校验拦截新增发送记录 |
| M3 留言预览 | 发送中 | 按钮「发送中…」、不可重复提交；同一操作重入恢复当前状态；未得结果不提前提示成功 |
| M3 留言预览 | 结果未知／提交后断网 | 「正在核实发送结果，请勿重复发送」；联网后或点查询结果核实原操作。收起 Sheet 不取消动作；返回该对象操作恢复核实，不新发。查询失败仍未知，不能改成确定失败 |
| M3 留言预览 | 确定失败／成功 | 失败留在预览可重试原操作，提交前再复核；成功提示后返回列表。只成功更新次数与时间，重复点击／重试最多一条通知和一次成功计数 |
| M3 留言预览 | 提交前离线 | 不提交；保留当前选择并提示恢复网络后重试；恢复后重新检查可用性和内容，必要时再次确认 |
| M4／M5 通知 | 加载／无通知／失败 | 沿用现有消息加载、空态与重试；不能使用本 FR 的空态替换其他系统消息；读取失败不能更改通知状态或快照 |
| M4／M5 通知 | 历史内容／二维码缺失或加载失败 | 读取发送快照；模板删除仍可读。原本无二维码不留空占位；有图但加载失败保留文字，避免破损图并允许重试，不篡改快照 |
| A1／A2／A3 列表 | 加载／空／查询空／失败 | 原表格容器显示加载；空与加载失败分开，失败给重试；查询空可重置，保留筛选值；无记录时表头与新增（适用时）仍可见 |
| A1／A2 表单 | 无效输入／保存中／失败 | 错误定位到字段、保留输入；保存中锁定提交；失败不改列表，成功才关闭并刷新；重复 ID 指向编辑原记录 |
| A2 删除 | 确认／删除失败 | 说明后果后确认；失败不移除模板，保留重试；成功后当前模板不可再选择，历史通知／记录仍可读 |
| A3 详情 | 加载／失败／失败记录 | 独立加载与重试；失败记录展示提交时间及失败原因；完整正文与实际内容分区，不能以当前模板重新计算历史 |
| A4 规则配置 | 加载／非法值／脏数据／保存失败 | 未加载不显示伪默认配置；字段错误阻止保存；未保存修改不生效；保存失败保留编辑并告知仍用原配置；保存成功更新操作人／时间 |
| 各可交互表面 | 聚焦／禁用 | 焦点清晰可见，禁用有原因；不能靠 hover 才出现操作。表单焦点顺阅读顺序，关闭浮层回原触发点 |

## 交互原语（Interaction Primitives）

- 点选单个对象、单个模板；下一步只生成预览，确认发送才提交。M3 返回 M2 可更换模板，不增加操作记录。
- 发送行为保留同一操作身份：双击、同一操作重试和未知结果核实不变成新的发送；另行发起新操作仍需全部校验。该要求是行为结果，不指定接口或存储机制。
- 未知结果提供「查询结果」作为恢复方式；自动恢复查询的时机、次数、退避及跨页面身份保存由技术方案落实，UX 不承诺固定完成时间。恢复查询不能偷偷发送。
- 频率提示的倒计时可以更新剩余秒数，到零只恢复手动操作，不能自动重发；重复限制显示含日期的北京时间，不仅显示「明天」。
- 浮层不叠多层编辑；Esc 关闭最上层可关闭表面，关闭后焦点回触发按钮。发送已提交时关闭仅收起，不改变后台动作及处理中状态。
- 后台查询不保存配置；重置只清空查询条件。规则关闭保留数值，重新开启恢复原值；统一保存成功后四项新配置对后续发送生效。
- 后续评审台的场景按钮只切换示例状态，嵌入式手机不新开窗口；规则抽屉与业务详情互斥，背景被遮罩时不可交互。

## 无障碍底线（Accessibility Floor）

视觉引用 DESIGN.md 的 `{typography.mobile-body}`、`{typography.admin-body}` 和已有色彩，必读对象、内容与错误采用深色正文。对比度目标及未验证组合见 DESIGN.md，不能假定继承后全部合格。

移动端触控目标至少 44pt（iOS）／48dp（Android），可以扩充热区而不改既有可见尺寸；字号放大时换行并允许滚动，不能裁掉「确认发送」和「返回选择」。选择话术用单选语义和可读选中态；按钮读出动作与禁用原因。二维码替代文本描述「团长联系方式二维码」，不把图像当唯一联系方式标签。

Sheet、Modal、Drawer 有标题与对话框语义，打开聚焦标题或首个有效控件、焦点限制在当前浮层、关闭返回原触发点；列表行留言按钮的可访问名称为「给{昵称}（右豹 ID {ID}）留言」。后台字段 label 与输入关联，错误文本与字段绑定；表格表头语义完整，截断正文可进入详情读取。

状态变化通过可访问的状态区域播报，成功、失败、处理中均有文字；倒计时不逐秒打断读屏。遵循系统减少动效设置，Sheet／抽屉滑入可省略。键盘 Tab 顺序依次为对象、模板、下一步、预览、确认；后台按筛选、查询、表格操作、详情顺序，所有操作可用 Enter／Space 激活。

## 关键旅程（Key Flows）

### UJ-1：团长小周给直属下级留言。

1. 已开白的小周进入团队成员列表 M1，核对小林的昵称、右豹 ID 和直属关系；直属成员和直属团队长走同一路径。
2. 点该行留言进入 M2，查看启用模板，单选一条固定话术并点下一步。
3. M3 展示替换后全文和第一组联系方式，小周滚动核对完整内容，不可编辑；变量缺失为空仍可发送。
4. 小周点确认发送，复核资格、关系、模板和内容；内容变化则留在更新后的预览，再次明确确认。
5. 通过四项限制后进入发送中；重复点击不触发新发送，未知结果进入核实，不自动重发。
6. **完成关键点：** 只有成功生成一条发给小林的站内通知，才展示「留言已发送」，关闭 Sheet 回到成员列表；后台出现同一操作的成功记录。

失败路径：无模板停留空态；资格失效返回列表；模板失效重新选择；命中限制显示第一项原因；发送确定失败保留预览重试同一操作；断网或超时导致未知则查询原操作结果。取消和预览不生成通知、不计次、不产生发送记录。

### UJ-2：直属下级小林阅读留言。

1. 小林进入「消息通知 → 系统通知」M4，在原系统通知列表看到标题「团长留言」及实际内容摘要。
2. 点击通知进入 M5 图文详情，按现有消息交互处理未读状态。
3. **完成关键点：** 小林能读到与小周最终确认一致的完整文字和已有二维码，空变量无占位符；没有回复、撤回或其他会话操作。
4. 返回系统通知列表，保留原列表上下文；是否阅读不改变小周成功发送次数。

失败路径：列表／详情加载失败在原表面重试；二维码有资源但加载失败保留文字并重试图片，原本无二维码不渲染图节点。之后模板被删或资料变更，仍读取这次发送快照。

### UJ-3：运营小陈管理并核查留言。

1. 小陈进入「用户 → 用户通知 → 团长留言」，在 A1 新增开白，输入小周的右豹 ID、核对昵称，状态开启后保存；已有记录则编辑原记录。
2. 在 A2 新增或编辑固定话术，填名称、正文、四类允许变量与启用状态，校验通过后保存；停用在编辑中操作，删除另行确认。
3. 在 A4 查看默认 100 条／日、同一下级 3 条／日、3 秒间隔、24 小时重复窗口及各自范围，调整独立开关／正整数后统一保存，核对更新人和时间。
4. 小周提交留言后，小陈进入 A3，组合团长、对象、模板的 ID／昵称或名称及状态筛选查询，打开记录详情。
5. **完成关键点：** 小陈可对照发送前模板与实际内容快照，核实对象、直属关系、模板、发送结果、时间与失败原因；成功记录可与通知一致核对。

失败路径：重复 ID 返回原记录编辑；无效模板变量或规则数值定位字段且不保存；保存失败保留表单，原配置继续生效；无查询结果可重置；发送失败有失败记录，拦截／取消／预览无记录；删除模板不损坏历史。记录只读、不导出，当前暂定永久保留不自动清理。

## 响应式与平台（Responsive & Platform）

手机依现有原生／WebView 容器；Sheet 不超过规范约 72% 高，长模板和二维码只滚动正文。系统字体放大时可扩展内容高度，动作区不覆盖正文；预览不调用键盘。图文详情遵循现有返回与底栏规则，不重建消息导航。

后台以 ≥1280px 桌面为主，筛选自动换行、表格区独立横向滚动；窄视口 Modal／Drawer 采用不超视口宽度的同类组件，不能把后台改造成新手机产品。深浅主题若现有后台启用则完整继承其 token；C 端不在本 FR 新增深色主题。

后续 Demo 采用既有外壳，顶部一级业务线固定为右豹主业务；左侧共用概览／组件规范，切换不改页头。1280×800 下评审可同时看到场景与完整手机；`#view-fe` 沿用 `calc(100vh - 188px)` 和规范最小高度，台内滚动。深链 `?tab=fe|admin|flow`，业务流程仅页内展示手写 SVG；规则抽屉只链接页内流程 Tab。
