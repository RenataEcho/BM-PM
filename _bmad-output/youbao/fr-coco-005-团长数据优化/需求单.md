# 需求单

业务线：右豹主业务

需求名：团长数据优化

编号：FR-CoCo-005

照着哪条现有需求做：无。手机画面按 `OPC_team_demo_v8_28.html` 还原。口径按 `团队数据需求1.0.md`。不并入 FR-CoCo-003 团队项目数据分析。

谁在用：团长。Demo 里的团长是北城，身份是 OPC 生态合伙人。

从哪个入口进来：团长数据页。

接着怎么点：

1. 数据页把服务带动拆成两个入口：奖励数据下的「服务带动奖励」只展示、不响应点击；成员数据下的「服务带动成员」可进入列表。「成员数据」旁有说明，点击浮层读取后台 `team_member_rule`。项目排行榜、奖励日历、身份权益只展示，不响应点击。
2. 团队成员列表看 TA的团队人数、团队总流水、TA的个人流水、TA贡献的团队奖励。
3. 服务带动成员列表沿用团队成员的样式和数据，并增加服务带动社群、服务带动奖励。
4. 点成员进入共用的奖励详情。被服务带动的成员要显示服务带动奖励金额。
5. 成员奖励详情用「常规团队奖励」「服务带动奖励」筛选。团队奖励详情不提供「全部奖励来源」筛选。
6. 奖励详情打开项目分析浮层，看该成员各项目的奖励贡献。导师托管的项目显示服务带动。项目带「今日贡献奖励」「持续贡献奖励」「近期无贡献」。
7. 奖励详情打开规则说明，内容来自后台配置。

后台要看什么：

- 表：团队奖励规则配置
- 字段：`team_reward_rule`，奖励详情「规则说明」读取这段文案
- 字段：`team_member_rule`，数据首页「成员数据」旁的说明读取这段文案

哪些情况不允许：

- 服务带动不改变团队归属。
- 成员奖励详情只有一套，不按成员再做不同页面。
- Demo 不接真实接口、登录、权限和持久化。

这次不做的：

- 不改 FR-CoCo-003 团队项目数据分析。
- 不实现真实社群详情页。源 Demo 里点击社群只提示进入未加入的社群页。
- 不做可点的管理后台原型。
- 历史收益只保留入口，不包含历史账单。

还没定的：

- 奖励比例、计奖基数和归属以正式结算规则为准。Demo 里的比例和金额是示例。
