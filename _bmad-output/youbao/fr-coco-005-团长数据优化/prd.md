## Vision

团长在同一套数据页里分清自己的团队奖励和被服务带动的部分，并能从成员列表追到共用的奖励详情、项目贡献和规则说明。

## Target User

团长要在手机上回答三件事：团队奖励里有多少来自服务带动，某个成员贡献了什么，这个成员的项目奖励现在还在不在贡献。

**JTBD：** 打开数据页后，分别进入奖励和成员，再打开一名成员的奖励详情，按常规或服务带动筛选，并看项目贡献和规则。

**Non-Users：** 不服务普通达人自己的收益页，不服务管理后台运营配置界面的日常操作。后台只提供规则文案。

**UJ：** 北城是 OPC 生态合伙人。他从数据页看到团队总奖励和成员数据，点开服务带动入口，再点一名成员看奖励明细和项目分析。

## Glossary

| 词 | 含义 |
|---|---|
| 团长 | 查看本团队奖励和成员的人。Demo 中是北城。 |
| 团队成员 | 团长团队里的成员。列表展示该成员自己的团队人数、团队总流水、个人流水，以及他给团长贡献的团队奖励。 |
| 服务带动 | 成员被服务带动后产生的奖励和社群关系。不改变该成员的团队归属。 |
| 常规团队奖励 | 服务带动范围以外、按团队规则计算的奖励。 |
| 服务带动奖励 | 服务带动范围内、按独立服务规则计算并计入团长团队奖励的部分。 |
| 服务承接社群 | 承接该成员服务带动的社群。 |
| TA的团队人数 | 该成员自己团队的成员总数。 |
| 团队总流水 | 该成员自己团队的总流水，包含他个人。 |
| TA的个人流水 | 该成员自己的个人流水，即用户个人的项目收益数据。 |
| TA贡献的团队奖励 | 该成员给团长贡献的团队奖励。 |

## Features

### FR-1 数据页拆开服务带动入口

数据页的服务带动信息不再合成一张卡片。奖励数据下提供「服务带动奖励」入口，成员数据下提供「服务带动成员」入口。

**Consequences：**

- 「服务带动成员」能点，并进入对应列表。「服务带动奖励」只展示金额，不响应点击。
- 「成员数据」标题旁有说明。点击打开浮层，内容读取后台字段 `team_member_rule`。点说明不进入成员列表。
- 服务带动奖励已计入团队奖励，页面上要说明这一点。
- 服务带动不改变团队归属。

### FR-2 团队成员列表的四项统计

团队成员列表每一名成员展示四项：TA的团队人数、团队总流水、TA的个人流水、TA贡献的团队奖励。

**Consequences：**

- 四项名称与 Glossary 一致。
- 团队总流水包含该成员个人。
- TA的个人流水只表示该成员自己的项目收益。
- TA贡献的团队奖励是他给团长贡献的团队奖励。

### FR-3 服务带动成员列表

服务带动成员列表的样式和数据与团队成员列表相同，并增加服务带动社群和服务带动奖励。

**Consequences：**

- 能看到服务承接社群。
- 能看到该成员的服务带动奖励，并可进入对应奖励。
- 一名成员有多个社群时，列表展示主要社群和数量；点开后列出这些社群。

### FR-4 共用奖励详情

所有成员的奖励详情共用一个页面。

**Consequences：**

- 成员被服务带动时，详情显示服务带动奖励是多少。
- 奖励数据增加标签「常规团队奖励」「服务带动奖励」，筛选条件同步增加。
- 详情提供项目分析。浮层展示该成员的项目奖励贡献。
- 项目被导师托管时，该项目显示服务带动。
- 项目增加标签：今日贡献奖励、持续贡献奖励、近期无贡献。
- 详情提供规则说明。浮层显示后台配置的规则内容，字段标识 `team_reward_rule`。

### FR-5 身份、排行和日历

数据页仍显示身份权益、项目排行榜和团队奖励日历。这三处和奖励区的「服务带动奖励」都不响应点击，也不再作为外壳场景。邀请入口保留。

**Consequences：**

- 团队奖励详情按成员展示累计奖励和今日新增，不提供「全部奖励来源」筛选。
- 身份权益、项目等级和奖励比例只作示例，正式计奖以平台结算规则为准。服务带动成员列表里的服务带动奖励金额只展示，不进入明细。
- 项目排行合并常规奖励和服务带动奖励。
- 历史收益入口保留，Demo 不包含历史账单。
