# 团长数据优化 — Experience Spine

## Foundation

单面手机，逻辑宽度 414px，嵌在迭代页里。视觉身份见 `DESIGN.md`。迭代外壳沿用现有记录台，本文件只写手机里的行为和壳层上的页签、规则、全屏。

没有新的组件库。按钮、抽屉、标签和流程图在外壳上沿用 `demo/iteration/component-spec-demo.html` 已有 class。

## Information Architecture

| 画面 | 从哪里来 | 做什么 |
|---|---|---|
| 数据页 | 团长进入 | 看团队奖励、成员数据，并分出两个服务带动入口 |
| 身份权益 | 数据页头图或规则 | 看身份等级和项目等级示例 |
| 团队奖励 | 数据页奖励主数字 | 按成员看各项目等级的团队奖励 |
| 团队成员 | 数据页成员数据 | 看四项统计 |
| 服务带动成员 | 数据页「服务带动成员」 | 与团队成员相同，并看社群和带动奖励 |
| 成员奖励详情 | 任一成员 | 所有成员共用。筛选、项目分析、规则说明 |
| 服务带动奖励 | 服务带动成员上的奖励条，或场景入口 | 只看服务带动奖励明细 |
| 项目排行榜 | 数据页 | 项目与成员的奖励排行 |
| 团队奖励日历 | 数据页奖励日历 | 按日看当月奖励 |
| 迭代外壳 | 总览点进 FR-CoCo-005 | 场景、需求规则、全屏预览、业务流程 |

画面参照：`demo/iteration/fr-coco-005-phone.html`。冲突时以本文和 `DESIGN.md` 为准；手机内部布局以来源 Demo 为准。

## Voice and Tone

短句，像账本说明。金额带单位或加号。服务带动每次出现都叫「服务带动」，不写成「托管奖励」或「导师奖励」。

| 这样写 | 不这样写 |
|---|---|
| 服务带动奖励已计入您的团队奖励 | 这笔钱已经算进去啦 |
| TA的团队人数 | 下级人数 |
| 常规团队奖励 / 服务带动奖励 | 普通 / 特殊 |
| 暂无符合条件的成员 | 空空如也 |
| 模拟数据，奖励统计与明细一致 | 以下为真实账单 |

未定的结算口径在手机里保持来源 Demo 的「以正式规则为准」。外壳上未定项写 `[待确认]`。

## Component Patterns

| 组件 | 用在 | 行为 |
|---|---|---|
| 服务带动奖励入口 | 数据页奖励卡下方 | 只展示金额，不响应点击 |
| 服务带动成员入口 | 数据页成员卡下方 | 点按进入服务带动成员列表 |
| 成员数据说明 | 数据页「成员数据」标题旁 | 点按打开浮层，读取 `team_member_rule`，不进入成员列表 |
| 成员四格 | 团队成员、服务带动成员 | 四项同时出现，名称固定 |
| 社群条 | 服务带动成员 | 一个社群直接显示名称；多个显示「名称 等 N 个社群」 |
| 奖励类型筛选 | 成员奖励详情 | 全部、常规团队奖励、服务带动奖励 |
| 项目分析 | 成员奖励详情 | 浮层，不离开详情 |
| 规则说明 | 成员奖励详情 | 浮层，读取 `team_reward_rule` |
| 备注 | 成员卡 | 浮层编辑，只留在本次 Demo，刷新即失 |
| 水印 | 列表页 | 开关只影响当前手机画面 |

## State Patterns

| 状态 | 画面 | 表现 |
|---|---|---|
| 有数据 | 列表和详情 | 显示示例成员和金额 |
| 筛空 | 成员列表、奖励列表 | 「暂无符合条件的成员」或「暂无符合条件的奖励」 |
| 无备注 | 成员卡底部 | 「暂无备注」或只显示加入时间 |
| 被服务带动 | 成员头 | 显示「服务带动」标签；详情多一行服务带动奖励金额 |
| 未被服务带动 | 奖励详情 | 不把服务带动金额当成必有字段去占一行主要结论 |
| 项目无贡献 | 项目分析 | 标签为「近期无贡献」 |
| 社群 | 点击社群卡 | 浮层说明进入未加入的社群页。本 Demo 不打开社群详情 |
| 历史收益 | 数据页 | 浮层说明演示不包含历史账单 |

## Interaction Primitives

- 点卡片主体进入该成员的奖励详情。点卡片里的按钮只做按钮自己的事。
- 返回回到上一画面，并回到离开时的滚动位置。
- 浮层点遮罩或「知道了」关闭。一次只关最上层。
- 搜索按用户 ID 或昵称过滤当前列表。
- 外壳场景条用消息切到对应手机画面。成员奖励详情场景打开棠宁 `3930131`。

## Accessibility Floor

- 可点的卡片和入口有文本，不只靠颜色。服务带动标签同时有「服务带动」四个字。
- 奖励主数字所在按钮有「查看团队奖励详情」这个名字。
- 手机里的钻取箭头如果单独可点，带「成员产生奖励详情」或同等名字。
- 外壳场景、页签、需求规则和全屏退出都能用键盘到达。Esc 先关规则抽屉，再退出全屏。

## Key Flows

### 北城拆开服务带动

北城晚上打开团长数据页，想知道今天的团队奖励里有多少是服务带动。

1. 他先看团队总奖励，再看奖励卡下面单独的「服务带动奖励」。
2. 他往下看成员数据，点标题旁的说明，读到后台 `team_member_rule`，再确认「服务带动成员」是另一个入口。
3. 他点「服务带动成员」，列表仍是成员卡，但每张卡多了服务承接社群和服务带动奖励。
4. 他点开一名带「服务带动」标签的成员。高潮：详情里能看见服务带动奖励金额，并能筛成只看「服务带动奖励」。
5. 他点项目分析，看到被导师托管的项目标着服务带动，以及今日贡献、持续贡献或近期无贡献。
6. 他点规则说明，读到后台 `team_reward_rule` 的文案，然后返回数据页。

## 迭代外壳

外壳有两个页签：前端交互、业务流程。没有管理后台页签。

需求规则抽屉分「前端需求」和「后台需求」，只写本需求。后台需求说明 `team_reward_rule` 由奖励详情的规则说明读取，`team_member_rule` 由数据首页「成员数据」旁的说明读取。页头「需求规则」左边是「全屏预览」，右上角「退出全屏」。

业务流程只在「业务流程」页签。规则正文不重复全文，只写「见本页业务流程」。
