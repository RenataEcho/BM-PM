模块 / 字段规则、来源与验收

成员奖励排行

统计成员为当前团队实际带来的奖励，不是成员个人推广收益。筛选成员或归属类型不会改变顶部项目总额。

完整需求规则与验收口径（点击展开）
功能规则 / 数据源 / 权限
统计来源已生效的团队奖励流水，必须关联项目ID、奖励成员ID、奖励归属类型、归属日期及唯一流水ID；不以个人收益直接代替
累计奖励按当前账号可见团队范围汇总该项目有效奖励净额；退款、冲正按业务规则形成调整流水，不覆盖原流水
成员数所选项目累计有效奖励成员去重；顶部为累计人数，榜单计数随筛选区间变化
排行按所选时间区间奖励净额排序；默认降序；同金额按首次有效奖励时间、用户ID稳定排序
筛选累计/今日/昨日/自定义日期、昵称/用户ID、奖励归属；筛选只影响榜单，顶部保持项目累计概览
占比成员当前区间奖励 ÷ 当前项目同区间总奖励；不以筛选后成员小计作为分母
服务带动按每笔奖励生效时的实际归属类型统计；加入导师团后新产生的服务带动奖励不重复进入直属/间属；历史邀请关系不改变
成员详情展示累计、当前区间、今日、昨日、奖励分类构成及奖励流水示例；无权限时隐藏敏感信息
历史与调整保留原奖励流水及调整流水、归属生效时间；历史结果支持按指定统计时点复核
对账项目奖励 = 成员归属奖励净额 + 无法分配到成员的独立调整项；存在未归属项须明确展示，不强制伪造成员归属
空状态无匹配成员显示空状态；无奖励项目仍可显示项目，但不进入有奖励成员排行
权限服务端按账号可见团队成员集合及奖励权限过滤；前端筛选不作为权限边界
待产品确认：跨日结算与奖励归属日期优先级、负向调整的展示方式、历史组织关系变化是否重算。这三项需与现有团队奖励账本保持一致。
