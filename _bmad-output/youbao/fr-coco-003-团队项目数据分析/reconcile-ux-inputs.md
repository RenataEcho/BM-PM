## 1. 用户已经明确的视觉与交互决策

### 1.1 身份与范围

- 最新名称是“团队项目数据分析”，编号是 `FR-CoCo-003`，业务线是“右豹主业务”；旧称“团队数据优化”“项目分析数据”和 `FR-COCO-03` 均需退出页面合同。
- V1 是移动端查看与分析链路，不新增运营管理后台，不提供编辑奖励、修改归属、调账、结算或审批。
- 主要链路固定为：团队数据页入口 → 项目数据首页 → 项目详情/成员排行榜 → 成员奖励详情底部抽屉。

### 1.2 本 FR 的视觉方向

- 指定参考 HTML 是本 FR 的视觉验收基准；应保留其页面层级、主要样式、文案位置和可见交互形态。
- 本 FR 明确使用品牌主色 `#FF603B` 和暖色背景 `#FFF3EE`。这是对通用移动端 `#ff4d22` 以及“数据页默认黑金 Hero”的本 FR 特例覆盖：本页采用参考中的浅橙 Hero，不改成黑金。
- 手机画面保持浅灰页底、白卡、轻阴影、暖橙强调、圆角卡片；图表和文字图例共同表达，不能只靠颜色。
- 项目数据首页的核心层级固定为：
  1. 返回栏与“项目数据”标题；
  2. 浅橙奖励 Hero，展示累计项目奖励、奖励项目数、今日奖励、昨日奖励；
  3. 项目奖励构成卡：累计/今日/昨日切换、环形图、文字图例；
  4. 项目奖励明细卡：排序器、全部项目卡片。
- 项目详情的核心层级固定为：项目信息与四项汇总 → 成员排行时间切换 → 搜索/归属/排序筛选 → 排行列表 → 加载更多。
- 成员详情使用手机画布内的底部抽屉，而不是新页面或迭代台右抽屉。

### 1.3 已确定的交互

- 团队数据页入口固定显示“项目数据”和“查看项目奖励构成与排行”，并显示奖励项目数与跳转标识；不显示成员数、累计奖励或今日奖励。
- 奖励构成默认累计，支持累计/今日/昨日；按当前范围重算排序、分组、总额和占比。前 4 个项目独立展示，第 5 名起合并为“更多项目”；“更多项目”不下钻。
- 项目明细仍展示全部奖励项目，不受图表分组影响；支持累计/今日/昨日三种降序排序；每个项目都可下钻。
- 成员排行支持累计/今日/昨日/自定义日期、昵称模糊搜索、用户 ID 精确搜索、奖励归属筛选、奖励升降序和昵称排序。
- 名次不是当前显示顺序号：名次始终按当前筛选结果的奖励金额降序计算；改为升序或昵称排序只改展示顺序，不改名次；同额采用竞赛排名，用户 ID 负责稳定展示。
- 成员详情关闭后保留排行榜的时间范围、搜索、归属、排序和滚动位置；逐层返回还要保留项目页、项目数据首页的筛选、排序和滚动上下文。
- Demo 使用同一套可对账的静态 Mock 数据，不连接真实接口、登录、权限或持久化。

### 3.3 隔离硬规则

- 禁止把 shell 的蓝紫主色、玻璃背景、后台按钮、400px Modal、右侧 Detail Drawer 混进手机画布。

- Esc 只关闭当前上下文的最顶层 overlay：iframe 聚焦时关闭成员 Sheet；父页面聚焦时关闭需求规则抽屉。不能一次关闭两层。
- 手机页按移动端宽度响应；迭代台负责 375×812 左右的展示框、缩放和桌面布局，手机内容不得读取 shell token。
- 本 FR 无管理后台 Tab。数据支持写入规则或业务流程，不新增一个“后台页面”表面。

## 5. P01 / P02 / P03 / P05 / P06 在 Demo 中的标注方式

统一原则：

- 默认主路径只使用非负、可对账、无未归因异常的 Mock 数据。
- 在迭代台规则抽屉集中列出 P-ID、问题、影响表面和“正式开发前阻塞”；手机画布只在直接受影响的字段或场景附近放短标记。
- 标记使用 `[Pxx 待确认]`，不得使用会暗示已选择某个方案的示例、文案或算法。
- 不把“元、两位小数、搜索/筛选/分页、竞赛排名”等已定内容继续标成待确认。

| P-ID | Demo 可如何标 | Demo 不得做什么 |
|---|---|---|
| P01 今日/昨日日期口径 | 在时间切换附近写“今日/昨日沿用现有团队奖励页；业务日期/入账日期、时区与日界线 [P01 待确认]”；示例日期仅标“Mock 日期” | 不写死北京时间、0 点日界线，也不声称按业务发生日或结算日 |
| P02 全冲正成员计数 | 在“累计奖励成员数”说明中标“全冲正为 0 的成员是否计数 [P02 待确认]”；主数据只放有正向有效奖励的成员 | 不用 Mock 是否显示该成员来暗示“计入”或“不计入” |
| P03 全冲正项目保留 | 在入口项目数和项目列表说明中共用“全冲正项目是否保留/计数 [P03 待确认]”；默认不构造全冲正项目 | 不把“零奖励项目列最后”泛化为对全冲正项目的正式结论 |
| P05 跨日调整归日 | 在历史记录/规则说明标“跨日退款、冲正、补发归原业务日或调整发生日 [P05 待确认]”；默认 Mock 不放跨日调整 | 不把调整写回某一天，也不让 Mock 汇总暗示归日策略 |
| P06 负值与非正总额 | 主路径坚持非负 Mock；另设“负值口径待确认”说明场景，只列受影响表面（概览/图表/列表/排行/详情）和 P-ID | 不做负值图表、不用 `max(0)` 当产品规则、不擅自隐藏负值、不把非正总额直接等同普通空态 |

参考 HTML 内“负数或总额非正时不强行展示饼图占比”的规则说明不能直接升级为 P06 结论；它只能作为风险提示，最终展示方式仍待产品回填 PRD。

## 6. 参考 HTML：视觉合同与 Mock 实现的分界

### 6.1 应提取为视觉 / 可见交互合同

- 浅灰移动页底、白卡、轻阴影、暖橙强调、`#FFF3EE` Hero、`#FF603B` 关键数字和选中态。
- 约 12px 页面留白、15–16px 卡片圆角、紧凑移动端字体层级和轻边框项目卡。
- 项目首页的顺序：标题栏 → Hero/KPI → 构成卡 → 项目明细卡。
- 构成卡的并排结构：环形图及中心总额 + 文字图例；窄屏可缩图，但不删除文字图例。
- 项目详情的顺序：返回栏 → 项目汇总 → 排行筛选 → 排行列表 → 加载更多。
- 成员行的视觉信息组：名次、头像、昵称/ID、归属标签、奖励金额/占比、详情箭头。
- 成员详情采用手机 Bottom Sheet，包含身份、2×2 汇总、归属和历史记录区。
- 可见控件及载体：累计/今日/昨日、自定义日期、搜索、归属筛选、排序、项目点击、成员点击、遮罩/关闭按钮。
- 项目图标的“暖橙方圆底板”可作为视觉语言；具体 emoji 或图标内容不是合同。

以上合同约束“长什么样、控件放在哪里、以什么载体交互”，字段含义和状态结果仍以 PRD 为准。

### 6.2 仅是 Mock 数据或实现，不得写进 spines

- 具体项目、成员、昵称、用户 ID、金额、日期、86 人、9 个项目、番茄小说等示例内容。
- `homeShares` 比例缩放、随机/公式生成流水、所有项目复用同一批成员、每位成员固定单一归属。
- 数组结构、函数名、DOM ID、内联样式、`conic-gradient` 画图方式、hash 路由、事件绑定方式。
- 每次加载 10 条、按钮“加载更多”的具体批量值。
- 参考版只有第一个项目可下钻、其他项目弹 `alert`；PRD 要求每个项目均可下钻。
- 用当前数组下标生成名次；它会在搜索、升序或昵称排序后改变名次，不符合 PRD。
- 返回首页直接滚到顶部；PRD 要求恢复筛选、排序与滚动。
- 内嵌 `<details>` 的“完整需求规则”、其中的待确认描述及“方案 A”等文案；这些不是需求权威来源。
- Mock 中用 `max(0)` 消除负数、仅生成非负数据，只是演示边界，不代表 P06 结论。
- 具体 emoji、页脚固定定位、`max-width: 440px` 的代码写法和具体 CSS selector 均可在不破坏视觉结果时调整。
