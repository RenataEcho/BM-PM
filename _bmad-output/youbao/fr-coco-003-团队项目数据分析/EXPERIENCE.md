## Foundation

- **形态**：移动端单列经营数据查看链路，嵌入桌面 FR 迭代外壳；不新增管理后台产品页。
- **视觉真源**：颜色、字号、间距、组件与父子隔离见 `DESIGN.md`。本文件只定义信息架构、交互、状态、流程与可访问行为。
- **产品真源**：最终 `prd.md` 与 V4.2 内嵌明确规则优先；用户提供的 V4.2 页面用于补充 IA、字段位置和交互结果；固定 Mock 值与实现代码不是合同。
- **统计边界**：项目和成员数据使用当前账号有权范围；全项目成员按成员去重，订单指标按订单唯一 ID 去重；团队奖励与成员关系采用 PRD 语义。
- **Demo 边界**：可使用已授权、非负、无并列且不含多项目关联订单的静态 Mock；不接真实接口、登录、权限或持久化。

## Information Architecture

| Surface | 入口 / 退出 | 核心职责 |
|---|---|---|
| S1 团队数据入口 | 既有团队数据页「成员数据」卡片底部内嵌“项目数据”；返回仍在既有页 | 在不改变成员指标和查看详情的前提下提供项目数据导航，不新增独立“项目分析”分区 |
| S2 项目数据页 | S1 进入；返回 S1 | 四项顶部概览、累计/今日/昨日奖励构成、项目/成员两个顶层 Tab |
| S3 项目详情 | S2 项目卡进入；返回 S2 | 当前项目身份、成员奖励排行/成员出单排行双 Tab、两榜共用筛选 |
| S4 全项目成员汇总抽屉 | S2 成员卡打开；关闭回 S2 | 当前周期下三项总计与各项目三项明细 |
| E1 既有成员产生奖励详情页 | S3 两榜成员卡外部跳转 | 接收成员 ID + 项目 ID，承接既有业务详情 |
| D1 外部迭代 Shell | 业务线总览进入本 FR | 承载评审 Tab、场景、手机 iframe 与规则 overlay，不属于产品 IA |

产品主路径为 `S1 → S2 → S3 → E1`，全项目成员分支为 `S2 → S4`。S4 只服务全项目成员入口；S3 两个榜单都交给 E1。D1 使用迭代外壳 token，S1–S4 使用 `DESIGN.md` 手机 token，两者不共享 DOM、焦点域或 overlay 层级。

## Voice and Tone

- 使用“团队奖励”“有效出单量”“出单流水（元）”完整字段名；出单流水明确为有效订单交易金额，不表述为个人收入。
- 空筛选写“未找到符合条件的成员/项目”；源数据为空写“当前暂无项目数据”或“当前暂无成员数据”；接口失败写“加载失败，请重试”。
- “更多项目”只说明其为第 6 名及之后项目的图表聚合，不暗示可展开或下钻。
- 未决口径只在规则说明中标记 `[待确认] Pxx`，不在主路径文案中暗示一个尚未决定的答案。
- Demo 可标“示例数据，不代表生产口径”；不得把项目名、成员名、金额、日期或固定数量写成业务事实。

## Component Patterns

### S1 Member Embedded Entry

- `{components.member-embedded-entry}` 位于成员数据白色卡片底部，与三项成员指标以分隔线连接；整行只有一个导航目标。
- 行内展示标题“项目数据”、副文案“查看项目奖励构成与成员排行”和跳转标识；V4.2 不要求展示项目数、成员数或金额。
- 不新增“项目分析”分区或外置入口卡；既有“查看详情”、成员指标与底部邀请按钮保持不变。

### S2 Overview and Reward Composition

- `{components.overview-grid}` 使用一个双列组件展示累计、今日团队奖励及对应出单流水，不展示昨日统计。流水固定在左列，奖励固定在右列；今日值使用灰色辅助文字，奖励值不单独高亮。
- 页头问号图标打开页面统计规则说明浮层；说明内容由后台配置，字段标识为 `data.tips`。
- 构成指标下拉支持“项目奖励构成 / 项目流水构成”；`{components.period-switch}` 控制当前指标的累计/今日/昨日周期。切换后重新计算金额、降序、前五项目与“更多项目”。
- `{components.donut-chart}` 后接结构化图例。图表与项目榜共享底层数据，但项目榜排序绝不改动图表指标、周期、排名、分组或金额。

### S2 Project Board

- 顶层 Tab 为“项目排行榜”。排序选择有且仅有三项：累计/今日/昨日出单流水降序，不提供团队奖励排序。
- 项目卡展示项目名称、项目 Icon、六项金额和进入详情的单一主操作。Icon 缺失或加载失败时使用 `{components.icon-fallback}`。
- “更多项目”不出现在项目列表；每个具体项目以稳定项目 ID 进入 S3。

### S2 Global Member Board

- 顶层 Tab 为“成员排行榜”。`{components.filter-card}` 从上到下为搜索、五项关系、时间选择、排序选择。
- 搜索支持用户 ID 或昵称；关系为全部、直属、间属、直属团队、间属团队；周期为累计、今日、昨日、近 7 日、近 30 日。
- 排序有且仅有团队奖励、出单流水、有效出单量三种降序。结果最多前 100 名。
- 每张 `{components.member-profile-card}` 展示名次、昵称、用户 ID、成员关系、有效出单量、出单流水、团队奖励。卡片语义明确为全部有权项目去重汇总。
- 点击成员打开 S4；S4 周期与成员榜当前周期同步，不让用户在抽屉内选择另一周期。

### S3 Project Detail Boards

- 顶部保留项目名称、Icon、导航和双 Tab，不展示项目概览 KPI。
- 两榜共用同一个搜索值、关系值和周期值；切换 Tab 不产生第二套筛选。搜索支持用户 ID / 昵称，关系五项，周期五项。
- S3 不提供排序控件。每榜最多前 100 名；第 100 名并列和同值稳定顺序由 P09 决定。
- 奖励榜固定按团队奖励降序，团队奖励为主强调指标。
- 出单榜固定按出单流水降序，出单流水为主强调指标，有效出单量使用醒目字段标签和同级数字层次。
- 两榜成员卡均完整展示昵称、用户 ID、成员关系、有效出单量、出单流水、团队奖励；不展示 V 标签、活跃度、加入日期或备注操作。
- 点击任一榜成员都向 E1 传递成员 ID 与当前项目 ID；不在 S3 打开 S4。

### S4 Aggregate Member Sheet

- `{components.aggregate-member-sheet}` 为手机文档内模态 Sheet。标题区显示成员昵称、用户 ID、成员关系和当前周期。
- 总计区展示有效出单量、出单流水、团队奖励；各项目明细逐项目展示同样三项。
- 同一订单关联多个项目时，总计和各项目明细的求和解释等待 P13；UX 不用脚注、强制等号或视觉对齐假设替代产品决策。

### E1 Handoff

- 正式产品按既有导航机制打开「成员产生奖励详情页」，传递成员 ID、项目 ID。V4.2 未要求向既有页面传递当前筛选周期。
- Demo 未连接既有页时，点击可打开规则提示：说明目标页名称及将传递的两个 ID；提示关闭后回到 S3。提示不是新详情页。

## State Patterns

本 FR 只把 V4.2 明确的状态作为合同：

- **搜索/筛选无结果**：保留当前筛选控件和取值，在列表位置显示“未找到符合条件的成员”，提供清除搜索或重置筛选的明确操作。
- **数据为空**：当概览、图表、项目或成员确实没有服务端数据时，在对应模块显示语义化空态；不生成伪卡片。真实零值可显示 `0` / `0.00`，但不得用零替代未知或失败。
- **接口错误**：保留页面身份与已知筛选标签，显示“加载失败，请重试”和重试按钮。接口异常永远不展示为 `0`、空榜或搜索无结果。
- **局部与整体**：若接口拆分，错误状态停留在受影响模块；若无法安全组合数据，则整个相关分析区域进入错误状态，不展示可能误导的局部合计。
- **权限**：前端必须按授权结果控制敏感字段、榜单或入口的呈现，后端对每次查询按账号、团队和项目范围再次校验。未授权请求不得返回有效出单量、出单流水或越权项目/成员数据。未授权时具体是隐藏、禁用、权限提示或其他形式仍为 `[待确认] P11`，本文不选择呈现方案。

本合同不要求预加载骨架、追加浏览机制、失败后沿用某个冻结时点，或返回后恢复筛选与滚动。实现可以采用不改变产品语义的技术加载反馈，但不能把它提升为验收前提。

## Interaction Primitives

- **顶层 Tab（S2、S3）**：使用 `tablist/tab/tabpanel`。Tab 键进入当前选中项一次，左右方向键移动焦点，Enter/Space 激活；选中状态同时可见并由 `aria-selected` 暴露。激活后焦点留在 Tab，状态区播报新榜单名称与结果数。
- **图表周期**：累计/今日/昨日使用带可见组名的单选分段控件。方向键移动并选择；更新完成后礼貌播报周期、总额和分类数量。
- **Select**：项目排序、全项目成员周期与排序都有持久可见标签，保留原生键盘行为。变更后焦点留在控件，结果区播报排序/周期和结果数。
- **Search**：可见或程序化标签为“搜索用户 ID 或昵称”。Enter 可提交，输入即时筛选时需节流；清除按钮名称为“清除搜索”，清除后焦点回输入框。无结果标题与搜索框通过说明关系关联。
- **Relation Scroller**：五项按单选组实现。Tab 进入当前项，左右方向键移动并选择；当前项自动完整滚入视口。触摸/触控板可横向滚动，但容器不抢占页面纵向手势；首尾标签都能完整到达。
- **Member/Project Cards**：整卡只保留一个主下钻目标；内部指标不制造重复焦点。可访问名称包含项目/成员身份、当前关键指标和目标。
- **S4 Sheet**：打开时记录触发卡，把手机背景设为 `inert`，焦点移到 Sheet 标题或关闭按钮并陷阱在 Sheet 内。Esc、可见关闭按钮和遮罩均可关闭；关闭后焦点回触发卡，若触发卡已不存在则回成员榜标题。
- **E1 外部页面交接**：触发前使用当前卡片的成员 ID 与当前项目 ID。单页应用路由后焦点落到 E1 主标题；若新浏览上下文打开，链接名称需说明“在新页面打开”。Demo 规则提示按模态焦点规则处理。
- **D1 父子协议**：iframe 标题为“FR-CoCo-003 团队数据 V4.2 手机演示”。父规则 overlay 打开时父页面其余内容（含 iframe）不可交互；手机 S4 打开时只约束子文档。一次 Esc 只关闭最上层并停止传播。

## Accessibility Floor

- 所有独立目标至少 `{spacing.touch-min}` × `{spacing.touch-min}`；375px 不横向溢出，关系控件是唯一允许的局部水平滚动区。
- 文本缩放 200% 时概览、筛选、指标和 Sheet 可换行/重排；不裁切标签，不以横向拖动画布读取普通内容。
- 普通文字对比至少 4.5:1；焦点环、边界和图形对象至少 3:1。选中、排名和数据映射均具备非颜色线索。
- 图表提供标题、周期、总额和结构化图例；图例按奖励降序列出编号、项目名、金额、占比，“更多项目”明确为聚合。若 SVG 从可访问树隐藏，图例承担完整等价信息。
- 成员集合使用列表或表格语义，名次为显式字段；三项指标都带完整字段名和单位。用户 ID 朗读名称包含“用户 ID”。
- 错误区域可感知并把说明与重试按钮关联；重试后不强制把焦点移离按钮，完成结果通过礼貌状态区播报。
- `prefers-reduced-motion: reduce` 时取消 Sheet 位移动画、图表入场和列表重排动画；焦点与结果反馈不依赖动画结束。
- 子文档设置 `lang="zh-CN"`、唯一 `<title>` 和一个主标题；不使用正 `tabindex`。

## Key Flows

### Flow 1 / UJ-1：比较项目经营表现

1. 小林进入 S2，先按“上层累计、下层今日；左侧流水、右侧奖励”的顺序读取四项顶部概览。
2. 他将奖励构成从累计切到今日，查看前五项目和“更多项目”的图形与结构化图例。
3. 他停留在“项目排行榜”，分别选择今日团队奖励降序和今日出单流水降序。
4. 项目列表顺序随六项排序变化，奖励构成图保持今日周期下自己的奖励降序与分组。
5. **Climax：** 小林可同时判断奖励贡献与流水表现，不把列表排序误读为图表变化。
6. 他点击具体项目，以稳定项目 ID 进入 S3。

失败分支：任一关键接口失败时显示错误与重试，不把概览、图表或卡片值写成零。

### Flow 2 / UJ-2：定位全项目关键成员

1. 小林在 S2 切换到“成员排行榜”。
2. 他输入用户 ID 或昵称，选择成员关系、近 30 日，并按出单流水降序。
3. 页面展示有权项目范围内去重后的前 100 名，每张卡完整展示身份与三项指标。
4. 他点击目标成员，打开 S4；Sheet 标题明确“近 30 日”，总计与各项目明细使用同一周期。
5. **Climax：** 小林在一个模态层中核对成员跨项目总贡献与分项目明细，不把同一成员当成多个成员。
6. 他关闭 S4，焦点回原成员卡。

失败分支：搜索/筛选无结果显示专属空态；接口失败显示错误重试，两者不互相伪装。

### Flow 3 / UJ-3：分析单项目双排行榜

1. 小林进入 S3，确认项目名称后在奖励榜与出单榜之间切换。
2. 他设置一次搜索、关系和近 7 日周期；两榜共用这组条件。
3. 奖励榜按团队奖励降序；出单榜按出单流水降序，并让有效出单量清晰可见；两榜卡片都保留三项指标。
4. 他点击任一榜中的成员，系统向 E1 传成员 ID、项目 ID。
5. **Climax：** 小林从不同经营视角进入同一既有成员详情载体，且项目身份不会丢失。

失败分支：Demo 未连接 E1 时显示规则提示，不模拟新成员详情。

## Responsive & Platform

- 手机 iframe 基准为 375×812，内容单列纵向滚动；较宽手机仍保持单列，不扩成桌面仪表盘。
- 200% 文本下，四项顶部概览、筛选双列和三项指标可重排；卡片名称可换行。关系选项保留局部滚动和完整选中项。
- D1 负责评审手机框与规则 overlay，不使用父级 `transform: scale()` 抵消浏览器缩放，也不让手机页面读取父 viewport 形成另一套布局。

## Demo Contract

- Demo 使用授权、非负、无并列且不含多项目关联订单的 Mock，覆盖三条 UJ 的主路径、筛选空态、数据空态和接口错误重试。
- Demo 的单项目成员点击可显示 E1 规则提示，因为实际业务页未连接；提示必须说明成员 ID + 项目 ID 的交接，不展示伪详情数据。
- 固定项目名、成员名、金额、日期、关系分布、数组、生成系数和路由实现不构成产品合同。
- D1 只负责外壳展示；S4 是手机内 Sheet。两者不共享样式、遮罩、焦点陷阱或 Esc。

## Open Gates

以下门禁只说明 UX 影响，不在本文件选择视觉或业务答案；完整问题、Owner 和关闭条件见 `prd.md` §9。

|---|---|

| P06 | 负净额、非正总额与抵消为零的展示和排序尚未决定 |
| P07 | 有效订单状态与退款/部分退款规则会改变有效出单量和出单流水 |

| P09 | 第 100 名并列截断与同值二次排序会影响三类成员榜的末位和名次 |

| P12 | 奖励台账/追溯模型是否继承会影响未来明细解释，但不改变本版不重复归属与历史归属合同 |
