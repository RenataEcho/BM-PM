## 4. 缺口

### G1 — 既有团队页颜色保护范围不够明确（中）

`DESIGN.md` 使用“手机 iframe 不混入蓝紫色”的全局表述，但 `入口参考.png` 中既有团队数据页包含紫色固定主操作。若按字面实施，可能把既有团队页的品牌控件一并改成暖橙色，违反“不改变原有团队奖励和成员数据”的入口语境。

建议后续明确：暖橙 token 约束新增入口卡及 S2–S4；既有团队页原组件和固定主操作保持原样，不因本 FR 重绘。

### G2 — 入口与底部固定操作的空间关系未定义（中）

截图底部有固定主操作，而双 spine 只写“成员数据之后的独立入口”，没有说明入口卡应位于固定操作上方、需要多少滚动底部留白、是否允许被固定操作遮挡。

建议后续明确：入口属于页面滚动内容，排在成员数据后；页面底部预留安全间距，入口的标题、项目数和点击区域不得被固定操作遮挡。

### G3 — 少量辅助文案的位置未被锁定（低）

参考 HTML 把“团队奖励分析”放在首页标题栏右侧，把图表统计说明放在构成卡底部，把“不是成员个人推广收益”的说明放在详情筛选区下方，并在页脚标明 Mock。双 spine 已覆盖这些语义或 Demo 声明，但未全部固定到参考位置。

建议后续区分处理：与理解统计口径直接相关的说明保留在对应模块附近；纯 Demo 声明留在迭代外壳或手机页脚，不进入产品 IA；标题栏辅助文案若不采用，应记录为有意删除。
