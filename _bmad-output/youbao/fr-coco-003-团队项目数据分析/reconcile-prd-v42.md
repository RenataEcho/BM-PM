## 2. V4.2 明确的新产品能力与口径

### 2.1 项目数据首页扩展

1. 项目数据页增加双 Tab：
   - `项目排行榜`
   - `成员排行榜`（跨全部项目汇总）
2. 项目排行榜同时展示：
   - 项目名称
   - 项目 Icon
   - 累计 / 今日 / 昨日团队奖励
   - 累计 / 今日 / 昨日出单流水
3. 项目排行榜提供六种降序排序：
   - 累计团队奖励
   - 今日团队奖励
   - 昨日团队奖励
   - 累计出单流水
   - 今日出单流水
   - 昨日出单流水
4. 列表排序与奖励构成图相互独立；切换列表排序不得改变饼图按奖励金额形成的排名和分组。
5. 项目 Icon 由后台配置；缺失时显示兜底图。

### 2.2 奖励构成改为 Top 5 + 更多

- 奖励构成仍支持累计、今日、昨日。
- 每个周期按团队奖励降序，独立显示前 5 个项目，其余聚合为「更多项目」。
- 「更多项目」仅用于图表聚合，不作为项目列表项。
- 该规则明确替换旧 PRD 的“前 4 个项目 + 第 5 名起合并”。

### 2.3 全项目成员排行榜

- 汇总当前账号有权查看的成员在全部项目产生的：
  - 有效出单量
  - 出单流水
  - 团队奖励
- 同一成员跨项目去重。
- 最多展示前 100 名；这是内嵌规则明确的产品上限，不是从脚本 `.slice(0,100)` 推断。
- 支持：
  - 用户 ID / 用户昵称搜索
  - 五类成员关系筛选：全部、直属、间属、直属团队、间属团队
  - 五种时间维度：累计、今日、昨日、近 7 日、近 30 日
  - 三种降序排序：团队奖励、出单流水、有效出单量

### 2.4 项目详情双排行榜

- 项目详情保留两个独立 Tab：
  - `成员奖励排行`：固定按团队奖励降序
  - `成员出单排行`：固定按有效出单流水降序，并显示有效出单量
- 两榜都只统计当前项目，每榜最多 100 名。
- 两榜共用：
  - 用户 ID / 昵称搜索
  - 五类成员关系筛选
  - 五种时间维度
- 项目详情不再提供排序下拉。
- 项目详情保留项目名称、导航和排行榜，明确不恢复原顶部四项统计卡片。

### 2.5 出单、关系、时间、权限与去重

- `有效出单量`：所选周期内有效订单笔数；无效、撤销或不符合结算口径的订单不计入。
- `出单流水`：有效订单交易金额，单位元，不代表成员个人收益。
- 跨项目汇总出单数据时，必须依据订单唯一 ID 去重。
- `成员关系`与`奖励归属`是两个不同维度：
  - 关系筛选采用全部、直属、间属、直属团队、间属团队。
  - 加入导师团不改变原邀请关系。
  - 后续适用奖励可按服务带动归属统计，且不得与其他归属重复计入。
  - 历史奖励归属保持发生时口径。
- 时间维度：
  - 累计：业务累计有效数据。
  - 今日 / 昨日：业务时区自然日。
  - 近 7 日 / 近 30 日：统一服务端统计窗口。
  - 列表与详情必须使用一致窗口。
- 权限：
  - 出单流水、订单量等敏感经营数据只向明确授权账号开放。
  - 前端按权限控制展示。
  - 后端仍须按账号、团队、项目范围再次校验，不得只隐藏组件。
- 异常状态：
  - 搜索或筛选无结果显示空状态。
  - 接口失败显示重试。
  - 不得把接口异常误显示成 `0` 收益。

## 7. 更新前基线识别的未确认业务口径

1. **订单有效状态合同**：规则只说明无效、撤销或不符合结算口径不计入，未列出实际状态枚举、退款 / 部分退款 / 补单的处理。

3. **窗口边界**：近 7 日 / 近 30 日是否包含当日、按自然日还是滚动小时窗口，未定义。
4. **Top 100 并列与稳定排序**：第 100 名并列是否截断、同值二次排序字段未定义。
5. **全项目成员关系冲突**：同一成员在不同项目 / 历史时点出现不同关系时，跨项目汇总榜使用当前关系还是订单 / 奖励发生时关系，未定义。
6. **授权模型**：哪些账号角色具备出单流水和订单量查看权限、无权限时隐藏整个 Tab 还是脱敏字段，未定义。
7. **项目入口项目数与全冲正项目**：V4.2 页面仍展示“奖励项目”概念，但完整规则没有重新定义入口数字及其与项目榜的对账关系。
