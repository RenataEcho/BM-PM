# FR-wen-005 · 一键代发用户定向约稿； · 行为合同

## Foundation（基础）

业务线为**右豹主业务（youbao）**。本次依据同目录[PRD v4](prd.md)的已确认口径，不继承原需求单中被更新的天单位、完成／超时旧称。全局号沿用FR-wen-005，不另占号；需求原名保留末尾分号。文档ux-v1表示本轮交付完成，不等于用户视觉签核。

面向三种表面：申请用户的移动端一键代发、剪辑手PC客户端「剪辑供稿－定向约稿」、管理后台。视觉引用[DESIGN.md](DESIGN.md)，手机以 `{colors.mobile-primary}` 为主操作色、`{colors.mobile-ink}` 为关键正文；PC使用 `{colors.pc-primary}`；后台使用 `{colors.admin-primary}`。继承现有供稿、站内通知、稿件审核、稿件详情、领取、回填和平台收费，不建立新的交易、登录或权限系统。

后续静态Demo只模拟状态和交互，不连接真实接口、登录、权限或持久化。业务上的权限限制必须可演示，但不实现真实鉴权服务。本次仅交付两份文档；独立UX审查按用户选择不执行，PRD对照与必要文档自检仍执行。

## Voice and Tone（文案）

文案说明当前事实、下一步及限制，不把平台处理过程描述为用户已获得稿件。状态采用PRD完整名称；「已回填」才代表完成。未提供书籍ID显示「未提供」，未上传关联稿件显示「暂无关联稿件」，删除稿件状态显示「已删除」，读取失败不能伪装成缺失。

### 已确认校验与接受确认

| 触发 | 精确文案／反馈 |
|---|---|
| 项目、书籍／剧或剪辑手缺失 | 「请填写完整后再提交申请」；标出缺失项并定位首错 |
| 已选剪辑手后换成未授权项目 | 「该剪辑手不做此项目稿件」；保留剪辑手、清空原书籍／剧 |
| 提交时项目与剪辑手不匹配 | 「该剪辑手不支持当前项目稿件，请修改后重新提交」；不产生申请 |
| 时限空值、负数、小数、非整数、超过999 | 「请输入0—999之间的整数，0表示不限制」；不保存 |
| PC通过前确认标题 | 「确认接受约稿」 |
| PC通过前确认正文 | 「请仔细核对本次约稿的项目及书籍／剧信息。书籍／剧信息可能由用户手工填写，平台暂不强制校验，请确认准确后再接受约稿。」 |
| PC通过前确认信息与按钮 | 同时展示项目、书籍／剧名称及已提供的ID；无ID写「未提供」。按钮「返回核对」「确认接受」 |

### 站内通知：仅两类触发

| 类型／结果 | 已确认通知正文 |
|---|---|
| 剪辑手审核通过 | 「你的定向约稿申请已通过，剪辑手将为你制作稿件，请前往约稿页面查看进度。」 |
| 剪辑手审核拒绝 | 「你的定向约稿申请未通过，你可以前往约稿页面查看记录并重新申请。」 |
| 剪辑手已上传 | 「剪辑手已上传你的定向稿件，正在等待后台审核。审核通过且可领取后，请及时领取；如有领取时限，请在截止前领取。可前往约稿页面查看进度。」 |

三段通知文案对应审核结果、上传两类场景；不新增审核通过可领取通知、短信、推送、催单或超时提醒。上传通知不写死48小时。通知点入时重新读取记录当前有效阶段，已结束仍可看，不能绕过审核或领取条件。

### 页面说明

制作中显示「剪辑手已接受约稿，正在制作，接受后不可取消」；稿件审核中显示「稿件已上传，正在等待后台审核，暂不可领取」。审核通过但尚不可领取时显示「稿件已通过审核，当前暂不可领取，请查看后续进度」，仍不显示领取倒计时。不限时显示「交付时限：不限制」或「领取时限：不限制」，不显示“永不过期”、虚构截止时间或零秒警告。新增布局说明文案不增加通知场景。

### 申请填写与选择联动

1. 历史入口预填来源项目、书籍／剧、剪辑手；主动入口三项由用户选择。申请说明选填，不添加素材类型、制作要求、参考说明或额外收费字段。
2. 选择项目时，若项目确实改变，清除书籍／剧名称及原ID并提示重新填写；已选剪辑手保留。若不匹配，就近显示已确认文案，不替用户自动更换剪辑手。
3. 未选剪辑手时，已知不支持当前项目的剪辑手仍可看身份及禁选原因，不能选中；不能把已有剪辑手切项目的冲突等同于自动清空剪辑手。
4. 书籍／剧搜索仅复用现有可检索信息，不承诺完整合作商书单。无结果可手填名称及已知信息；没有ID也可提交，不增加强制匹配验证。网络失败与搜索无结果分开显示。
5. 提交时统一检查三必选项及项目—剪辑手权限，历史入口同样校验。表单有错保留所有尚有效输入并定位错误，不以灰色按钮代替错误说明。
6. 相同申请的提交处理进行中暂禁重复点击；一次完成后用户仍可再发起另一份相同内容申请。此防重不构成业务去重限制。重新申请仍重新校验，不沿用旧权限结果。

### 后台列表、详情与配置

列表列顺序：**申请用户昵称／ID、申请书籍名称／ID、剪辑手昵称／ID、申请时间、申请状态、稿件标题／ID、操作（查看详情）**。申请说明只在详情完整展示，不平铺为长表列。未上传的关联稿件为空；书籍手填无ID显示「未提供」。

筛选仅使用PRD已定项：申请用户昵称／ID、剪辑手昵称／ID、申请状态、申请时间范围、稿件ID。状态选项完整覆盖下方11阶段，不添加“处理中”“已完成”等替代枚举。默认申请时间倒序。点击查询才应用条件，回第1页；重置清空条件并提示，按后台规范不自动查询；切换每页条数回第1页。分页提供10／20／50条及首页、上一页、下一页、末页，边界禁用。日期起点不得晚于终点。

详情按以下五组呈现，申请书籍与关联稿件书籍分组标明，避免误认。

| 分组 | 完整只读字段及缺失处理 |
|---|---|
| 申请用户信息 | 右豹昵称、ID |
| 申请信息 | 申请时间、书籍（名称、书籍ID）、约稿剪辑手、申请说明；说明未填显示「未填写」，ID未提供显示「未提供」 |
| 剪辑手信息 | 剪辑手昵称、ID |
| 申请状态 | 当前申请状态；以完整名称显示 |
| 关联稿件信息 | 封面、标题、稿件ID、关键词、项目、书籍（名称、书籍ID）、回填数量、稿件目录、稿件上传时间；代运营合作模式（账号运营、任务协作）；稿件类型（图集、视频、压缩包）；素材类型（图集、混剪、口播、解说）。未上传时整组显示「暂无关联稿件」；回填数量沿用现有稿件字段，0不写成缺失；已删除稿件按现有可读记录显示「已删除」，不提供领取入口 |

后台记录及抽屉只读，不提供通过、拒绝、取消、改派、延期、代领或新增删除按钮。原稿件审核入口不变，不能因约稿记录只读而取消原审核能力。

统计固定五项：约稿总数（已提交申请，含撤销、拒绝、超时等）、约稿完成数（仅已回填）、超时交付数（仅超时未交付）、未按时领取数（仅超时未领取）、未按时回填数（仅超时未回填）。不加按日周月拆分、完成率或超时占比。重复申请是不同申请；驳回后多次上传不增加约稿总数。筛选无结果不应把五项全量总数变成0。

时限配置单独编辑，不在记录行里改某一申请：交付时限默认72小时，用户领取时限默认48小时；两项各为0—999整数，允许0和999，拒绝空值、小数、负数、非整数和超限值，不自动截断或取整。输入旁常驻「0表示不限制」及「配置修改不影响已有申请」。已有申请继续原适用配置，驳回也用该申请原适用交付时限；两项0均不改变领取后24小时回填。

## State Patterns（状态与时限）

### 申请阶段与动作矩阵

下表11个状态名称为唯一阶段枚举。填写表单、上传进度、权限异常、审核已通过但不可领取均为局部交互事实，不增设阶段。后台各阶段均只能「查看详情」。

| 当前阶段 | 用户可用动作／说明 | 剪辑手可用动作／说明 | 计时／出口 |
|---|---|---|---|
| 待审核 | 查看申请、撤销；仍可另发申请 | 查看、通过、拒绝 | 不设响应期限，不开始交付计时 |
| 已撤销 | 查看结果、重新申请 | 只读，不可再承接 | 结束 |
| 已拒绝 | 查看结果、重新申请 | 只读 | 结束；发送拒绝通知 |
| 制作中 | 看制作进度，不可取消，不可领取 | 有权限且在有效窗口可供稿；驳回后可修改原稿再送审 | 接受／每次驳回启动完整交付时限；0不限；上传仍为此阶段 |
| 稿件审核中 | 看送审进度，无领取入口 | 看审核进度，不开新的独立稿件供稿 | 交付倒计时关闭；驳回回制作中；审核通过且实际可领取才进待领取 |
| 超时未交付 | 查看结果、重新申请 | 只读，不得新上传／重试／送审 | 结束；清理已上传未领取稿件；迟到成功不恢复 |
| 待领取 | 查看稿件→既有领取流程 | 看交付结果，不替用户领取 | 实际可领取起默认48小时；0不限；领取成功进待回填 |
| 超时未领取 | 查看结果、重新申请；不可领取已失效稿件 | 只读 | 结束；未领定向稿件失效并删除为已删除 |
| 待回填 | 去回填→既有回填流程；领取不等于完成 | 看当前进度 | 领取成功起24小时；不由领取时限或关键词占用期限替代 |
| 已回填 | 查看完成记录、可重新申请 | 只读 | 完成、结束，不删已领稿件 |
| 超时未回填 | 看超时结果、可重新申请 | 只读 | 结束；沿用既有超时处理，不删已领稿件 |

结束清理只针对关联的**已上传但未领取**定向稿件；拒绝或其他结束状态若实际存在此类稿件也适用，没有稿件不虚构删除记录。已领取稿件不因完成或超时未回填被本规则删除。定向稿件不进C端代发广场，其他用户从任何入口也不能领取。

### 三种时钟与上传等待

时间展示采用当前申请真实适用值及截止时刻；有限时长同时显示绝对截止与可读剩余时间，不只用倒计时数字。下面D为**该轮交付截止时刻**，不是上传发起时刻。

| 情形 | 界面与动作要求 |
|---|---|
| 待审核 | 显示等待审核，可撤销；不出现72小时接单倒计时或自动拒绝 |
| 接受后首次制作 | 采用该申请交付时限，自同意时起；默认72小时。用户不可取消 |
| 交付时限0 | 写「交付时限：不限制」，不显示交付倒计时、D或D+2等待上限，不据此产生超时未交付 |
| D之前或D瞬间发起上传 | 允许发起；显示进度但申请仍制作中。D之后不能再新发起或重试 |
| 到D仍有有效进行中上传 | 保持制作中，写「上传处理中，最晚等待至本轮交付截止后2小时」并展示D+2绝对时刻；停止把原倒计时显示成负数；只允许该次既有上传继续，暂不超时结束或删除 |
| 该上传在D+2及之前成功 | 正常进入稿件审核中，关闭交付时钟，发送上传通知；包括D发起、恰在D+2成功 |
| D之前上传失败／取消 | 仍在有效制作窗口可重试，不虚构成功送审 |
| D之后有效上传失败／取消 | 超时未交付，结束及清理；不得继续重试 |
| 到D+2仍未成功 | 超时未交付；此后成功结果不得恢复申请、送审或发送有效交付通知 |
| D到期无成功送审且无有效上传 | 超时未交付，不提供新上传入口 |
| 上传成功等待官方审核 | 稿件审核中，交付时钟关闭；无审核倒计时，不把审核等待计入交付超时，也不继续受D+2约束 |
| 后台驳回 | 回制作中，展示驳回事实及现有可用驳回说明；从驳回时重新获得申请原适用完整交付时限，默认新的72小时；不是恢复剩余时间。0仍不限，每一有限轮次都重算D及D+2 |
| 审核通过但实际不可领取 | 仍显示当前稿件进度和暂不可领取说明，不另造状态；不开放领取、不启动领取计时、不重新开启交付计时 |
| 审核通过且实际可领取 | 转待领取，自实际可领取起使用申请原适用领取时限，默认48小时；不是上传或通知时间 |
| 领取时限0 | 待领取写「领取时限：不限制」，无领取倒计时，不因未领超时结束或删除；领取后仍按24小时回填 |
| 领取成功 | 转待回填，显示既有24小时回填期限，沿用原流程；所选运营模式采用领取时分润配置 |

## Interaction Primitives（交互原语）

- 触摸／点击执行明确动作；表单选择返回原上下文。手机Sheet在手机内覆盖，点遮罩或关闭返回表单；关键提交不由点遮罩触发。PC／后台详情右侧overlay，编辑和确认居中，不挤压底层页面。
- 接受确认「返回核对」关闭弹窗，不改变待审核、不启动时限；「确认接受」才校验并执行。确认时申请如已撤销，提示当前状态并刷新，不可继续承接。用户撤销时若已先通过，显示制作中及不可取消；先发生者生效，同一申请只有一次有效变更。
- 审核、撤销、领取、回填、上传送审等处理中限制同次重复操作；最终以当前有效结果更新记录，旧按钮、通知或迟到上传结果不能恢复结束申请。
- 用户撤销与剪辑手拒绝使用既有确认框，取消返回原记录；不引入拒绝原因必填、拒绝后申诉或催单动作。通过后的撤销不显示为可操作按钮；权限禁选项仍显示可读原因。
- 运营模式由剪辑手按上传时配置选择；账号运营／任务协作分润分别使用所选模式在领取时的配置。申请与上传页面不展示“已锁定分润”，既有领取页承担领取时确认。平台收费按原流程向剪辑手收取，不新增约稿费、订金、违约金或退款机制。
- 桌面Esc只关闭最顶层浮层，关闭后焦点回触发项；确认／编辑取消不提交。后台重置和取消分开，重置只清筛选输入，取消关闭编辑不保存。
- 后续Demo规则抽屉仅写当前FR，分前端需求／后台需求；前端及业务流程定位前端规则，管理后台定位后台规则。PC相关规则归前端需求并标明剪辑手角色。流程说明只写「见本页业务流程」，图不放抽屉。
- 后续业务流程使用手写SVG，沿用`.flow-page`、`flow-edges`、`flow-nodes`、`.flow-legend`；一菱形一问题、正交线、失败／驳回回环到对应重做起点顶边、终态重提连新申请入口，清楚区分原稿重送审和新申请。优先单图闭环，图静态不驱动状态，不使用Mermaid。

## Accessibility Floor（可访问性底线）

- 手机交互热区至少44×44px，文字放大200%后可滚动读全；申请说明、完整状态、截止时刻和按钮不能被键盘或安全区遮挡。
- 所有输入有label及必填／选填语义；错误用文字关联输入，提交失败定位首错。剪辑手禁选原因可被焦点和读屏访问，不依赖hover或淡色。
- Sheet、modal、drawer有可读标题及关闭控件；阻断式浮层限制焦点在最顶层，关闭回触发点，不允许Tab落入遮罩后的不可操作内容。
- 状态和时限除颜色外有完整文字。倒计时不用每秒读屏播报；进入新阶段或上传失败使用适度的状态播报。通知定位后把目标记录置于可见区并可聚焦。
- 键盘可查询、翻页、查看详情、确认与取消。表格截断文本提供可聚焦或详情的全文读取途径；触摸不依赖原生title的hover表现。
- 正文对比目标按DESIGN.md执行；关键内容用 `{colors.mobile-ink}`／`{colors.admin-ink}`，不能用浅灰独立表达。继承配色尚未通过本FR真实渲染测量，不宣称WCAG AA已验收；风险见DESIGN.md的UX-02。
- 减少动态效果时取消非必要滑入和闪烁，保留明确静态结果。加载不覆盖整页或令原按钮跳位。

## Key Flows（关键旅程）

以下沿用PRD的示例人名及UJ标题，不构成新增调研结论。

### UJ-1：小林从历史稿件继续约稿

1. 小林在过往已领稿件记录点「约稿」，来源稿件未被领完也不拦截。
2. 申请带入项目、书籍／剧和剪辑手；小林可修改三项，选填说明。
3. 若换项目，书籍／剧清空；若新项目不被原剪辑手支持，原剪辑手保留并出现冲突提示，小林调整后提交。
4. 新记录进入待审核，小林可查看或撤销；审核通过后转制作中，不再提供撤销。
5. **关键时刻：** 小林确认申请已被剪辑手接受，页上明确制作阶段与适用时限，同时知道此后不可取消。

失败路径：必填缺失／项目权限不匹配时在原表单修正；撤销与接受并发时展示先发生的有效结果，不显示双重成功。已撤销／已拒绝可打开新申请重新提交。

### UJ-2：小周主动申请并完成发布

1. 小周从底栏进「约稿」，点「定向约稿」，选择项目、书籍／剧和剪辑手；搜索无结果时手填书名，无ID仍可提交。
2. 收到审核通过通知，点击定位申请；稍后收到上传通知，记录是稿件审核中，只有进度没有领取入口。
3. 后台审核通过且实际可领取时，记录转待领取，小周看到该申请适用的领取截止时间；不限时则显示不限制。
4. 小周从记录点「查看稿件」，在既有详情按现有条件完成领取，使用领取时的分润配置；记录变待回填，开始24小时回填期限。
5. 小周通过原回填流程提交发布信息。
6. **关键时刻：** 记录变「已回填」，小周看到完整闭环，领取本身没有被提前记为完成。

失败路径：点击旧通知时依当前状态显示；尚不可领不放行；超时未领取则记录结束、未领稿件已删除，可重新申请。已领取但超时未回填则记超时未回填，保留已领稿件并沿用既有超时处理。

### UJ-3：剪辑手小陈承接并供稿

1. 小陈进入PC「剪辑供稿－定向约稿」，查看申请用户、项目、书籍／剧及说明，点通过。
2. 弹窗展示核对提醒和项目信息；小陈可返回核对，确认接受后才进入制作中并开始该申请适用交付时限。
3. 小陈使用现有供稿步骤选择当时可用运营模式，面向该申请用户上传单份定向稿件。
4. 上传成功进入稿件审核中，交付时钟关闭；如后台驳回，返回制作中，从驳回时获得完整原适用时限，修改同一原稿再送审。
5. 后台审核通过且用户实际可领取，申请进入待领取。
6. **关键时刻：** 小陈看到原稿成功完成审核并交付给指定申请用户，没有流入代发广场，官方审核等待也没有误算超时。

失败路径：接单前已撤销则不能接受；失去项目权限则阻止上传并联系客服，原时限不暂停。有限轮次D及之前发起的上传可等至D+2；截止后失败／取消或到上限仍未成功，转超时未交付，迟到成功不恢复。交付时限0不适用该超时规则。

### UJ-4：管理人员小王查看记录与配置

1. 小王进入后台约稿记录，查看五项全量统计。
2. 按申请用户、剪辑手、状态、时间范围或稿件ID查询，统计保持全量；列表默认申请时间倒序。
3. 点「查看详情」打开五组只读字段，核对申请书籍与稿件信息，关闭返回原列表上下文。
4. 小王打开「时限配置」，检查交付72小时、领取48小时的适用值，可各自设为0—999整数；阅读0含义及不影响已有申请的说明后保存。
5. **关键时刻：** 小王完成全量记录排查和后续时限配置，已有申请仍使用原适用时限；约稿记录没有变成管理审批工作台。

失败路径：配置非法时在原modal纠错、保存失败保留输入；详情失败局部重试，不把缺失当删除。需要审核稿件时回原稿件审核流程，不能在约稿记录代接单、延期或代领。
