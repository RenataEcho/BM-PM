# FR-wen-005 · 一键代发用户定向约稿； · v4 当前

## 1. Vision（愿景）

用户领取某项目某本书籍／剧的稿件后，可能因其出单收益较高，希望熟悉该内容的剪辑手继续供稿。本增量让用户能够从历史已领稿件发起继续约稿，也能直接在「约稿」页面主动向选定剪辑手申请，不要求来源稿件被领完。

一次申请形成从审核、制作、交付、领取到回填的可查看闭环。定向稿件只供申请用户领取，保留现有运营模式、分润、平台收费、稿件审核、领取与回填规则，避免把约稿另建成一套交易流程。

## 2. Target User（目标用户）

### 2.1 JTBD（待完成的任务）

| 角色 | 所处情境与任务 | 本次获得的能力 |
|---|---|---|
| 申请用户 | 历史已领稿件收益较好，希望继续获得同类内容；或已有明确项目及书籍／剧需求 | 向选定剪辑手申请，查看进展，领取定向稿件并回填 |
| 剪辑手 | 收到面向自己的约稿申请，需要判断是否承接并按时交付 | 在 PC 客户端审核申请、定向供稿、查看处理状态 |
| 后台管理人员 | 需要查看所有用户约稿情况并设定时限 | 查看约稿记录，配置交付时限和用户领取时限；按原流程审核稿件 |

### 2.2 Non-Users（非目标用户）

- 面向全部剪辑手公开发布需求、等待抢单的用户，不在本增量范围内。
- 希望通过约稿记录执行代用户取消、代剪辑手接单等管理操作的人员，不在本增量范围内。

### 2.3 UJ（用户旅程）

以下人名为示例，用于串联需求单已给出的流程，不代表新增用户调研结论。

- **UJ-1：小林从历史稿件继续约稿。** 小林发现已领取的某本书籍稿件收益较好，在过往已领稿件记录列表点击约稿，带入项目、书籍／剧和剪辑手。小林可修改这三项，选填申请说明后提交。待审核时可以撤销；剪辑手通过后，小林查看制作进展并等待交付，不能再取消。
- **UJ-2：小周主动申请并完成发布。** 小周从一键代发底部菜单进入「约稿」，点击「定向约稿」，自行选择项目、书籍／剧与剪辑手并提交。小周收到审核结果及上传提醒，待稿件审核通过且实际可领取后，从申请记录进入稿件详情，按时领取，再于领取后 24 小时内回填发布信息，申请记为「已回填」。
- **UJ-3：剪辑手小陈承接并供稿。** 小陈在 PC 客户端「剪辑供稿－定向约稿」查看申请并选择通过或拒绝。通过后按交付期限制作，上传时自由选择现有运营模式。若失去项目上传权限，小陈需联系客服开启权限后再上传；上传成功后进入「稿件审核中」并关闭交付倒计时；审核驳回则从驳回时重新获得完整交付时限，小陈可修改原稿件后重新送审。审核通过且用户实际可领取后才启动领取计时。
- **UJ-4：管理人员小王查看记录与配置。** 小王在后台查看全部用户约稿记录，了解申请用户、剪辑手、状态、关联稿件及申请信息，并配置交付时限和领取时限。小王不通过约稿记录干预申请，稿件审核仍在原审核流程中执行。

## 3. Glossary（术语表）

| 术语 | 本文定义 |
|---|---|
| 定向约稿 | 申请用户向选定剪辑手申请指定项目、指定书籍／剧稿件的行为 |
| 约稿申请 | 一次提交形成的独立记录；撤销或结束后可再次提交，允许重复申请 |
| 申请用户 | 发起该约稿申请、且有权领取所供定向稿件的用户 |
| 剪辑手 | 接收申请、审核承接并供稿的对象，其项目上传权限约束选择及上传 |
| 项目 | 一键代发已有项目，是书籍／剧选择及剪辑手供稿权限校验的上下文 |
| 书籍／剧 | 用户希望获得稿件的内容对象；支持搜索快捷填入，项目变更后清除原信息并重新填写 |
| 来源稿件 | 从历史已领记录发起申请时，用来带入信息的原稿件 |
| 定向稿件 | 与本次约稿申请关联、仅供申请用户领取、不进入 C 端代发广场的稿件 |
| 稿件审核中 | 剪辑手上传定向稿件成功、等待后台审核的状态；关闭交付倒计时，但用户尚不可领取 |
| 可领取 | 稿件通过后台审核且申请用户实际可以领取；此时启动用户领取计时 |
| 交付时限 | 剪辑手同意后首次启动的上传期限，单位为小时，默认 72 小时；每次后台驳回后按该申请适用的完整时限重新计时，等待审核期间不倒计时；0表示不限制 |
| 用户领取时限 | 从后台审核通过后用户实际可领取时计算的领取期限；单位为小时，默认 48 小时；配置变更不影响已有申请；0表示不限制 |
| 回填期限 | 用户领取稿件后 24 小时内回填发布信息，沿用既有逻辑 |
| 运营模式 | 沿用现有供稿的任务协作、账号运营等模式，上传时由剪辑手选择 |
| 分润配置 | 任务协作和账号运营分别独立配置，采用所选模式在用户领取时的分润配置 |
| 结束状态 | 本次申请不再推进的结果，包括已撤销、已拒绝、超时未交付、超时未领取、超时未回填及已回填（完成状态） |

## 4. Features（功能需求）

### 4.1 用户发起与撤销申请

#### FR-1：双入口与约稿记录页

实现 UJ-1、UJ-2。一键代发模块底部菜单新增「约稿」入口，页面承载用户的约稿记录、领取稿件入口，并提供「定向约稿」按钮；过往已领稿件记录列表增加约稿入口。

**Consequences（可验收结果）：**

- 从历史已领记录点击约稿可进入申请，带入来源稿件的项目、书籍／剧及剪辑手，三项均可修改。
- 从「约稿」页面点击「定向约稿」可主动申请，由用户选择三项信息，不依赖历史来源稿件。
- 来源稿件尚未被领完时，用户仍可发起约稿。
- 用户可在「约稿」页面查看自己的申请记录；稿件实际可领取时，可由记录进入所供稿件详情并按现有流程领取。

#### FR-2：申请内容与项目权限校验

实现 UJ-1、UJ-2。申请包含项目、书籍／剧、剪辑手，以及非必填的「申请说明」。

**Consequences（可验收结果）：**

- 不填写申请说明仍可提交；不新增素材类型、制作要求、参考说明字段。
- 未选剪辑手且已选项目时，不支持当前项目的剪辑手禁止选择。
- 已选剪辑手后改选其未获授权项目，保留已选剪辑手，并提示「该剪辑手不做此项目稿件」。
- 项目与已选剪辑手不匹配时，禁止提交，提示「该剪辑手不支持当前项目稿件，请修改后重新提交」。
- 历史信息带入后如存在项目与剪辑手不匹配，同样执行上述校验，不因来源是历史稿件而豁免。
- 项目、书籍／剧、剪辑手均为提交必选项，任一缺失时拦截提交，提示「请填写完整后再提交申请」。
- 项目变更后，清除已填写的书籍／剧信息，用户须重新填入，不保留原项目的书籍／剧内容。
- 书籍／剧填写支持搜索快捷填入信息，复用平台现有可检索信息，不要求取得完整合作商书单；搜索无结果时允许手工填写。暂不强制校验合作商书单及书籍／剧与项目的匹配关系，项目与剪辑手权限校验不变。
- 手工填写保留用户输入，无法取得书籍ID时显示「未提供」，不得虚构ID或因缺少搜索结果、书籍ID拦截提交。

#### FR-3：待审核撤销及重复申请

实现 UJ-1、UJ-2。提交后进入待审核，不设置剪辑手响应期限，用户可在此阶段撤销。

**Consequences（可验收结果）：**

- 待审核申请不会因等待超过交付时限而自动结束；交付时限仅从剪辑手同意时开始。
- 用户撤销待审核申请后，本次申请结束。
- 剪辑手通过后，用户不可取消；页面操作与实际处理结果均不得允许取消通过后的申请。
- 撤销或结束后允许重新申请；允许重复申请，不增加“一组项目、书籍／剧、剪辑手只能申请一次”的业务限制。
- 撤销与审核通过以先发生者为准，只产生一次有效状态变更；最终通过则不可撤销，最终撤销则不可继续承接。

### 4.2 剪辑手审核、制作与定向交付

#### FR-4：PC 客户端审核申请

实现 UJ-3。PC 客户端「剪辑供稿」新增「定向约稿」模块，剪辑手查看并处理面向自己的申请。

**Consequences（可验收结果）：**

- 剪辑手可以对待审核申请选择通过或拒绝，不能继续处理已撤销或其他结束状态的申请。
- 拒绝后本次申请结束；点击通过先二次提醒，确认接受后进入「制作中」，按适用配置启动交付计时。
- 二次确认弹窗标题「确认接受约稿」，正文「请仔细核对本次约稿的项目及书籍／剧信息。书籍／剧信息可能由用户手工填写，平台暂不强制校验，请确认准确后再接受约稿。」同时展示项目、书籍／剧名称及已提供的ID；按钮「返回核对」「确认接受」。返回不改变状态、不启动计时；确认时仍须校验申请未被先行撤销。
- 审核结果通过站内通知提醒申请用户，通知区分通过与拒绝结果。
- 本增量不为待审核申请增加自动接单、自动拒绝或响应超时规则。

#### FR-5：交付计时与超时结束

实现 UJ-1、UJ-3、UJ-4。交付时限后台可配置，单位为小时、仅可输入整数，默认 72 小时（原 3 天等值换算）。从剪辑手同意约稿开始计时；后台修改配置不影响已有申请。

**Consequences（可验收结果）：**

- 没有同意的申请不启动交付计时；同意后使用该申请适用的交付时限开始倒计时；适用时限为 0 时不限制，不显示倒计时、不产生「超时未交付」。
- 配置修改不改变已有申请的时限，后续驳回重计也使用该申请原适用时限。
- 截止时刻前或截止瞬间发起上传均有效；考虑大文件耗时，该次上传在截止后2小时等待上限内成功（含上限瞬间），也正常进入「稿件审核中」。上传过程中仍为「制作中」，不新增阶段。
- 截止前或截止瞬间已发起且仍在进行的有效上传，最多等待至该轮交付截止时间后2小时，等待期间暂不执行超时结束或稿件删除；成功送审后关闭交付倒计时，官方审核等待不计入超时交付。
- 后台驳回时，从驳回时重新获得完整交付时限，默认配置下为新的 72 小时；不恢复上传前剩余时长，也不计入此前审核等待时间。
- 剪辑手可修改同一原稿件后重新送审；再次上传送审后进入「稿件审核中」并关闭倒计时。每次驳回均按上述规则重新计时。
- 首次或驳回后倒计时到期，既未成功送审也没有上述有效进行中的上传，则记为「超时未交付」并结束，有已上传未领取稿件按 FR-8 清理。到期后无有效上传的申请不能再新发起上传。
- 后台审核通过且申请用户实际可领取后转为待领取，启动领取倒计时；审核通过但实际不可领取时不得提前启动领取计时，也不得因官方审核流程耗时重开交付倒计时。
- 有限交付时限下，有效上传在截止后明确失败或取消，即按「超时未交付」结束；截止前失败允许重试，截止后不得新发起或重试上传。
- 有效上传的等待上限为该轮交付截止时间后2小时，不是发起上传后2小时。截止时间为D时，D时刻发起的上传在D+2小时及之前成功均正常流转；到D+2小时仍未成功则记为「超时未交付」，按FR-8清理未领取稿件。此后迟到的上传成功结果不得恢复申请、送审或发送有效交付通知。
- 首次交付和驳回后重新计时的每一轮均适用同样等待上限；上传成功进入「稿件审核中」后不再受该上限约束，官方审核等待不计时。交付时限为0时无交付截止时间，不适用截止后2小时规则，也不据此产生超时结束。

#### FR-6：定向供稿与现有运营规则复用

实现 UJ-3。剪辑手从定向约稿模块针对申请供稿，复用现有供稿、运营模式和分润配置。

**Consequences（可验收结果）：**

- 本轮按一份申请对应一个定向稿件，不支持多稿件交付、补稿、替换稿件。
- 制作期间若失去项目权限，不允许上传该项目稿件；需剪辑手联系客服开启权限后再上传，不自动绕过权限。
- 上传时按当时的运营模式配置由剪辑手自由选择；任务协作与账号运营分润独立配置，不互相混用。
- 用户领取时，使用所选运营模式在领取时的分润配置，不锁定申请时或上传时的分润配置。
- 定向稿件不进入 C 端代发广场流转，不允许其他用户通过广场领取。
- 定向稿件仍须经过管理后台稿件审核，约稿记录只读不取消原有稿件审核能力。
- 上传成功即记为「稿件审核中」并关闭交付倒计时，但不代表用户可以领取；审核通过且实际可领取后再启动领取流程。
- 后台驳回后允许修改原稿件再送审，始终保持同一申请关联同一个稿件；此操作不是增加补稿或替换为另一份稿件，交付重计按 FR-5 执行。

#### FR-7：两类站内通知

实现 UJ-1、UJ-2、UJ-3。本需求新增站内通知仅覆盖剪辑手审核结果、剪辑手已上传稿件两个场景。

**Consequences（可验收结果）：**

- 剪辑手通过或拒绝时，申请用户收到对应审核结果通知。
- 剪辑手已上传稿件时，告知申请用户稿件已上传、正在后台审核，并提醒审核通过且可领取后按时领取；通知不代表已通过审核或已可领取。
- 用户收到上传提醒后，如稿件尚不可领取，不得通过通知绕过审核或领取条件。
- 不在本轮增加短信、推送等渠道，也不额外增加审核通过可领取、超时、催单等新通知场景。
- 本版通知文案：审核通过「你的定向约稿申请已通过，剪辑手将为你制作稿件，请前往约稿页面查看进度。」；拒绝「你的定向约稿申请未通过，你可以前往约稿页面查看记录并重新申请。」；上传「剪辑手已上传你的定向稿件，正在等待后台审核。审核通过且可领取后，请及时领取；如有领取时限，请在截止前领取。可前往约稿页面查看进度。」
- 上传通知不写死 48 小时，以兼容不同适用时限及0表示不限制的申请。
- 两类通知统一跳转「约稿」页面并定位对应记录；已结束记录仍可查看，不自动重新申请；尚不可领取时只展示进度，实际可领取后才提供详情及领取入口，点击通知不直接触发领取。

### 4.3 用户领取、回填与申请结束

#### FR-8：按时领取与未领取稿件清理

实现 UJ-2、UJ-4。用户在交付后按时领取，领取时限由后台以小时配置。领取入口沿用稿件详情及既有领取流程。

**Consequences（可验收结果）：**

- 只有申请用户可领取该定向稿件，领取条件沿用现有流程，不因约稿豁免。
- 用户领取时限默认 48 小时，从管理后台审核通过后用户实际可领取时开始计算；如果审核通过时仍不可领取，须等到实际可领取再计时。
- 后台修改领取时限配置不影响已有申请；每份申请沿用其原适用领取时限。领取时限为 0 时不限制，不显示领取倒计时、不因未领取结束申请或删除稿件；领取后的 24 小时回填规则不变。
- 用户超时未领取，本次申请结束；不能把上传时间、上传通知时间或仍不可领取时的审核通过时间作为起点。
- 申请结束时，关联的已上传但未领取的定向稿件失效并删除，稿件状态改为「已删除」；此规则覆盖拒绝、超时未交付、超时未领取等结束结果中实际存在未领取稿件的情况。
- 稿件已领取后，不适用“申请结束删除未领取稿件”的规则，不因本次清理删除已领取稿件。
- 交付超时结束后，即使后台后续完成审核，也不得恢复该次申请或重新开放该定向稿件领取。

#### FR-9：领取后回填及最终结果

实现 UJ-2。用户已领取后，申请状态变为「待回填」；回填期限为领取稿件后 24 小时，沿用现有逻辑。

**Consequences（可验收结果）：**

- 领取成功后，申请展示「待回填」，不得在仅领取时记为「已回填」。
- 用户在既有期限内回填发布信息后，申请记为「已回填」，流程结束。
- 领取后超时未回填，约稿申请记为「超时未回填」，该状态为结束状态。
- 既有领取与回填超时处理继续沿用；本增量不增加自动豁免或延长期限的规则。
- 用户领取时限、关键词占用期限、领取后 24 小时回填期限是不同规则，不得相互代用。

### 4.4 后台配置、记录与收费边界

#### FR-10：时限配置与只读约稿记录

实现 UJ-4。管理后台新增约稿记录，查看所有用户记录；支持交付时限、用户领取时限配置。

**Consequences（可验收结果）：**

- 约稿记录包含申请用户信息、剪辑手信息、申请状态、关联稿件信息、申请信息五组内容。
- 五组内容的完整字段及列表／详情分工见下表；列表保留重要字段，详细信息可用「查看详情」文字按钮打开右侧抽屉，尤其申请信息无需全部平铺。
- 后台约稿记录仅查看，不提供通过、拒绝、取消、改派、延期、代领等管理操作。
- 交付时限和用户领取时限均以小时为单位配置，仅可输入整数，不支持小数；默认分别为 72 小时、48 小时。两类配置修改均不影响已有申请。
- 两类配置均只可保存 0—999 之间的整数，包含0和999；0表示对应阶段不限制。负数、超过999、小数、空值及其他非整数输入不得保存，提示「请输入0—999之间的整数，0表示不限制」。
- 两类时限独立配置。交付时限为0时，同意后及每次驳回后均不启动交付倒计时；领取时限为0时不启动领取倒计时。两者均不影响领取后24小时回填规则。
- 原稿件审核流程继续提供审核能力，与约稿记录只读分别验收。


| 信息组 | 完整字段 |
|---|---|
| 申请用户信息 | 右豹昵称、ID |
| 申请信息 | 申请时间、书籍（名称、书籍ID）、约稿剪辑手、申请说明 |
| 剪辑手信息 | 剪辑手昵称、ID |
| 申请状态 | 当前申请状态 |
| 关联稿件信息 | 封面、标题、稿件ID、关键词、项目、书籍（名称、书籍ID）、回填数量、稿件目录、稿件上传时间；代运营合作模式（账号运营、任务协作）；稿件类型（图集、视频、压缩包）；素材类型（图集、混剪、口播、解说） |

列表方案：展示申请用户昵称／ID、申请书籍名称／ID、剪辑手昵称／ID、申请时间、申请状态、稿件标题／ID，以及「查看详情」文字按钮。申请说明等长内容放入右侧抽屉，抽屉按上述五组展示完整字段。未上传时关联稿件信息为空；手填且无书籍ID时显示「未提供」；回填数量沿用既有稿件字段，不因一申请一稿件删去。

筛选及排序：支持申请用户昵称／ID、剪辑手昵称／ID、申请状态、申请时间范围及稿件ID查询；默认申请时间倒序。状态选项仅使用第5节完整阶段名称。抽屉只读，五项总数统计保持全量，不随列表筛选变化。

#### FR-11：平台收费保持原流程

覆盖 UJ-2、UJ-3。收费模式由平台设定，平台按剪辑手配置收取，与用户、稿件及本次约稿无关，完全沿用原有流程。

**Consequences（可验收结果）：**

- 不因发起、通过、拒绝、撤销或超时结束约稿申请新增约稿费、订金、违约金或退款规则。
- 不按申请用户或本次定向稿件另设平台收费模式。
- 分润仍按 FR-6 的运营模式及领取时配置执行，不能将平台收费配置与分润配置混为同一规则。

## 5. 状态与时限口径

完整阶段名称为：**待审核、已撤销、已拒绝、制作中、稿件审核中、超时未交付、待领取、超时未领取、待回填、已回填、超时未回填**。「已回填」即完成状态。后台驳回后返回「制作中」，上传过程中也为「制作中」，不新增阶段。已撤销、已拒绝、各超时状态及已回填为结束状态。

| 当前阶段 | 触发条件 | 下一阶段／结果 | 核心约束 |
|---|---|---|---|
| 申请填写 | 校验通过并提交 | 待审核 | 项目、剪辑手须匹配；必选项缺失提示「请填写完整后再提交申请」 |
| 待审核 | 用户撤销 | 已撤销，结束 | 不设响应期限 |
| 待审核 | 剪辑手拒绝 | 已拒绝，结束 | 发送审核结果通知 |
| 待审核 | 剪辑手通过 | 制作中 | 发送审核结果通知，启动交付计时；不可取消 |
| 制作中 | 交付时限为0且上传成功，或截止前／截止瞬间发起且在截止后2小时内（含上限）成功送审 | 稿件审核中 | 允许在等待上限内跨截止时刻完成；发送上传通知并关闭交付倒计时 |
| 稿件审核中 | 等待后台审核 | 稿件审核中 | 官方审核耗时不计入交付倒计时，不因此超时结束 |
| 稿件审核中 | 后台驳回 | 制作中 | 从驳回时重新获得申请适用的完整交付时限；允许原稿修改后再送审 |
| 制作中 | 有限交付时限到期，未成功送审且无有效进行中上传 | 超时未交付，结束 | 有已上传未领取稿件则删除 |
| 制作中 | 有效上传在截止后失败／取消，或到截止后2小时仍未成功 | 超时未交付，结束 | 清理未领取稿件；迟到上传成功不得恢复申请 |
| 稿件审核中 | 审核通过且用户实际可领取 | 待领取 | 从实际可领取时起算，默认 48 小时；0不计时 |
| 待领取 | 有限领取时限到期仍未领取 | 超时未领取，结束 | 稿件失效并删除，状态「已删除」 |
| 待领取 | 用户领取成功 | 待回填 | 按领取时分润配置；开始既有 24 小时回填计时 |
| 待回填 | 按时回填发布信息 | 已回填，结束 | 不删除已领取稿件 |
| 待回填 | 超时未回填 | 超时未回填，结束 | 既有超时处理继续沿用 |

结束后可以重新申请，新申请独立推进，不恢复原申请；重复申请不等于重复处理同一记录。

## 6. 非目标与本轮范围

本轮覆盖第 4 节的用户入口与申请记录、申请填写及权限校验、剪辑手审核及定向供稿、交付与领取时限、回填结果、两类站内通知、后台只读记录、配置及五项总数统计。

- 不建设公开求稿、抢单或向全部剪辑手广播需求的场景。
- 不增加素材类型、制作要求、参考说明等申请字段。
- 不改变现有运营模式、分润配置、平台收费、稿件详情、领取与回填流程；仅增加本需求明确的定向约束及申请状态。
- 不提供剪辑手通过后的用户取消能力，不增加后台约稿记录管理操作。
- 不将定向稿件流转到 C 端代发广场。
- 不支持多稿件交付、补稿、替换稿件；后台驳回后修改同一原稿件重新送审保留。
- 本轮产出为本需求 PRD，设计文档、需求合同、Demo、总览登记及代码实现由后续步骤处理。

## 7. 跨端一致性与验收重点

- 用户侧、剪辑手 PC 客户端和后台应反映同一申请的有效结果，已结束申请不能继续审核、交付或领取。重复点击同一处理操作不得让同一申请产生重复有效结果；撤销与审核通过以先发生者为准，截止瞬间发起上传仍有效，跨截止上传在截止后2小时内（含上限）成功正常流转；到上限未成功或截止后失败／取消则结束，迟到结果不得恢复申请。
- 每份定向稿件的申请归属及申请用户归属须可核对，非申请用户不能从详情或其他入口领取；不新增一套账号登录或权限体系。
- 上传送审、后台审核、实际可领取三个节点应可区分。重点验收等待审核不倒计时、驳回后获得完整交付时限、原稿修改送审再次关闭计时，以及审核通过但实际不可领取时不启动领取计时。
- 结束清理只针对已上传且未领取的定向稿件，重点验收已领取但超时未回填的稿件不会被误删。

## 8. 总数统计

后台本轮只做总数统计，不按日、周、月拆分，不增加完成率或超时占比。本节统计为只读，不改变 FR-10 的管理操作边界。

| 统计项 | 计数口径 |
|---|---|
| 约稿总数 | 已提交的约稿申请总数，含后续撤销、拒绝及其他结果；重复申请作为不同申请分别计数 |
| 约稿完成数 | 最终状态为「已回填」的申请数，领取后未回填不计为完成 |
| 超时交付数 | 最终状态为「超时未交付」的申请数；等待官方审核不计为超时交付 |
| 未按时领取数 | 最终状态为「超时未领取」的申请数 |
| 未按时回填数 | 最终状态为「超时未回填」的申请数 |

**Consequences（可验收结果）：** 每份申请在对应统计项内只计一次；驳回后多次重新送审不增加约稿总数；总数按申请记录统计，不按上传次数或稿件数量统计。五项统计覆盖全部约稿记录，不默认与列表筛选联动。
