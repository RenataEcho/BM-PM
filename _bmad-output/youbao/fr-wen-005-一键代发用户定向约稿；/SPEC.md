# FR-wen-005 · 一键代发用户定向约稿； · 需求合同

本合同与必读附件 [prd.md](prd.md)、[DESIGN.md](DESIGN.md)、[EXPERIENCE.md](EXPERIENCE.md) 共同定义实现与验收范围。PRD 提供完整业务条款、术语及字段；DESIGN 定义视觉与布局；EXPERIENCE 定义页面、动作、状态、异常及精确文案。附件为合同组成部分，不能只读本摘要后省略附件规则。

业务线为「右豹主业务（youbao）」，需求名保留需求单原话及末尾分号。已定 UX 优先于 PRD，再优先于 Demo；旧需求单中的天单位、旧状态称呼及早期产物边界以 PRD v4 和当前 UX 为准。本次只产出需求合同；`status: final` 表示文档已交付，不表示 Demo、生产功能或视觉签核已完成。

## Why（为什么做）

用户希望在历史已领稿件收益较好时继续向剪辑手约稿，也能主动指定项目、书籍／剧和剪辑手。此次在现有一键代发中建立申请、审核、定向供稿、领取及回填闭环，让用户和剪辑手看清进度，让后台查看全量记录及配置时限，同时沿用既有供稿、收费和履约流程。

## Capabilities（能力与验收结果）

- **CAP-1：双入口申请与记录**（PRD FR-1；UJ-1、UJ-2）
  - **intent:** 用户可从历史已领稿件继续约稿，也可主动申请并查看自己的记录。
  - **success:** 历史入口带入项目、书籍／剧、剪辑手且三项可改；主动入口由用户选择，不要求来源稿件被领完。约稿页承载记录、定向约稿入口，并在实际可领取后提供进入既有稿件详情的入口。

- **CAP-2：申请填写与权限校验**（PRD FR-2）
  - **intent:** 用户可提交明确且符合剪辑手项目权限的需求。
  - **success:** 项目、书籍／剧、剪辑手必填，申请说明选填。切项目清除书籍／剧名称及 ID，保留已选剪辑手并提示权限冲突；未选剪辑手时不支持当前项目的对象禁选。历史预填同样校验；缺项或权限不匹配不产生申请。搜索复用现有信息，无结果可手填，无书籍 ID 显示「未提供」且不阻断，不强校验完整合作商书单或书籍与项目匹配。错误文案逐字沿用 EXPERIENCE「已确认校验与接受确认」。

- **CAP-3：待审核撤销与重复申请**（PRD FR-3）
  - **intent:** 用户可在承接前撤销，并可独立发起后续申请。
  - **success:** 待审核无响应期限，可撤销；剪辑手通过后不可取消。撤销与通过以先发生者为准，只生效一次。撤销或结束后可重新申请，允许重复内容的新申请，不恢复旧记录、不施加业务去重限制。

- **CAP-4：剪辑手审核**（PRD FR-4；UJ-3）
  - **intent:** 剪辑手可核对定向申请后决定承接或拒绝。
  - **success:** PC「剪辑供稿－定向约稿」只处理面向自己的待审核申请；通过前展示「确认接受约稿」及附件规定的完整核对正文、项目、书籍／剧名称与已提供 ID。「返回核对」不改状态、不计时；「确认接受」校验最新状态后才进入制作中。拒绝结束申请；已撤销或结束的申请不能承接。

- **CAP-5：交付计时与异常结束**（PRD FR-5）
  - **intent:** 剪辑手可在明确的适用期限内送审，用户可分辨制作、送审及超时结果。
  - **success:** 接受后开始该申请交付计时；成功上传送审进入稿件审核中并关闭计时，官方审核等待不算交付超时。驳回回制作中，自驳回时重新获得原适用完整时限。有限轮次截止时刻 D 及之前可发起上传，有效进行中上传最多等至 D 后 2 小时，含上限瞬间成功；超时结束及例外严格执行下方约束与 EXPERIENCE「三种时钟与上传等待」。

- **CAP-6：单稿定向供稿与运营规则复用**（PRD FR-6）
  - **intent:** 剪辑手可向申请用户交付一份定向稿件，沿用现有供稿和运营模式。
  - **success:** 一申请一稿，后台驳回后仅修改同一原稿件再送审；制作中失去项目权限时禁止上传，需联系客服恢复权限，不自动暂停时限。稿件不流入代发广场。上传时按当时配置选择运营模式，任务协作／账号运营分润独立，按所选模式在用户领取时的配置执行，不提前锁定。

- **CAP-7：站内通知与记录定位**（PRD FR-7）
  - **intent:** 用户可获知审核结果和上传进展，并回到对应记录查看。
  - **success:** 仅剪辑手审核结果、已上传两类触发，正文使用 EXPERIENCE「站内通知：仅两类触发」的三段原文。通知统一进入约稿页定位记录，已结束仍可查看；上传提醒不代表可领取，不写死 48 小时，不直接领取或自动重新申请。

- **CAP-8：领取与未领稿件清理**（PRD FR-8）
  - **intent:** 申请用户可按既有条件领取定向稿件，超时未领稿件停止流转。
  - **success:** 后台审核通过且实际可领取才进入待领取并启动原适用领取时限，仅申请用户可领，原条件不豁免。有限领取时限到期未领记超时未领取。申请结束时，实际存在的已上传但未领取定向稿件失效并删除，稿件状态为「已删除」；已领稿件不适用此清理规则。

- **CAP-9：回填与最终结果**（PRD FR-9；UJ-2）
  - **intent:** 用户可完成发布回填并获得明确的申请结果。
  - **success:** 领取成功仅进入待回填，自领取起按既有 24 小时规则回填；按时回填为已回填（完成），否则为超时未回填并结束。既有超时处理沿用，不因超时未回填删除已领稿件；领取时限、关键词占用期限不得替代回填期限。

- **CAP-10：后台查询、时限配置与全量统计**（PRD FR-10、第 8 节；UJ-4）
  - **intent:** 管理人员可查看全量申请、核对关联信息并设定后续申请的时限。
  - **success:** 列表、筛选、排序及五组只读详情完整实现 EXPERIENCE「后台列表、详情与配置」，行操作仅查看详情；原稿件审核能力保留在原流程。两类时限独立配置，0—999 整数小时，默认交付 72、领取 48；非法值按附件原文拦截。五项统计为约稿总数、约稿完成数、超时交付数、未按时领取数、未按时回填数，全量且不随筛选变化，按申请及对应最终状态计数，不因重送审重复增加。

- **CAP-11：平台收费保持原流程**（PRD FR-11）
  - **intent:** 用户及剪辑手可沿用既有收费机制完成定向约稿。
  - **success:** 平台按剪辑手配置收取费用，与本次申请用户、稿件及约稿无关；申请、通过、拒绝、撤销或超时不新增约稿费、订金、违约金或退款规则。平台收费与运营模式分润分别沿用原口径。

## Constraints（不可变约束）

- 阶段名称仅为：待审核、已撤销、已拒绝、制作中、稿件审核中、超时未交付、待领取、超时未领取、待回填、已回填、超时未回填。上传中仍为制作中，驳回回制作中，审核通过但暂不可领取不增设阶段；完整动作矩阵以 EXPERIENCE「申请阶段与动作矩阵」为准。
- 待审核不计交付时限；同意及每次驳回才启动完整适用交付时限。配置修改不影响已有申请，驳回也不得换用新配置；审核等待不计时，审核通过但不可领取既不启动领取时钟，也不重开交付时钟。
- 有限交付轮次的 D 是该轮交付截止时刻。D 前或 D 瞬间发起的上传可在 D+2 小时及之前成功送审；等待期间不超时结束或删除，D 后不得新发起或重试。D 前失败可重试；D 后有效上传明确失败或取消立即超时未交付；D 到期无有效上传或到 D+2 仍未成功也超时结束。迟到成功不能恢复申请、送审或发送有效交付通知。成功送审后不再受 D+2 上限约束。
- 交付、领取时限为 0 分别表示该阶段不限制，不显示倒计时、不据此超时结束；交付为 0 不适用 D+2，领取为 0 不因未领取删除稿件。两者均不改变领取后的 24 小时回填期限。配置拒绝负数、超 999、小数、空值及其他非整数，不取整或静默截断。
- 三端须反映同一有效结果，同一处理不重复生效；结束申请不得通过旧按钮、旧通知或迟到上传／审核结果恢复。归属校验覆盖详情及其他入口，非申请用户不得领取。后台约稿记录只读不等于取消既有稿件审核。
- 视觉、页面顺序、组件、精确校验与通知文案、空态／加载／错误、权限不可用、焦点与键盘、可访问性及响应式行为均继承两个 UX 附件，不另起配色或控件。移动端、剪辑手 PC、后台、外壳保持各自作用域。
- 后续 Demo 保持三个主 Tab「前端交互／管理后台／业务流程」，前端内切换「用户端／剪辑手PC端」，深链 `?tab=fe|admin|flow`。手机嵌入页内，详情右侧 overlay、编辑居中 modal，底层页面不挤窄；规则抽屉只写本 FR，分前端／后台，流程只指向页内业务流程 Tab；流程图按组件规范手写 SVG，不用 Mermaid。
- 后续 Demo 仅用示例数据模拟操作，不接真实接口、登录、权限或持久化。新增页面按仓库规则另开 `demo/iteration/fr-*.html`，不回改已上线、归档或他人 FR 页；顶部业务线保持右豹主业务，左侧共享「概览／组件规范」。本合同不新增页面、不变更登记及其他需求文件。

## Non-goals（明确不做）

- 不建设公开求稿、抢单、群发需求，不将定向稿件流入 C 端代发广场。
- 不增加素材类型、制作要求、参考说明等申请字段，不增加完整合作商书单接入或强制书籍匹配校验。
- 不支持多稿件、补稿或替换稿件；保留修改同一原稿件后重送审。
- 不提供通过后取消，后台约稿记录不提供通过、拒绝、取消、改派、延期、代领或删除操作。
- 不增加自动接单、自动拒绝、待审核响应超时、申诉、催单、通知渠道或其他通知场景。
- 不增加按日／周／月统计、完成率或超时占比，不改变既有收费、分润、领取、回填或关键词规则。
- 本次不生成 Demo、技术架构、接口设计、开发故事或生产实现，不扩展其他 FR。

## Success signal（成功信号）

- 以 UX 中 UJ-1 至 UJ-4 的四条旅程验收：双入口能申请且校验一致；剪辑手核对承接、定向送审；只有审核通过且实际可领取才开放原领取流程；领取仅为待回填，按时回填后才已回填；后台能查五组详情、修改后续时限、查看不受筛选影响的五项统计。
- 以状态及异常场景逐项验证：撤销／通过竞态只生效一次；驳回完整重计；D 瞬间发起、D+2 瞬间成功有效；截止后失败／取消、上限未成功及迟到成功不复活；两种 0 不限、配置不回改已有申请、非申请人不可领、只清理未领稿件、已领超时未回填不误删；精确文案、当前动作、计时显示和统计均符合附件。Demo 阶段用可点示例及场景模拟验证，不宣称真实服务已上线。
