## 2026-11-18 v2 复验与限制

本轮使用19889端口，保留既有批注副本机制；手机已回填卡片可复制到同文档，退出副本能恢复原交互与业务状态。本轮用户已成功发送16条批注，但这不能证明所有嵌套场景稳定。

控制台在页面初始化仍记录 `MutationObserver.observe` 参数非 Node 的异常，没有来源URL或调用堆栈。当前 FR 业务脚本无 MutationObserver 调用，仅有已绑定存在节点的 ResizeObserver。以上证据只能排除本 FR 直接调用 MutationObserver，不能定位到某一客户端注入脚本，也不能证明异常就是批注不可用的唯一根因。此前「客户端注入」描述应按此证据限制理解。

可复现的结构风险是总览 iframe → FR 页 → 手机 iframe 的多层嵌套与移动端动态渲染／缩放。当前批注视图将手机画面复制到FR页，减少一层 iframe，仍不能消除总览外层嵌套。直接FR页与批注视图是已保留的兼容路径，不是客户端根治补丁。

防回归：移动端切场景后重新生成批注副本；加载／处理中禁止生成；返回交互恢复原 iframe，不让副本发起操作；mockups 同步，外壳、iframe及脚本资源统一使用 scope-v2 缓存版本。后续若复现须记录页面地址、嵌套层级、发生时间和带堆栈的错误，再定位客户端问题，不能只反复改业务页面。
