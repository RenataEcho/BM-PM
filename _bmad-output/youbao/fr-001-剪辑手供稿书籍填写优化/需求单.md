# 需求单

编号：FR-001

业务线：右豹主业务

需求名：剪辑手供稿书籍填写优化

照着哪条现有需求做：无（本仓尚无对应 FR；增量落在已有右豹 PC 端代发剪辑手「剪辑供稿 / 上传稿件」第二步）

谁在用：代发剪辑手（PC 端）

从哪个入口进来：右豹 PC 端剪辑手剪辑供稿，上传稿件第二步「填写并选成片流程」

接着怎么点：

1. 进入上传稿件，走到第二步填写并选成片流程。
2. 在书籍名称输入时，系统对数据库书名做模糊检索；剪辑手可点击结果快速选书。
3. 点选联想结果时只补空：自动填入当前仍为空的书籍 ID、书籍链接（以及书籍类型，若当时为空）；已有内容不覆盖。选中后书籍名称、ID、链接不与库强绑定，剪辑手仍可改。
4. 书籍名称、书籍 ID 都支持模糊搜索；选中搜索结果后，只填充当时未填写的书籍名称、书籍 ID、书籍类型、书籍链接；已有内容不覆盖。
5. 项目系由第一步所选项目映射（见补充口径）。点下一步才校验：无异常直接进第三步；有异常才弹窗。字节系、知乎系可「继续提交」进入第三步；海外短剧、海外小说只能「关闭」，留在第二步。其他项目无书库，不校验。
6. 字节系、知乎系不拦截的原因：书库不全，允许剪辑手仍填写并继续。第三步最终提交本增量不拦截。

后台要看什么：

- 表：
  - 字节系：`yx_fanqie_book_lists`（校验剪辑手填写的书籍 ID）
  - 知乎系：`novel_sections`（校验剪辑手填写的书籍链接）
  - 海外小说/短剧：现有任务库 `yx_story_task` 的 `book_id`（校验书籍 ID）
- 字段：书籍名称、书籍 ID、书籍类型、书籍链接（C 端填写与补空涉及）；校验对照字段以各表为准（字节系书籍 ID，知乎系书籍链接，海外 `yx_story_task.book_id`）

哪些情况不允许：

- 海外短剧、海外小说：点第二步「下一步」时未百分百匹配，不允许进入第三步。第三步最终提交本增量不拦截。
- 字节系、知乎系：未百分百匹配仍允许点弹窗「继续提交」进入第三步。
- 其他项目：本增量不做书籍校验，也不因书籍字段拦截。

这次不做的：

- 不接真实登录、权限和持久化（Demo 约定）。
- 不改已上线、已归档或别人名下的 FR 页面。
- 不把书籍名称 / ID / 链接做成与库记录强绑定（选完仍可改）。
- 点选或搜索回填时不覆盖已填写内容。

还没定的：

- [ASSUMPTION] 百分百匹配是否去掉首尾空格：PRD 暂按不去。
- [ASSUMPTION] 书库查询失败时海外是否拦截：PRD 暂按不因故障拦截。
- [ASSUMPTION] 书籍类型点选后是否允许手改：PRD 暂按允许。

## 提需原话

加一下代发剪辑手侧后续需求:可以填写校验也可以模糊搜索

字节系:用 yx_fanqie_book_lists 这个表校验一下剪辑手填写的书籍 ID 是否正确

知乎系:用 novel_sections 这个表校验一下剪辑手填写的书籍链接是否正确

海外小说/短剧:用现在的任务库 yx_story_task 的 book_id 校验一下

1 和 2 校验是否正确但不限制不能填写,原因:我们的书库也不全。

## 补充口径（本次已确认）

- 需求名改为：剪辑手供稿书籍填写优化。
- 点选联想时只补空，不覆盖已填。
- 上传稿件第二步：书名模糊检索可选书；书名与书籍 ID 均可模糊搜索并补空（名称、ID、类型、链接）。
- 字段不与库强关联，剪辑手可改名称、ID、链接。
- 项目系按第一步项目映射：知乎系（盐言聚星拉活、知乎故事、知乎社区）；字节系（番茄小说、番茄畅听、红果短剧APP、PikPak）；海外短剧；海外小说；其他项目暂无书库、不做校验。
- 正确 = 书籍名称/ID 为主的字段与数据表百分百匹配。
- 检索触发由实现择优；单平台上千条；结果最多 20 条；无结果提示「暂无结果」。
- 书籍类型与书籍名称、书籍 ID、书籍链接在同一张表。
- 校验只在第二步点「下一步」后：无异常直接进第三步；有异常才弹窗。字节系文案「书籍ID与书籍不匹配，确认要继续提交吗？」；知乎系文案「书籍链接与书籍名称不匹配，确认要继续提交吗？」；按钮「取消」「继续提交」。海外短剧/小说文案「书籍ID与书籍名称不匹配，请填写正确后再提交！」；按钮「关闭」。
- 只在第二步「下一步」拦截；第三步最终提交不拦截。
