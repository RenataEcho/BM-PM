# PRD: 剪辑手供稿书籍填写优化

## 0. Document Purpose

本文只覆盖全局迭代 **FR-001「剪辑手供稿书籍填写优化」**，业务线为右豹主业务（`youbao`）。读者是本仓产品、UX 与研发：用它约束后续 `DESIGN.md`、`EXPERIENCE.md`、`SPEC.md` 与 Demo，不描述别的迭代。

正文里的 **FR-1、FR-2…** 只表示本增量第 n 条能力，不是全局编号。全局号写在 front matter 的 `iteration_id: FR-001`。

结构：词汇以 Glossary 为准；能力按功能分组，每条带可验收 Consequences；未确认口径在正文标 `[ASSUMPTION]`，并在第 9 节汇总。

本仓尚无对应已有 FR 页可改。增量落在已有右豹 PC 端代发剪辑手「剪辑供稿 / 上传稿件」第二步「填写并选成片流程」。项目系由**第一步已选项目**映射，本增量不改第一步选项目交互。尚无本需求的 `DESIGN.md`、`EXPERIENCE.md` 与 Demo 文件名。Demo 落地后，在 Purpose 补写 `demo/iteration/fr-*.html` 文件名。

输入：同目录 `需求单.md`（含提需原话与已确认补充口径）。不要把其他迭代的 PRD 并进本文。

## 1. Vision

代发剪辑手在 PC 端上传稿件时，第二步要填书籍信息。今天主要靠手敲。书库里其实有书，但检索和回填不顺；填错了，不同项目系该拦的没拦住、不该拦死的又可能卡住——字节系和知乎系书库本来就不全。

本增量做两件事：让剪辑手用书籍名称、书籍 ID 在书库里模糊检索并点选；点选后，当前触发检索的字段按点选内容覆盖，其他书籍字段只给空着的字段补值，选完仍可改。点「下一步」时按第一步所选项目映射项目系，对照书库做百分百匹配：字节系、知乎系不匹配则弹窗确认，选「继续提交」仍进入第三步；海外短剧、海外小说不匹配则弹窗后留在第二步，不能进第三步。其他暂无书库的项目不做校验。第三步的最终提交，本增量不拦截。

价值是少来回翻书、少把海外任务的错书籍带到第三步，同时不因为不完整的国内书库把稿件卡死。

## 2. Target User

### 2.1 Jobs To Be Done

- **功能：** 在上传稿件第二步尽快对准一本书，把空着的书籍字段填对，再点下一步进入第三步。
- **功能：** 点下一步时知道当前填写相对书库是否百分百匹配；字节系 / 知乎系即使不匹配也要能进入第三步。
- **情境：** PC 端连着处理多条供稿，一手资料和系统字段经常只齐一部分；第一步已经选好了项目。
- **情绪：** 不想被不完整书库误拦，也不想海外任务带着错的书籍 ID 进入第三步。

### 2.2 Non-Users (v1)

- 导师、企业号运营、管理后台配置人员：本增量不改他们的工作台。
- 不走「剪辑供稿 / 上传稿件」第二步的其他右豹角色。
- 需要把字段锁死在书库记录上、不许改的流程：v1 明确不做强绑定。

### 2.3 Key User Journeys

内部单角色，旅程从轻。主角是代发剪辑手「周然」，在右豹 PC 端做剪辑供稿。

- **UJ-1. 周然靠书籍名称点到库里的书，空字段被补上。**
  - **Persona + context：** 周然手里有书籍名称，书籍 ID 和书籍链接还空着。
  - **Entry state：** 第一步已选有书库的项目；已进入上传稿件第二步「填写并选成片流程」。
  - **Path：** 在书籍名称输入；系统对对应书库做模糊检索，列表最多 20 条；点一条结果。
  - **Climax：** 空着的书籍 ID、书籍链接、书籍类型被补上；他看见字段有值，仍能改。
  - **Resolution：** 继续本步其余填写。Realizes FR-1, FR-3, FR-4.

- **UJ-2. 周然已经填了一部分，再用书籍 ID 搜，已填内容还在。**
  - **Persona + context：** 他先手填了书籍名称，再拿书籍 ID 去搜。
  - **Entry state：** 同上，书籍名称已有内容。
  - **Path：** 在书籍 ID 做模糊检索，点选一条。
  - **Climax：** 当前用来检索的书籍 ID 按点选结果覆盖；其他字段只填充当时仍空的字段。
  - **Resolution：** 书籍字段仍可手改。Realizes FR-2, FR-3, FR-4.

- **UJ-3. 字节系任务对不上书库，周然确认后仍进入第三步。**
  - **Persona + context：** 书库对不上，但稿件必须往下走。第一步选的是字节系项目（如番茄小说）。
  - **Path：** 点下一步；系统对照 `yx_fanqie_book_lists` 发现不是百分百匹配；弹出「书籍ID与书籍不匹配，确认要继续提交吗？」
  - **Climax：** 点「继续提交」进入第三步；点「取消」留在第二步。Realizes FR-6, FR-9。知乎系文案与对照字段不同，确认路径同构（FR-7）。

- **UJ-4. 海外任务书籍对不上，周然被留在第二步。**
  - **Persona + context：** 第一步选了海外短剧或海外小说。
  - **Path：** 点下一步；弹出「书籍ID与书籍名称不匹配，请填写正确后再提交！」只有「关闭」。
  - **Climax：** 关闭后仍在第二步，不能进入第三步。第三步若已进入，本增量不在最终提交上再拦。Realizes FR-8, FR-9。

- **UJ-5. 无书库项目，点下一步不弹书籍校验。**
  - **Persona + context：** 第一步选了未列入知乎系、字节系、海外短剧、海外小说的其他项目。
  - **Climax：** 点下一步，无本增量的书籍校验弹窗，直接进入第三步（仍受该步原有其他校验约束）。Realizes FR-5。

## 3. Glossary

后文只用这些词，不另起同义说法。

- **代发剪辑手** — 本增量唯一操作者；在右豹 PC 端做剪辑供稿。
- **剪辑供稿** — 代发剪辑手上传并填写稿件的工作入口。
- **上传稿件** — 剪辑供稿里的上传流程，至少分三步：第一步选项目，第二步填写并选成片流程，第三步最终提交。
- **项目** — 第一步选择的具体业务项目。本增量用它映射项目系，不改第一步交互。
- **填写并选成片流程** — 上传稿件第二步；本增量的检索、补空、校验弹窗只发生在这一步。
- **第三步** — 填写并选成片流程之后的那一步，是本条上传稿件的最终提交所在；本增量不在第三步拦截。
- **书籍名称** — 第二步书籍字段之一；可输入、可模糊检索、可被补空；参与百分百匹配。
- **书籍 ID** — 第二步书籍字段之一；可输入、可模糊检索、可被补空；参与百分百匹配。
- **书籍类型** — 第二步书籍字段之一；与书籍名称、书籍 ID、书籍链接在同一张书库表；点选检索结果时若当时为空则可被补空。
- **书籍链接** — 第二步书籍字段之一；可输入、可被补空；知乎系百分百匹配的对照字段之一。
- **书籍字段** — 书籍名称、书籍 ID、书籍类型、书籍链接的统称。
- **项目系** — 由第一步所选项目映射出的校验分组，取值只能是：知乎系、字节系、海外短剧、海外小说、其他项目。
- **知乎系** — 项目为盐言聚星拉活、知乎故事、知乎社区之一。书库表 `novel_sections`。
- **字节系** — 项目为番茄小说、番茄畅听、红果短剧APP、PikPak 之一。书库表 `yx_fanqie_book_lists`。
- **海外短剧** — 第一步所选项目为海外短剧。书库用现有任务库 `yx_story_task` 的 `book_id`。
- **海外小说** — 第一步所选项目为海外小说。书库用现有任务库 `yx_story_task` 的 `book_id`。
- **其他项目** — 未列入知乎系、字节系、海外短剧、海外小说的项目；暂无书库，本增量不做校验。
- **书库** — 用于模糊检索与校验的对照数据；按项目系落到不同表，不是一张统一库。单平台书籍数据上千条量级。
- **模糊检索** — 按代发剪辑手当前输入，在对应书库里找候选供点选。书籍名称、书籍 ID 都要支持。触发时机由实现择优。
- **补空** — 点选检索结果后，当前触发检索的字段用点选值覆盖；其他书籍字段只写入当时仍为空的字段，已有内容不覆盖。
- **强绑定** — 点选后把字段锁到书库记录、禁止改。本增量不做。
- **百分百匹配** — 以书籍名称、书籍 ID 为主（知乎系同时对照书籍链接）的填写值，与对应书库同一行记录的对应字段字符串完全一致。比较前去掉首尾空格；仍不忽略 query、尾斜杠、http/https，不做大小写折叠。
- **校验正确** — 达到百分百匹配。
- **异常** — 点下一步时未达到百分百匹配。无异常则不弹窗、直接进入第三步。
- **提示不拦截** — 出现异常时弹窗，代发剪辑手可取消留在第二步，或点「继续提交」进入第三步。用于字节系、知乎系。
- **拦截** — 出现异常时弹窗，只能关闭并留在第二步，不能进入第三步。用于海外短剧、海外小说。不作用于第三步的最终提交。
- **下一步** — 第二步填写并选成片流程上，进入第三步的按钮。本增量的校验与拦截只挂在这里。
- **继续提交** — 字节系、知乎系异常弹窗上的按钮文案；行为是进入第三步，不是第三步上的最终提交。
- **取消** — 字节系、知乎系异常弹窗上的按钮；关闭弹窗，留在第二步。
- **关闭** — 海外短剧、海外小说异常弹窗上的唯一按钮；关闭弹窗，留在第二步。
- **暂无结果** — 模糊检索无候选时的提示文案。

## 4. Features

### 4.1 书籍字段模糊检索与补空

**Description:** 代发剪辑手在填写并选成片流程中，对书籍名称、书籍 ID 做模糊检索；点选后当前检索字段按候选覆盖，其他字段按补空写入，且不与书库强绑定。检索范围是第一步项目所映射书库。Realizes UJ-1, UJ-2.

**Functional Requirements:**

#### FR-1: 书籍名称模糊检索

代发剪辑手可以在书籍名称输入时，对对应书库做模糊检索并点选候选。Realizes UJ-1.

**Consequences (testable):**

- 在填写并选成片流程中，书籍名称可触发针对当前项目系书库的模糊检索。
- 有匹配时展示可点击候选，最多 20 条。
- 无匹配时提示「暂无结果」，不展示假数据行。
- 点选后进入 FR-3 的补空，而不是整表覆盖。
- 触发时机（逐字 / 防抖 / 回车等）由实现按上千条量级择优，产品不规定某一种。Demo 只要能输入后看到候选或「暂无结果」。

#### FR-2: 书籍 ID 模糊检索

代发剪辑手可以对书籍 ID 做模糊检索并点选候选。Realizes UJ-2.

**Consequences (testable):**

- 书籍 ID 与书籍名称一样支持模糊检索和点选。
- 结果条数上限、无结果文案与 FR-1 相同：最多 20 条；无则「暂无结果」。
- 从书籍 ID 点选与从书籍名称点选，补空规则同为 FR-3。

#### FR-3: 点选只补空

点选检索结果时，当前触发检索的字段按候选值覆盖；其他书籍字段只填充当时未填写的值。四个字段来自同一张书库表。Realizes UJ-1, UJ-2.

**Consequences (testable):**

- 当前触发检索的字段（书籍名称或书籍 ID）→ 直接覆盖为点选候选对应字段值，即使触发检索前输入了部分内容。
- 其他书籍字段在点选瞬间已有内容 → 保持原值。
- 其他书籍字段在点选瞬间为空，且候选带该值 → 写入候选值。
- 不得用候选整行覆盖所有已有书籍字段。
- 书籍类型与书籍名称、书籍 ID、书籍链接从同一行补出，不从另一张表拼类型。

#### FR-4: 选后可改、不强绑定

点选后，书籍名称、书籍 ID、书籍链接不与书库记录强绑定，代发剪辑手仍可改。Realizes UJ-1, UJ-2.

**Consequences (testable):**

- 点选之后，书籍名称、书籍 ID、书籍链接仍可编辑。
- 点选之后，书籍类型仍可编辑；手改值不被点选记录回填覆盖，并按当前项目系的校验规则参与下一步判断；若该项目系不校验书籍类型，则不参与百分百匹配。
- 改这些字段不会被强制写回点选时的书库行。
- 改完后的值在点下一步时按第 4.2 节重新校验，不因为曾经点选过就视为永久校验正确。

**Notes:** 书籍类型点选后允许手改，行为与另外三个书籍字段一致。

**Feature-specific NFRs:**

- 单平台书库上千条时，模糊检索返回最多 20 条结果。本 FR 不设置独立检索延迟指标，验收要求输入后能展示候选或「暂无结果」，具体查询优化和防抖策略由实现决定。

### 4.2 按项目系校验

**Description:** 代发剪辑手点击下一步时，系统用第一步项目映射出的项目系，判断填写是否百分百匹配。无异常则直接进入第三步。字节系、知乎系异常则提示不拦截；海外短剧、海外小说异常则拦截在第二步。其他项目不做本增量校验。Realizes UJ-3, UJ-4, UJ-5.

**Functional Requirements:**

#### FR-5: 用第一步项目映射校验源

系统按第一步已选项目映射项目系、书库表和是否校验。

**Consequences (testable):**

| 第一步项目 | 项目系 | 书库 | 本增量是否校验 |
|---|---|---|---|
| 盐言聚星拉活、知乎故事、知乎社区 | 知乎系 | `novel_sections` | 是 |
| 番茄小说、番茄畅听、红果短剧APP、PikPak | 字节系 | `yx_fanqie_book_lists` | 是 |
| 海外短剧 | 海外短剧 | `yx_story_task.book_id` | 是 |
| 海外小说 | 海外小说 | `yx_story_task.book_id` | 是 |
| 上表未列出的项目 | 其他项目 | 无 | 否 |

- 不得用错表做该项目系的百分百匹配。
- 其他项目：点下一步不因书籍字段弹出本增量校验窗，也不因书籍字段拦截。
- 本增量不提供第一步改选项目的新交互；Demo 可用场景切换代表不同第一步项目。

**百分百匹配判定：**

- 字节系：以 `yx_fanqie_book_lists` 同一行的书籍 ID 与填写值做字符串完全一致比较；名称、类型、链接只用于检索和补空。
- 知乎系：以 `novel_sections` 同一行的书籍链接与填写值做字符串完全一致比较；名称用于异常文案语义，ID、类型用于检索和补空。
- 海外短剧、海外小说：以 `yx_story_task` 的 `book_id` 与填写的书籍 ID 做字符串完全一致比较；名称用于异常文案语义。
- 参与判定的字段为空，或查不到包含该字段的对应记录时，均视为未百分百匹配；不得把空值当作匹配成功。
- 校验字段和用于补空的书籍字段必须来自同一条书库记录，不得跨行拼接后判定匹配。

#### FR-6: 字节系提示不拦截

字节系出现异常时弹窗确认，不强制留在第二步。Realizes UJ-3.

**Consequences (testable):**

- 点下一步且未百分百匹配 → 弹窗文案原文：「书籍ID与书籍不匹配，确认要继续提交吗？」
- 操作按钮只有「取消」「继续提交」。
- 「取消」：关闭弹窗，留在第二步。
- 「继续提交」：进入第三步。
- 不得把字节系异常做成只能关闭、不能进入第三步。

#### FR-7: 知乎系提示不拦截

知乎系出现异常时弹窗确认，不强制留在第二步。

**Consequences (testable):**

- 点下一步且未百分百匹配 → 弹窗文案原文：「书籍链接与书籍名称不匹配，确认要继续提交吗？」
- 操作按钮只有「取消」「继续提交」。
- 「取消」：关闭弹窗，留在第二步。
- 「继续提交」：进入第三步。
- 不得把知乎系异常做成只能关闭、不能进入第三步。

#### FR-8: 海外短剧、海外小说拦截在第二步下一步

海外短剧或海外小说出现异常时，不允许进入第三步。第三步最终提交本增量不拦截。Realizes UJ-4.

**Consequences (testable):**

- 点下一步且未百分百匹配 → 弹窗文案原文：「书籍ID与书籍名称不匹配，请填写正确后再提交！」
- 操作按钮只有「关闭」。
- 「关闭」：关闭弹窗，留在第二步，不能进入第三步。
- 改为百分百匹配后再点下一步：无异常，直接进入第三步。
- 不得在第三步最终提交上再做本增量的书籍拦截。
- 海外短剧与海外小说文案、按钮、拦截点相同，仅第一步项目不同。

#### FR-9: 只在点击下一步时校验

校验只在第二步点击下一步之后发生。无异常直接进入第三步，有异常才弹窗。

**Consequences (testable):**

- 输入过程、失焦、点选检索结果：不因本增量弹出校验窗。
- 点下一步且校验正确：无弹窗，进入第三步。
- 点下一步且异常：先弹窗，不直接进入第三步；是否进入第三步由 FR-6 / FR-7 / FR-8 的按钮决定。
- 其他项目：点下一步不走本增量异常弹窗（FR-5）。
- Demo 不接真实接口；用示例书库表现百分百匹配与异常。弹窗文案用本节原文，不用 `[待确认]`。

**Feature-specific NFRs:**

- 产品实现应对书库查询失败与「未百分百匹配」可区分，避免把基础设施故障显示成代发剪辑手填错。故障时：字节系/知乎系仍可走提示不拦截；海外短剧/海外小说不因查库失败拦截，界面标明系统异常而非填写错误。
- 查库失败时不等于未百分百匹配：保留第二步已填写内容并单独显示系统异常；海外不因查库失败拦截。本 FR 不定义自动重试次数或新增重试按钮，用户关闭异常提示后留在第二步。

### 4.3 后台对照（研发与 Demo 可读）

**Description:** 本增量没有新的运营配置台。后台要能对照需求单给出的表和字段，供研发验收与 Demo「管理后台」页展示校验用数据，而不是让运营改规则。

#### FR-10: 校验对照表可读

研发和 Demo 后台能按项目系看到用于校验的表、字段与示例行。

**Consequences (testable):**

- 同一张书库表示例行同时能看到书籍名称、书籍 ID、书籍类型、书籍链接（海外以该表实际有的字段为准，至少含用于百分百匹配的书籍名称与书籍 ID）。
- 本增量不要求运营在后台增删改这些表。

## 5. Non-Goals (Explicit)

- 不接真实登录、权限和持久化（Demo 约定）。
- 不改已上线、已归档或别人名下的 FR 页面；本增量另开 Demo 页。
- 不改第一步选择项目的交互，只消费其结果。
- 不在第三步最终提交上做本增量的书籍拦截。
- 不做书籍名称 / 书籍 ID / 书籍链接与书库记录的强绑定。
- 点选或搜索回填时不覆盖当前检索字段之外的已填写内容；当前检索字段按点选结果覆盖。
- 不把导师商务、企业号或剪辑供稿其他步骤并进本 PRD。
- 不在本增量重做成片流程选择、上传文件本身、任务创建。
- 不把书库表做成运营可配置的规则引擎。
- 不为其他项目补书库。

## 6. MVP Scope

### 6.1 In Scope

- 填写并选成片流程：书籍名称、书籍 ID 模糊检索（最多 20 条，无结果「暂无结果」）；点选补空；选后可改。
- 按第一步项目映射项目系；百分百匹配；下一步时弹窗。
- 字节系、知乎系提示不拦截；海外短剧、海外小说拦截在第二步下一步；其他项目不校验。
- Demo 用示例数据表现检索、补空、弹窗、拦截；后台页只读对照表。

### 6.2 Out of Scope for MVP

- 真实接口、登录、权限、写库。
- 书库补全（正是字节系/知乎系不拦截的原因）。
- 将书籍类型做成独立检索入口（只作为补空字段）。
- 第三步最终提交的书籍拦截。
- 移动端适配：入口是右豹 PC 端。

## 7. Success Metrics

内部工具增量，没有对外发布指标。下列成功指标仅作为内部验收口径，不是增长实验。

**Primary**

- **SM-1：** 在覆盖海外短剧、海外小说各至少 1 个正确匹配和 1 个未匹配场景的内部回归验收中，未百分百匹配时 0 次从第二步下一步进入第三步。Validates FR-8.
- **SM-2：** 在覆盖字节系、知乎系各至少 1 个异常场景的回归验收中，点「继续提交」后均可进入第三步。Validates FR-6, FR-7.

**Secondary**

- **SM-3：** 点选检索结果后，已填写书籍字段保持不变（补空回归用例通过）。Validates FR-3.
- **SM-4：** 其他项目点下一步 0 次弹出本增量书籍校验窗。Validates FR-5.

**Counter-metrics (do not optimize)**

- **SM-C1：** 不要为了「一次填全」去覆盖当前检索字段之外的已填字段或把字段强绑定到书库。Counterbalances SM-3.
- **SM-C2：** 不要为了降低海外错填而把提示不拦截升级成字节系/知乎系拦截。Counterbalances SM-2.
- **SM-C3：** 不要把第二步的拦截复用到第三步最终提交。Counterbalances SM-1.
