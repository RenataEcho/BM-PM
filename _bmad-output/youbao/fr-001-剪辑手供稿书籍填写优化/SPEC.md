# FR-001 · 剪辑手供稿书籍填写优化

本文件与 companions 共同构成实现、测试和验收合同；PRD 的词汇、项目映射和详细规则、DESIGN 的视觉、EXPERIENCE 的状态与交互均须读取。已定 DESIGN / EXPERIENCE 优先于 PRD；下述待确认项仍按暂定口径执行，不视为已确认。

## Why · 为什么做

右豹 PC 端代发剪辑手在「剪辑供稿 / 上传稿件」第二步「填写并选成片流程」需要快速找到书籍并补齐信息。通过检索与补空减少手填；在进入第三步前阻断海外错填，同时允许字节系、知乎系在书库不完整时确认后继续。

## Capabilities · 能力与验收

- **CAP-1 · 按书籍名称检索**（PRD FR-1）
  - **intent:** 代发剪辑手能按书籍名称在当前项目系书库模糊检索并选择候选。
  - **success:** 输入后展示至多 20 条可点选候选；无命中显示「暂无结果」，不显示假数据行。
- **CAP-2 · 按书籍 ID 检索**（PRD FR-2）
  - **intent:** 代发剪辑手能按书籍 ID 片段检索并选择候选。
  - **success:** 结果上限、空态及点选补空行为与名称检索一致；查询范围随第一步项目映射。
- **CAP-3 · 点选只补空**（PRD FR-3）
  - **intent:** 代发剪辑手能补齐缺失的书籍字段，同时保留已填写内容。
  - **success:** 以点选瞬间为准，名称、ID、类型、链接仅在为空且候选带值时从同一条记录补入；已有值全部保持原值，包括触发检索时输入的关键词或 ID 片段；随后关闭候选并将焦点返回触发字段。
- **CAP-4 · 选后仍可修改**（PRD FR-4）
  - **intent:** 代发剪辑手能继续调整书籍字段，不被候选记录锁定。
  - **success:** 名称、ID、链接选后可编辑且不自动恢复候选值；再次点下一步按当前值校验，不因曾经选中过而默认正确。类型可编辑沿用下述假设。
- **CAP-5 · 按第一步项目分流**（PRD FR-5）
  - **intent:** 系统能按已选项目采用对应书库及校验策略。
  - **success:** PRD FR-5 项目映射中的知乎系、字节系、海外短剧、海外小说均使用各自对照源；其他项目跳过本 FR 书籍校验与弹窗，仍受原有其他校验约束。
- **CAP-6 · 字节系异常可继续**（PRD FR-6）
  - **intent:** 字节系书籍 ID 未匹配时，代发剪辑手能自行决定是否继续。
  - **success:** 点下一步显示「书籍ID与书籍不匹配，确认要继续提交吗？」；「取消」留第二步且字段不变，「继续提交」进入第三步。
- **CAP-7 · 知乎系异常可继续**（PRD FR-7）
  - **intent:** 知乎系书籍链接未匹配时，代发剪辑手能自行决定是否继续。
  - **success:** 点下一步显示「书籍链接与书籍名称不匹配，确认要继续提交吗？」；「取消」留第二步且字段不变，「继续提交」进入第三步。
- **CAP-8 · 海外异常留在第二步**（PRD FR-8）
  - **intent:** 海外短剧、海外小说未匹配的书籍 ID 不能通过第二步下一步。
  - **success:** 两类项目均显示「书籍ID与书籍名称不匹配，请填写正确后再提交！」；只有「关闭」，关闭后字段不变且留第二步；修正为匹配后再点下一步可进入第三步。
- **CAP-9 · 只在下一步校验**（PRD FR-9）
  - **intent:** 代发剪辑手在完成第二步时获得校验反馈，填写过程不被校验窗打断。
  - **success:** 输入、失焦、点选均不弹校验窗；点下一步无异常直接进入第三步，有异常按 CAP-6～8 处理；查询期间禁重复操作。查库故障显示系统异常并保留内容，不伪装成填写错误；第三步最终提交不执行本 FR 拦截。
- **CAP-10 · 后台对照只读可查**（PRD FR-10）
  - **intent:** 研发和验收者能核对项目系使用的表、字段与示例记录。
  - **success:** Demo 管理后台可区分三类书库，展示名称、ID、类型、链接的示例行；海外按实际字段展示，至少含名称与 ID；不提供运营增删改或规则配置。

## Constraints · 约束

- 项目映射完整清单见 PRD FR-5：知乎系对应盐言聚星拉活、知乎故事、知乎社区；字节系对应番茄小说、番茄畅听、红果短剧APP、PikPak；海外短剧、海外小说分别成系，其余均为其他项目。
- 以 UX 对照字段及 PRD FR-5 具体规则为当前口径：字节系校验 `yx_fanqie_book_lists` 的书籍 ID；知乎系校验 `novel_sections` 的书籍链接；海外两系校验 `yx_story_task.book_id`。名称不额外参与当前判定；书籍类型只在项目规则明确要求时参与，本版未定义此类规则。名称匹配口径差异见待确认项。
- 百分百匹配指对应字段字符串完全一致；不做大小写折叠，不忽略链接 query、尾斜杠或 http/https 差异。不将模糊命中当作校验成功，不跨行拼接记录；四个补空字段来自同一书库记录。
- 单平台上千条书籍，候选最多 20 条；检索触发由实现择优。候选摘要、加载、键盘上下选择 / Enter / Esc、浮层关闭、焦点管理、防重复操作及状态恢复遵循 EXPERIENCE；不以 Toast 替代确认弹窗。
- 视觉与组件继承 DESIGN 及其引用的现有规范；按钮、弹窗、抽屉、Tag、流程图使用 `demo/iteration/component-spec-demo.html` 既有 class。桌面优先，按既有断点四列降两列、一列；保留 200% 缩放可用性、可访问名称、可见焦点、弹窗焦点限制及减少动效支持。
- Demo 使用示例书库表现匹配与异常，未定口径在页面标 `[待确认]`，已定弹窗文案保持原文。新建本 FR 页面，不回改已上线、已归档或他人 FR 页面；规则抽屉只写本 FR，流程指向页内业务流程 Tab，流程图用手写 SVG。

## Non-goals · 非目标

- 真实接口、登录、权限、持久化或写库；书库补全、其他项目新增书库、运营规则引擎。
- 改造第一步项目选择、成片流程选择、上传文件、任务创建或其他业务线工作台。
- 第三步最终提交新增书籍拦截；字段与书库强绑定、覆盖已填内容；书籍类型独立检索入口。
- 独立移动端产品适配；现有外壳的小屏降级仍须保留。

## Success signal · 成功信号

- 回归覆盖海外短剧、海外小说各至少一个正确与未匹配场景：正确可进入第三步，未匹配从第二步进入第三步为 0 次；字节系、知乎系各至少一个异常场景，确认后均可进入第三步。
- 名称 / ID 两入口均验证候选、空态、部分填写补空与手改后重新校验；已填字段被覆盖为 0 次。其他项目本 FR 弹窗为 0 次，第三步本 FR 拦截为 0 次。可访问性及故障状态按 EXPERIENCE 与 CAP-9 演示通过。

## Assumptions · 暂定口径

- `[ASSUMPTION]` 匹配不自动去首尾空格；参与判定字段为空或无对应记录时视为未匹配。
- `[ASSUMPTION]` 书籍类型点选后仍可手改，不被后续点选覆盖；是否参与判定取决于项目规则。
- `[ASSUMPTION]` 查库失败与未匹配分开，包含海外在内均不因故障执行错填拦截；显示系统异常，关闭提示后仍留第二步。本 FR 不定义自动重试次数或新增重试按钮，也不据此承诺故障时自动进入第三步。
- `[ASSUMPTION]` 检索触发算法由实现择优，不设独立延迟指标，以输入后可展示候选或空态验收；成功信号为内部验收口径，不是增长指标。

## Open Questions · 待确认

- 需求单与 PRD Glossary 提到名称 / ID 为主的匹配，PRD FR-5 具体规则与 UX 对照字段则仅比较 ID 或链接：是否还需名称同时完全一致？当前按既定 UX 执行，不擅自增加名称校验。
- 是否自动去掉首尾空格？当前暂不去掉。
- 海外查库失败是否最终允许越过第二步，以及如何继续？当前只确定不按错填拦截、异常关闭后留第二步，未定义故障放行入口。
- 书籍类型点选后是否允许手改？当前暂允许。
