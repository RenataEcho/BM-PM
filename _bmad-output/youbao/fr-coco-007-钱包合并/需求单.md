# 需求单

业务线：右豹主业务

需求名：钱包合并

编号：FR-CoCo-007

照着哪条现有需求做：按桌面 `FR-023-豹钱包与零钱包/leopard-wallet-demo.html` 还原手机画面。外壳场景、规则和流程图按同目录 `fr-leopard-wallet.html`。不改 FR-016 已有页面。

谁在用：在「我的钱包」查看收益、划转和提现的用户。

从哪个入口进来：我的钱包。首页头图是可提现资金，下面入口是总收入、提现账户、收益明细、账单明细、历史余额划转。

接着怎么点：

1. 首页看可提现资金、可划转余额、已提现、已划转，再进总收入、账单或账户。
2. 改版前三个旧钱包的余额从历史划转一次划完。不能选账户，也不能改金额。首次确认弹出协议。
3. 把可划转余额划入可提现资金。当前接口不选实名账户。后端换成钱包应税接口后，划入前要选实名账户。
4. 点提现不新做页面。弹窗写明：使用已经开发的钱包2.0提现页面样式即可。

后台要看什么：

- 表：可提现余额、零钱包、历史可划转；余额动账；收益动账。
- 字段：时间、标题、方向、金额、口袋或分类、动账后余额、备注。历史划转沿用 FR-016 的应税，个人调云账户，对公跳过。

哪些情况不允许：

- 金额为空、为 0 或超出对应余额时不提交。
- 当前接口下，划入不校验实名账户。钱包应税接口下，未选实名账户不能划入。
- 应税失败时，历史余额不扣，可提现不加。
- 新产生的收益不再写入项目、团队、活动三个口袋。

这次不做的：

- 不改 FR-016 已有页面，也不在本页重复演示提现风控文案。提现沿用已经开发的钱包 2.0 页面，本需求不另做提现页。
- 不接真实接口、登录和持久化。Demo 里的 3% 只是示例税额。

还没定的：

- [ASSUMPTION] 收益入账、支出按列表展示。
- [ASSUMPTION] 平台发放等于其他收益，含原活动钱包。
- [ASSUMPTION] 历史划转不再选择个人或对公。Demo 仍按示例税率对全部历史余额扣税，税后进入可划转余额。
- [ASSUMPTION] 扣税只发生在历史划转。若改到划入零钱包，再改这一条。
- [ASSUMPTION] 零钱包不按实名账户拆开。
- [ASSUMPTION] 待结算不能划转，也不能提现。
- [ASSUMPTION] 提现账户页只列已认证实名，到账银行卡仍在提现页选择。
