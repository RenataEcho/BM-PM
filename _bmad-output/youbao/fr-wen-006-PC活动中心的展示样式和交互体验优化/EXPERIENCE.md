# FR-wen-006 · PC活动中心优化

## Foundation

业务线为**右豹主业务**；载体是 PC 客户端，使用者为 PC 客户端所有用户，具体活动可见性仍遵循现有规则。视觉引用 [DESIGN.md](DESIGN.md)，继承右豹 C 端现有 token 和组件，PC 布局适配见其 D-01 至 D-06。

本合同只调整发现、浏览和阅读体验。活动标题、时间、人数、标签、介绍、案例、榜单、奖励结果及按钮均使用现有数据和业务语义，不新增后台、接口字段、登录、权限或持久化。后续 Demo 只用示例状态，不执行真实操作。

本次用户明确要求开始设计，取代需求单早期「仅补充资料」阶段限制。已有 PC 画面和部分线上行为尚待核实，本文为草案；可以评审布局，实施与上线前须完成下文业务待确认矩阵。PC 与移动端的信息一致，不要求布局相同。

## Information Architecture

| 界面 | 入口 | 提供的信息与退出位置 | 需求映射 |
|---|---|---|---|
| 工作台活动区 | PC 工作台首页右侧 | 最多前 3 个活动摘要；点击打开同一详情，关闭返回原工作台 | PRD FR-1、UJ-1 |
| 活动中心 | 服务增长-活动中心 | 四个筛选和所有当前可见活动；保留既有加载方式 | PRD FR-2、UJ-2 |
| 活动详情抽屉 | 工作台摘要或活动卡片 | 基本信息、奖励结果、有效详情 Tab、既有按钮；关闭返回触发位置 | PRD FR-3、UJ-1/UJ-2 |
| 介绍内容 | 详情内介绍 Tab（有效时） | 最多 6 个有效模块连续阅读，富文本及已有链接 | PRD FR-3 |
| 案例内容 | 详情内案例 Tab（有效时） | 各案例标题、图片和视频，动作依现有能力 | PRD FR-3 |
| 榜单内容 | 详情内榜单 Tab（开启时） | 配置数量内的名次、头像、脱敏昵称、数值及描述；允许空榜 | PRD FR-3 |

活动详情不是新路由页面，不新增详情面包屑层级或运营配置入口。初始列表筛选为既有默认项；[ASSUMPTION E-01] 若现有无明确默认，则设计预览用「全部」，上线前核实，不据此重置已有用户状态。详情首次打开默认首个按既有前端规则可见的 Tab；全部无有效内容时隐藏整个 Tab 栏，仍显示允许展示的基本信息和现有操作。

本次界面均由 DESIGN.md 的区域表和组件表定义，尚无本 FR 视觉 Mock。既有后台截图只作内容及配置证据，不作为 PC 最终布局稿。

## Voice and Tone

界面文案用中文，直接说明发生了什么和可继续的动作。活动名称、介绍、标签、按钮和奖励结果文案不由本需求改写；不把浏览人数叫报名人数，不把参与人数改为获奖人数。

| 场景 | 文案与约束 |
|---|---|
| 导航/筛选 | 活动中心；全部 / 进行中 / 已结束 / 已参与 |
| 人数 | 「浏览 {既有展示值}」「参与 {既有展示值}」；单位及数字格式沿用移动端口径，不自行求和或改万位精度 |
| 活动区或全部列表为空 | 「暂无活动」；不展示虚拟推荐，不把不可见活动泄露为标题 |
| 单个筛选无结果 | 「暂无符合条件的活动」；可使用原筛选切换，不新增参与入口 |
| 列表失败 | 「活动加载失败，请重试」；保留「重试」操作 |
| 详情失败 | 「活动详情加载失败，请重试」；保留「重试」与关闭 |
| 活动不再可见 | 「该活动暂不可查看」；不显示已无权查看的正文或按钮 |
| 缺少统计数据 | 对缺失项显示「浏览 —」或「参与 —」，不得以 0 代替未知；真实 0 正常展示 |
| 奖励结果 | 只呈现现有返回的中奖/未中奖等文案；关闭配置或尚无结果时不推导状态 |
| 设计待确认 | 文档使用 `[ASSUMPTION]`；后续 Demo 在评审说明层写 `[待确认]`，不伪装成生产错误 |

[ASSUMPTION E-02] 上述通用空态、错误文案为本次体验提案；若 PC 已有同义标准文案则复用。业务生成的空榜和奖励结果文案始终沿用现状。

## Component Patterns

组件名对应 DESIGN.md.Components；颜色、尺寸不在本节另定。

| 组件 | 行为规则 |
|---|---|
| workbench-activities（工作台活动区） | 按经核实的现有可见性、选取和排序展示最多 3 条；不足不补齐。点击摘要打开对应活动。既有导航仍可进入活动中心，不添加新的推荐算法 |
| activity-filter（活动筛选） | 四项单选，切换即使用既有筛选语义更新结果；「已参与」来自现有关系，不由点击或打开详情推算。返回原筛选时保持能力依原 PC；本次至少关闭抽屉不得清除当前筛选 |
| activity-card（活动卡片） | 卡片作为一个可聚焦入口；Enter/Space 或点击打开同一活动，避免 Logo 和标题形成重复焦点。两行摘要截断时完整名称在可访问名称及详情中可读；不依赖 hover 才能打开 |
| project-logo（项目 Logo） | 只读取已核实的项目标识数据；缺失或加载失败用中性占位，活动名仍可打开。多项目来源及显示策略待确认，不默认取第一项、不用活动封面替代 |
| activity-drawer（活动详情抽屉） | 打开时保存来源卡片、筛选及列表位置，焦点移入头部；关闭图标、遮罩、Esc 关闭同一抽屉，返回来源上下文。打开期间背景禁止滚动和交互 |
| activity-summary（详情基本信息） | 完整显示允许展示的标题、开始/结束时间、人数、标签、封面；封面缺失不影响阅读。项目关联、所属平台/赛道等后台字段不因有值就新增公开展示；活动描述仅已有规则允许时显示 |
| activity-tag（活动标签） | 多个标签按既有顺序展示并换行；非交互标签不获得键盘焦点、不变成筛选条件 |
| reward-result（奖励结果） | 在现有配置开启、现有状态有结果且允许展示时出现；不新增领取动作，不根据榜单名次本地计算中奖。结果不存在不补「未中奖」 |
| detail-tabs（详情 Tab） | 只有原有有效介绍、案例或开启的榜单才显示对应项；不补空壳介绍/案例。选择 Tab 只切正文，不重载整抽屉、不改活动。切换时正文回到该内容起点，键盘焦点留在所选 Tab |
| introduction-content（活动介绍） | 按有效模块配置顺序连续呈现；后台编辑子 Tab 不外露。长富文本不折叠为摘要；图文、表格、链接保持内容完整。链接目标与打开方式沿用现有行为 |
| case-group（活动案例） | 按现有下发顺序展示标题及媒体；保留图/视频类型。图片点击查看、视频播放控件和跳转均继承已核实的现有能力，不因截图显示缩略图就新增灯箱、下载或自动播放 |
| ranking-list（榜单） | 开关关闭时不显示 Tab；开启但无数据时保留 Tab 并呈现现有空榜文案。列表数量、名次、头像、脱敏昵称、数值、小字和周期描述照原数据，不重排名、不去脱敏、不新增领奖 |
| detail-actions（详情按钮区） | 最多 2 个，顺序、文案、主次、目标与动作沿用现状。跨 Tab 是否可见依 Q-05 核实结果：若仅介绍显示则其它 Tab 无按钮区；若所有 Tab 显示则保持全部显示。本设计不预先选择分支。无按钮时不加「立即参与」 |
| content-feedback（内容反馈） | 加载、空态、错误分别展示在所属区域；请求失败不冒充空数据。重试仅重试原加载，不触发按钮业务动作。关闭/切换后旧加载结果不得覆盖新活动或新筛选 |

[ASSUMPTION E-03] 非业务交互提案：详情关闭保留列表筛选、滚动与焦点；详情 Tab 切换回内容起点；首次重新打开详情回基本信息与默认有效 Tab。页面刷新、跨活动、重启客户端不承诺保存这些临时状态，不新增持久化。

### 详情信息呈现条件

| 数据/配置 | 呈现条件及边界 |
|---|---|
| 基本信息 | 仅现有可见活动；不从本地日期推导新状态，时间格式与时区跟随现有产品 |
| 活动封面 | 已配置且允许显示；与项目 Logo 是不同信息 |
| 介绍 | 根据现有有效内容下发规则，最多 6 个模块上下接续；不修改后台完整性校验 |
| 案例 | 根据现有完整性与下发规则；未下发的案例不占卡位 |
| 榜单 | 由现有开关及展示数量控制；开启空榜与隐藏是不同状态 |
| 奖励结果 | 由现有开关及用户结果控制；本次不重建奖励计算、发放或领奖流程 |
| 详情按钮 | 原配置及现有状态决定；非跳转按钮点击后文案/状态沿用实际实现，不把点击成功等同于「已参与」 |

## State Patterns

| 状态 | 界面与处理 | 可继续动作 |
|---|---|---|
| 首次加载 | 工作台/活动中心显示与摘要/卡片结构相同的骨架；不把骨架人数写为 0 | 其它既有导航可用 |
| 切换筛选加载 | 保留选中项并标记结果区忙碌；不让旧结果被误认为新筛选已完成 | 可换其它筛选；只展示最后一次选择的结果 |
| 正常、少于 3 条 | 工作台仅显示实际条数；中心按现有分页/加载能力展示 | 打开对应活动 |
| 无可见活动 | 活动区与「全部」显示「暂无活动」 | 既有导航仍可用 |
| 筛选无结果 | 当前选中项不回退；显示「暂无符合条件的活动」 | 切换筛选 |
| 列表失败/离线 | 显示失败和重试；若保留既有缓存，则明确未更新，不能承诺最新数据 | 重试或返回现有导航 |
| 详情加载 | 抽屉框架、关闭和骨架出现；不显示上一活动正文与按钮 | 关闭 |
| 详情失败/离线 | 保留框架、错误文案；不把失败变成无介绍 | 重试或关闭 |
| 活动失效/不再可见 | 停止展示该活动正文和操作，提示暂不可查看；不新增权限系统 | 关闭回原列表；后续更新遵循现有数据行为 |
| 缺 Logo/封面/头像 | Logo 中性占位；缺封面收回区域；头像用现有默认图；不影响名称及详情入口 | 正常阅读 |
| 缺人数/时间 | 人数用 —；时间缺失项用 —，不补日期、0或倒计时 | 正常阅读，实施时核对数据问题 |
| 缺标签/无按钮 | 不显示空标签或空操作栏，不补默认动作 | 正常阅读或关闭 |
| 介绍/案例未配置 | 隐藏对应 Tab；其余有效内容正常显示 | 切换有效 Tab |
| 榜单开启但为空 | 保留榜单 Tab，显示既有空榜状态与文案 | 切其它有效 Tab或关闭 |
| 媒体加载失败 | 只在对应媒体位显示加载失败，不吞掉案例标题与其它媒体；重试能力继承现有媒体组件 | 其它内容仍可读 |
| 奖励无结果/开关关闭 | 不展示结果提示，不解释为未中奖 | 正常阅读 |
| hover/focus/active | 卡片、筛选、Tab、关闭、按钮均有可见反馈；focus 不仅靠颜色 | 键盘与鼠标均可操作 |
| 业务按钮处理中/失败/完成 | 按原按钮组件和业务状态反馈；未核实前不新增完成态或成功承诺 | 继承原有重试/继续行为 |

后续 Demo 不接接口，以上状态用场景切换演示，所有数字、奖励及活动素材注明示例；不把模拟反馈写成真实参与或领奖成功。

## Interaction Primitives

1. 单击或键盘激活摘要/卡片打开右侧详情；不双击、不拖拽，不新增右键菜单。
2. 抽屉锁定背景滚动，头与条件操作区固定，正文独立滚动；Tab 在正文内吸顶。表格只在自身容器横向滚动，页面和抽屉不出现整层横向滚动条。
3. Esc 只关闭最上层。若既有媒体组件有自己的浮层，先关闭媒体层，再次 Esc 才关闭详情；不能一次级联关掉两层。
4. 关闭后恢复触发卡片焦点及列表位置；卡片已消失时焦点回到活动区标题或当前筛选，避免丢到页面顶端。
5. 抽屉打开/关闭沿用已有轻量动效；`prefers-reduced-motion` 下即时显示/隐藏，交互结果相同，不新增奖励庆祝动画。
6. 点击详情按钮、富文本链接执行既有目标行为；是否外部浏览器、新窗口或客户端内页以现有实现为准。非跳转按钮的文案变更不能代替参与判定。

[ASSUMPTION E-04] 遮罩关闭、焦点回归和减少动效是本次非业务体验提案；若现有客户端组件的能力不同，实施前核实并补齐可访问替代方式。阅读详情没有编辑数据，不加离开确认弹窗。

## Accessibility Floor

- 卡片入口具有完整活动名称；Logo/封面与旁边活动名重复时用装饰性替代文本，独立媒体提供现有可用标题或说明。
- 筛选与详情 Tab 具备选中状态和对应面板关系；左右方向键移动同组 Tab，Enter/Space 激活，Home/End 可至首尾。Tab 键进入/离开当前组，不依赖鼠标 hover。
- 抽屉具备对话框语义、可读名称和模态标识；打开后焦点位于头部，Tab/Shift+Tab 限定在当前抽屉或更上层浮层内，背景内容不可聚焦。
- 关闭控制的可访问名称为「关闭活动详情」，按钮及 Tab 点击目标至少 `{spacing.control-h}`。聚焦元素不得被固定头、Tab 或底部操作区遮挡。
- 日期、人数、获奖结果、名次和脱敏昵称不能只由色彩表达；文本对比和品牌按钮大字规则按 DESIGN.md.Colors，不能宣称继承的所有灰色已达 AA。
- 缩放到 200% 时文字重排、名称和操作不裁切；超宽富文本表格提供可聚焦的局部横向滚动区域和说明。图片按比例缩放，长链接允许断行。
- 加载区域使用忙碌状态，加载失败/筛选结果变化可由低干扰状态区播报；不把每条榜单或浏览数字变化都强制朗读。
- 视频字幕、图片替代文本沿用已有内容能力；当前素材能力不明须核验，不能通过新增后台必填字段扩大本需求。

## Key Flows

以下人物是用于走查的示例角色，不新增用户分层或权限。

### UJ-1. PC 用户从工作台发现活动并查看详情。

小林在 PC 工作台处理日常任务，想先了解一条活动再决定是否按既有入口继续。

1. 小林打开工作台，右侧显示经既有规则确定的前 3 个以内活动摘要。
2. 她通过项目 Logo、活动名称和浏览/参与人数辨认活动，点击目标摘要。
3. 同一活动的右侧宽抽屉打开；小林看到完整名称、时间、人数、标签与允许展示的封面。
4. 她阅读奖励结果（存在时），切换有效的介绍、案例、榜单，介绍模块按配置顺序连续呈现。
5. **高潮：**小林在不离开工作台的情况下读清活动内容和时间，能够辨认当前活动真正提供的原配置按钮；她可按原行为继续，也可决定暂不操作。
6. 她关闭详情，工作台仍在原位置，焦点回到目标摘要。

失败分支：摘要加载失败只显示区域失败和重试；详情失败保留关闭及重试，不能显示上一活动。活动已不可见则显示暂不可查看，关闭回工作台。按钮未配置时不补「立即参与」；按钮行为未核实不在设计中造成功态。

### UJ-2. PC 用户在活动中心筛选并比较活动。

小周从工作台进入「服务增长-活动中心」，想比较进行中的活动，并查看自己已参与活动的原有信息。

1. 小周进入活动中心，看到四个筛选及可见活动卡片。
2. 她选择「进行中」，列表按现有状态口径更新；没有结果时保留该选择并明确提示。
3. 她打开一张卡片，阅读完整基本信息，再切换案例或榜单；开启空榜仍显示原空态。
4. **高潮：**小周读完活动后关闭抽屉，原「进行中」筛选、列表位置和卡片焦点仍保留，可以接着比较下一张卡片。
5. 她切换「已参与」，结果来自现有参与关系；刚才查看活动或点击普通详情按钮不会被本次设计自行算作参与。
6. 她打开一条已有参与记录对应的活动查看结果，原配置及结果开关控制提示与按钮，关闭后返回该筛选。

失败分支：筛选切换失败不回退成「全部」也不声称无活动；保留失败提示与重试。快速切换时过期结果不能覆盖当前选中项。目标卡片因现有可见性更新消失时，关闭焦点回到当前筛选，不泄露旧内容。

## Responsive & Platform

尺寸均为 DESIGN.md D-01 的 PC 设计提案；只适配 PC 客户端窗口，不改造移动端产品。

|---|---|
