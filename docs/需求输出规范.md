# 需求输出规范

给项目小伙伴。自己不改文件。每一步把提示词发给这个项目里的助手，等这一步做完再发下一步。

需求名用需求单里的原话，不要另起名字。编号等产品回复，不要自己编。

## 规则

- 业务线先写明，再做设计。只能是「右豹主业务」「导师商务」「企业号」。
- 全局编号是 `FR-0xx`。PRD 正文里的 `FR-1`、`FR-2` 只表示本需求里的第几条。全局号写在 PRD front matter 的 `iteration_id`。
- 新页面另开 `demo/iteration/fr-*.html`。已上线、已归档，或别人名下的页面不改。
- 不另起配色和组件。C 端用 `docs/design/移动端设计规范.md`。迭代外壳用 `docs/design/iteration-shell/`。管理后台用 `docs/design/admin-ui-spec.md`。按钮、弹窗、抽屉、Tag、流程图从 `demo/iteration/component-spec-demo.html` 复制 class。
- 文档和页面用中文。没定的在文档里标 `[ASSUMPTION]`，页面上写 `[待确认]`。
- Demo 不接真实接口、登录、权限和持久化。按钮可点，数据是示例。
- 需求规则抽屉只写当前这条。流程说明只指向页内「业务流程」。流程图手写 SVG，不用 Mermaid。
- 预览只用 `19889`。总览页是 http://127.0.0.1:19889/framework-shell.html 。

冲突时以此为准：已定的 `DESIGN.md` 与 `EXPERIENCE.md`，然后是本需求的 `prd.md`，然后是 Demo。Demo 和设计不一致时，改 Demo。

## 产物

| 产物 | 路径 |
|---|---|
| PRD | `_bmad-output/planning-artifacts/prds/prd-{项目名}-{日期}/prd.md` |
| 视觉 | `_bmad-output/planning-artifacts/ux-designs/ux-{项目名}-{日期}/DESIGN.md` |
| 行为 | 同目录 `EXPERIENCE.md` |
| 需求合同 | `_bmad-output/specs/spec-{slug}/SPEC.md` |
| Demo | `demo/iteration/fr-*.html` |
| 总览登记 | 根目录 `README.md`「迭代需求」表；`demo/iteration/framework-shell.html` 进行中列表 |

每条需求另开当天的文件夹。不要把别的 PRD 改成这条需求。

PRD 必须有这些节：Document Purpose（写清本文件覆盖哪一刀，以及 `FR-n` 和全局 `FR-0xx` 的区别）、Vision、Target User（JTBD、Non-Users、UJ）、Glossary、Features（每条带可验收的 Consequences）、非目标、假设与待决（`[ASSUMPTION]` 索引）。后文用词和 Glossary 一致。已有 Demo 时，在 Purpose 里写出文件名。不要把别的迭代 PRD 并进来。

页头版本写成 `FR-0xx · 需求名 · v1 当前`。以后改版写成 `vN 当前`。

登记时 `data-line`：右豹主业务 `youbao`，导师商务 `mentor`，企业号 `enterprise`。状态只有四种：待开始、开发中、已上线、已暂停。已上线进归档，已暂停进废纸篓。

## 1. 记下需求

先不要做设计，也不要做页面。按 `docs/需求单.md` 的字段记下内容。

```text
这是一条新需求。先不要做设计和页面。
按 docs/需求单.md 的字段把下面内容记下来。业务线只能是「右豹主业务」「导师商务」「企业号」之一，必须先有业务线。需求名用我写的原话，不要改名。编号先空着。

业务线：
需求名：
照着哪条现有需求做：
谁在用：
从哪个入口进来：
接着怎么点：
后台要看什么：
哪些情况不允许：
这次不做的：
还没定的：
```

做完：业务线和需求名已记下，编号仍空着。

## 2. 占号

产品回复 `FR-0xx` 之后再发。把提示词里的 `FR-0xx` 换成真实编号。

```text
这条需求的全局编号是 FR-0xx。先占这个号。
PRD 正文里的 FR-1、FR-2 只表示本需求里的第几条，不要当成全局编号。
不要新开页面，也不要改已有页面。
```

做完：这个号已被这条需求占用，还没有新页面。

## 3. 写 PRD

新开一个对话，使用 `bmad-prd`。

```text
/bmad-prd
为 FR-0xx 写 PRD。业务线是「……」，需求名用需求单里的原话。
按 docs/需求输出规范.md 写到当天的 prd-{项目名}-{日期}/prd.md。
只写这一条需求，不要并进别的 PRD。没定的标 [ASSUMPTION]。
```

做完：当天目录里有 `prd.md`，front matter 的 `iteration_id` 是这个 `FR-0xx`。

## 4. 做设计

新开一个对话，使用 `bmad-ux`。界面是这条需求的主体时做这一步。

```text
/bmad-ux
为 FR-0xx 做设计。业务线是「……」，需求名用需求单里的原话。先按这个业务线设计。
视觉和行为写到当天的 ux-{项目名}-{日期}/DESIGN.md 和 EXPERIENCE.md。
不另起配色和组件。C 端用 docs/design/移动端设计规范.md，迭代外壳用 docs/design/iteration-shell/DESIGN.md，管理后台用 docs/design/admin-ui-spec.md。
```

做完：同一天的 UX 目录里有 `DESIGN.md` 和 `EXPERIENCE.md`。

## 5. 写需求合同

新开一个对话，使用 `bmad-spec`。

```text
/bmad-spec
按这条需求的 PRD 和 UX，写成 _bmad-output/specs/spec-{slug}/SPEC.md。
需求名用需求单里的原话。目录没有就新建。
```

做完：`_bmad-output/specs/spec-{slug}/SPEC.md` 已存在。

## 6. 做 Demo 页

```text
按 docs/ITERATION-FR-GUIDE.md 为 FR-0xx 新建 demo/iteration/fr-*.html。
页头写 FR-0xx · 需求名 · v1 当前。需求名用需求单里的原话。
已有页面不要改。按钮、弹窗、抽屉、标签、流程图从 demo/iteration/component-spec-demo.html 复制 class。
页签只用到的才放：前端交互、管理后台、业务流程。不要为了凑齐页签去改总览左侧的「概览 / 组件规范」。
手机画面嵌在页内，不要新开窗口。详情用右侧抽屉，编辑用中间弹窗，删除先确认。浮层盖在页面上，不要把后面的页面挤窄。
需求规则抽屉分「前端需求」「后台需求」，只写本需求。流程图手写 SVG，不用 Mermaid。一个菱形只问一个问题，驳回画回起点。规则里不写全文流程，写「见本页业务流程」。
不接真实接口、登录、权限和持久化。没定的写 [待确认]。
页面和 DESIGN.md、EXPERIENCE.md 不一致时，改页面。
```

做完：新页面能打开。页头是 `FR-0xx · 需求名 · v1 当前`。右上角「需求规则」只写本需求。用不到的页签没有放。

## 7. 登记到总览

```text
把 FR-0xx 登记两处。
根目录 README.md 的「迭代需求」表加一行，写上业务线。
总览页先切到该业务线，再在进行中列表加一行，data-line 为 youbao、mentor 或 enterprise。
状态用「待开始」或「开发中」。不要编需求名。
```

做完：README 和总览进行中列表都能看到这一行，业务线与 `data-line` 一致。

## 8. 自己点开验收

在项目目录执行：

```bash
python3 -m http.server 19889 --directory demo/iteration
```

然后发：

```text
用 python3 -m http.server 19889 --directory demo/iteration 预览。
打开 http://127.0.0.1:19889/framework-shell.html ，切到这条业务线，从进行中点进 FR-0xx。
核对页头、用到的页签、需求规则抽屉。页签可直接打开：?tab=fe、?tab=admin、?tab=flow。不要打开别的端口。
```

页签也可以直接打开：前端 `?tab=fe`，后台 `?tab=admin`，流程 `?tab=flow`。

做完再对一遍：

- 编号是产品给的，没有自己编
- 用的是新页面，旧页面没有被改
- 总览和 README 都能点到，业务线与 `data-line` 一致
- 页头有编号、需求名和版本，需求规则只写本需求
- 用到的页签都能打开；有手机画面的，画面嵌在页内
- 页头仍是当前业务线；左侧仍是同一组「概览 / 组件规范」

## 9. 提交

确认页面没问题后再发。做完的标准是：总览里能点开这条需求，并且已经推送到约定分支。一次只含这一条需求改过的文件。浏览器下载和本地日志不要加入。

```text
只提交这一条需求改过的文件。浏览器下载和本地日志不要加入。
提交说明用 feat(FR-0xx): 一句话。
```

只改已有页上一句话时，提交说明用 `fix(FR-0xx): 一句话`。只改总览状态、和某一条需求无关时，用 `chore: 一句话`。
