# PRD 草稿：批量传订单

## 1. Document Purpose

定义右豹后台品牌项目批量上传订单、处理、审核和分发的交互与服务边界。页面原型为 `批量传订单/dist/index.html`，需求池交互入口为 `demo/iteration/fr-xiaoyu-004.html`。全局编号为 FR-XIAOYU-004，由产品分配，本文内部条目 FR-1 等不代表全局编号。本需求已获用户授权登记，编号为 FR-XIAOYU-004。

## 2. Vision

让后台人员从一个批量入口提交多份订单表单，明确每份表单所属项目，跟踪处理与审核结果，并由后台将审核通过的订单分发到对应项目订单列表。

## 3. Target User

### JTBD

当运营人员需要导入多个品牌项目订单表单时，希望批量选择文件、逐份确认项目，并在一个列表中处理失败数据、审核和跟进分发结果，以减少逐项目重复导入及人工追踪。

### Non-Users

- 普通品牌项目成员不使用本后台批次管理入口。
- 本需求不改变项目订单详情、订单结算或项目配置流程。

### User Needs

- 能一次选择多个 CSV、XLS、XLSX 表单。
- 文件名可映射项目，无法映射时可以手动单选项目。
- 能一键处理待上传清单，并逐表单查看处理结果。
- 能重传失败表单，且原记录显示新的进度和结果。
- 处理完成后才能审核。审核通过后由后台分流订单。
- 能单独查看分发状态及未审核订单重传前的确认提示。

## 4. Glossary

| 名称 | 定义 |
| --- | --- |
| 表单 | 用户选择的 CSV、XLS 或 XLSX 源文件 |
| 上传批次 | 一个表单及其处理任务、处理结果的记录 |
| 处理完成 | 文件内订单校验完成，可一键审核并分发 |
| 部分失败 | 部分订单上传未成功，或订单与关键词归因关系校验异常 |
| 审核状态 | 对订单批次的业务审核状态，取未审核或已审核 |
| 分发状态 | 服务端将订单写入项目订单列表的任务状态 |

## 5. Features

### FR-1 批量选择与项目映射

运营人员可以一次选择多份支持格式的表单。系统按文件名映射项目；未匹配时操作人员可以在该行编辑并从已有项目中单选一个项目。未完成映射的表单不能提交。每个表单只能关联一个项目。

**Consequences**：有效文件可加入待上传清单；清单逐条提供编辑和删除；一个「一键处理」操作将所有有效表单提交为独立处理任务。

### FR-2 订单处理列表

系统按表单记录文件名、项目、上传时间、处理状态、处理进度、成功/失败数量、订单量、金额和审核状态。处理中表示订单仍在校验，显示实时进度；处理完成显示 100%；处理失败显示异常。状态与进度分别呈现。

**Consequences**：用户可以按文件名、项目、处理状态、审核状态筛选；能下载源文件及失败文件；完成、部分失败、失败和处理中均可区分。

### FR-3 失败表单重传

部分失败、处理失败表示部分订单上传未成功，或订单与关键词归因关系校验异常。用户可下载失败文件查看逐行失败原因并修订后重传。重传任务关联原批次，原列表行显示新进度，完成后更新处理数据及订单统计。

**Consequences**：重传不产生无法追溯的孤立记录；后端按待确认规则合并成功订单并防止重复入库。

### FR-4 审核通过

只有处理完成的表单可以一键审核并发起分发。确认弹窗说明审核后后台按项目分流这一组订单，订单状态更新为已审核。

**Consequences**：处理中、部分失败、处理失败的审核操作禁用；审核动作由服务端校验状态和权限并记录审计。

### FR-5 订单分发列表

每组审核成功的订单表单在分发列表记录一行，展示文件名、项目、分发时间、分发状态、订单状态和编辑操作。分发失败（例如接口报错或已审核订单分流异常）时显示重传；分发成功时编辑单元格为空。若重传校验发现订单审核未完成，显示二次确认。

**Consequences**：分发状态与订单审核状态独立更新；取消二次确认不改变记录；重传结果更新原分发记录。

## 6. 非目标

- 项目映射管理后台、批次批量审核和删除已入库订单。
