# 批量传订单 · 开发说明

## 交付边界

本目录是需求草稿，全局编号为 FR-XIAOYU-004。当前交互页面为本地演示数据，不连接登录、上传存储、任务处理、审核权限、订单库或分发服务。页面内模拟状态仅用于体验交互，不作为接口行为承诺。

## 建议的服务端职责

1. 接收多个表单及每个表单唯一的项目 ID。若前端按文件名匹配项目，后端仍校验项目有效、用户有权操作，并记录文件名、源文件、项目、上传人和创建时间。
2. 为每个表单创建可追踪处理任务，服务端解析 CSV/XLS/XLSX 并返回处理状态、进度、成功行、失败行、订单量、金额及失败原因。
3. 重传失败文件时关联原批次与失败行，保留原始表单、重传文件和处理历史。成功订单按稳定业务键去重，避免重复入库。
4. 仅允许处理完成的批次进入审核。后端再次校验状态、审核权限及并发版本，审核操作具备幂等性并写审计记录。
5. 处理完成的表单允许操作人员一键审核并发起分发。审核成功后创建该表单组的分发记录，后台订单分发服务按已确认的项目 ID 分流订单。即使分发失败也保留该组记录供重传；订单审核状态、分发状态分别维护。
6. 部分失败或处理失败表示部分订单未上传成功，或订单与关键词归因关系校验异常。失败文件需提供逐行失败原因，修订后重传更新原表单批次。
7. 分发失败可能由接口报错或已审核订单分流异常导致。重传更新原分发组，不新增组；若重传前校验发现审核未完成，前端需二次确认，后端仍需执行权限和状态校验。

## 建议数据实体

| 实体 | 关键数据 | 说明 |
| --- | --- | --- |
| 上传批次 | 批次 ID、原文件名、项目 ID、上传人、上传时间、处理状态、进度 | 一份表单对应一个处理批次 |
| 行处理结果 | 批次 ID、源行号、成功/失败、失败原因、订单业务键 | 支持失败文件生成与修订重传 |
| 审核记录 | 批次 ID、审核人、审核时间、审核结果、版本号 | 仅处理完成可审核通过 |
| 分发任务 | 批次 ID、项目 ID、分发状态、重试次数、更新时间 | 与订单审核状态分开存储 |
| 项目订单 | 订单 ID、项目 ID、订单状态、来源批次 | 审核通过后由服务端写入对应项目订单列表 |

## 建议状态

- 处理状态：处理中、处理完成、部分失败、处理失败。
- 审核状态：未审核、已审核。
- 分发状态：待分发、分发中、分发成功、分发失败。
- 进度只描述处理任务推进；失败状态使用异常提示，不用 100% 表示成功。

## 接口评审时需补齐

- 上传创建、任务查询/订阅、源文件下载、失败文件下载、失败行重传、审核通过、分发状态查询/重传的正式接口及鉴权方式。
- 进度推送方式（轮询、SSE 或 WebSocket）、更新频率及任务超时策略。
- 文件大小、行数、编码、表头、公式/合并单元格处理、金额精度、日期与时区、恶意文件和保留周期。
- 文件名到项目的映射规范、别名和歧义解决；页面当前支持操作人员手动单选项目覆盖自动映射。
- 失败重传如何关联原批次、部分成功是否可审核、订单去重键、分发重试与状态回滚。
- 操作审计、并发审核、重复请求、网络中断后的恢复和重复上传处理。

## 验收范围

- 未映射项目时不可提交；手工指定后每个表单只关联一个项目。
- 一键处理将队列中每份表单分别创建任务，列表按服务端状态展示。
- 仅处理完成可审核；确认后由服务端审核并触发项目分流。
- 分发成功编辑为空，失败记录可重传；未审核重传前要求二次确认。
- 重传结果更新原批次/分发记录，源文件、失败原因、处理与分发审计可追溯。
