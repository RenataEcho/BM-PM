组件规范 Design System

迭代需求 Demo 内按钮、文字链、弹窗、抽屉、Toast、流程图，以及需求规则抽屉和Demo 一屏展示的统一规范。所有 FR 页须复用以下 class 与布局，保证全站一致。

Button 文字链 表格操作 确认弹窗 编辑弹窗 详情抽屉 需求规则 一屏展示 Toast Tag 业务流程图

1 · Button 按钮

高度 34px（筛选区 32px）；圆角 7px。主操作每区域仅一个 Primary。

Primary
查询、提交、保存、确认
.btn .btn-primary
Ghost
取消、重置、次要操作
.btn .btn-ghost
Rule
Page Header「需求规则」入口
.btn .btn-rule
Danger
确认弹窗内 destructive 主按钮；慎用大面积使用
.btn-danger / .btn-danger-ghost

4 · 确认弹窗（Confirm Modal）

居中 overlay；宽 400px。删除/撤回/不可逆操作用 Danger 主按钮；可取消操作用 Ghost + Primary。

使用场景
  • 删除等不可逆操作
  • 二次确认提交（如批量操作）
  • 不用于详情/编辑（详情→Drawer，编辑→Modal 表单）

5 · 编辑弹窗（Edit Modal）

居中 overlay；宽 480px。Footer：取消 Ghost + 保存 Primary。Demo 提交后 Toast + 关闭。

6 · 详情抽屉（Detail Drawer）

右侧滑入 overlay；宽 480px。关键词详情、只读 list。不挤压主列表宽度。需求规则用独立抽屉（见下节），不要和详情抽屉共用一份内容。

7 · 需求规则抽屉

Page Header 右上角打开。独立于页内 Tab。Demo 仍在左侧完整可见，便于对照。默认宽 480px。

展示结构

  1. 入口：仅 Page Header 右侧 .btn .btn-rule。打开后按钮加 .active / aria-expanded="true"。
  2. 壳：.drawer-overlay + .drawer.rule。从右侧滑入，不挤压 Demo 宽度。
  3. 顶栏：标题写 FR-0xx · vN 需求规则，与页头编号/版本同步；右侧只有关闭。
  4. 内 Tab：.rule-tab-bar 仅「前端需求 / 后台需求」。打开时按当前页内 Tab 定位：前端交互、业务流程 → 前端需求；管理后台 → 后台需求。
  5. 正文：.rule-section + h3 用 --accent-rule。前端：业务目标、页面与入口、交互规则、边界规则、业务流程（只写「见本页业务流程」）。后台：业务目标、数据表与字段、列表与筛选、边界规则。
  6. 滚动：抽屉 flex 列；Header / Tab 不滚，.drawer-body 独立滚。
  7. 关闭：关闭钮、遮罩、Esc、再次点「需求规则」。关闭后 Demo 可继续点。

同屏对照

  1. 遮罩半透明，Demo 整页仍看得到。不要改成全屏文档站，也不要用角标浮窗替代抽屉。
  2. 遮罩打开时 Demo 不可点，避免抽屉和表格同时操作。这不是阻断阅读，只挡误点。
  3. 规则只写当前 FR。不写 Sidebar 架构、全局组件说明、Swagger。
  4. 不在抽屉里嵌流程图或复述文字版全流程。图只在页内「业务流程」Tab。
  5. 内容特别长、双栏对照时可用 .drawer.wide（720px）。默认不要开到 960px。
class：.btn-rule .drawer.rule .rule-tab-bar .rule-panel .rule-section。正文结构见 ITERATION-FR-GUIDE.md 第五节。

高度与滚动

  1. Chrome 钉住：Sidebar、面包屑、Page Header、页内 Tab 占视口顶部。经验高度约 188px（页头描述最多两行）。
  2. Demo 台吃剩余高度：#view-fe.page-view.active { height: calc(100vh - 188px); min-height: 560px; display: flex; flex-direction: column; }
  3. 内部分层：.demo-layout { flex: 1; min-height: 0; }；.scene-panel { flex-shrink: 0 }；.mockup-board { flex: 1; min-height: 0; overflow: hidden }；.board-scroll { overflow: auto }。
  4. 后台 Tab：表区域 min-height: calc(100vh - 188px)；.table-wrap { overflow: auto }。详情抽屉 overlay，不把表顶出视口。
  5. 流程 Tab：.flow-svg-wrap { max-height: 72vh; overflow: auto }。图在面板内滚，不要靠 body 滚。

前端交互（模板 B）

  1. 默认 上场景 / 下手机墙，或 左场景 / 右手机（≥1280px 约 5:7）。一屏内必须同时看到场景列表和至少一台完整手机。
  2. 多场景：点场景按钮把对应手机滚进 .board-scroll，不要让整页跳走。
  3. C 端 Mockup 用页内 iframe：?embed=1&screen=。不提供「新窗口打开」作为主入口。
  4. 手机画布逻辑宽 390px；iframe 画 375×812，按框做 transform-origin: 0 0 缩放。

硬限制

  1. 不要让 body 跟着 Demo 变长：评审要滚整页才能看到手机，算不合格。
  2. 不要把场景说明写成大段把 Demo 台顶出视口；长说明放需求规则。
  3. 不要在 Demo 台外再挂第二份手机或后台表。
  4. 打开需求规则后 Demo 仍完整露在左侧，不要改成规则独占一屏。
改完用 1280×800 视口目视：不滚 body 就能点场景、看到一台完整手机、打开需求规则后 Demo 仍在。
参考实现：fr-alias-bind.html、fr-creator-home-2-opt.html 的 #view-fe 高度写法。

11 · 业务流程图（SVG Flow）

FR Demo「业务流程」Tab 的研发对照图。默认一张图闭环；拆第二张是例外。手写 SVG，正交折线。

结构与色板

默认一张图走完：提交 → 写入 → 审核分支，驳回闭环回到起点。能在本图闭环就不要再拆第二张。菱形只问一个是/否。

前端 / 操作 后端 / 写入 异步 / 任务 校验 / 分支 阻断 / 驳回
容器：.flow-page .flow-tab-bar .flow-svg-wrap .flow-edges .flow-nodes .flow-legend
前端 / 操作 后端 / 写入 异步 / 任务 校验菱形 阻断 / 驳回 跳过 / 中性

实现要点

  1. 分层渲染：先画 flow-edges，再画 flow-nodes。连线层在下，避免折线横穿线框。
  2. 正交折线：只用水平 / 垂直 line 或 polyline。分叉与汇聚走节点间隙的专用通道，禁止斜线穿框。
  3. 端点落边：折线起止落在节点顶 / 底 / 左 / 右边，悬空端点视为断流。
  4. 能闭环就只用一张图：主路径、校验分支、驳回/失败回环能画进同一张 SVG 并接到起点，则只保留一个业务流程，不要预置流程 2。只有两条互不汇合的主链（例如收益达标 vs 指定用户），或单图闭环后通道必然打架、线穿框、节点被裁切时，才启用第二张，并用横向 Tab 切换。
  5. 闭环：驳回、失败、重提必须接到起点顶边。回环走外侧通道，禁止贴画布边缘停住（看起来像断线）。
  6. 间距：相邻节点纵向 ≥24px；菱形与上下节点 ≥30px；左右分支框与菱形顶点 ≥16px。
  7. 一菱形一问题：菱形只问一个是 / 否。判定公式、口径、比较符写在菱形内或紧邻副文案，禁止把「收益达标」合成一步。
  8. 文本：主文案 11–13px；副文案 10px + muted。超 12 字用 tspan 换行，线框留足内边距。
  9. 分支标注：「是 / 通过」贴对应折线旁用绿色；「否 / 驳回」用红色。
  10. 多图才出 Tab：仅在按上条拆出第二张时才出现 .flow-tab-bar，单面板只展示一张，禁止纵向堆叠。图例仍放面板底部共用。只有一张图时不要空挂「流程1」。
  11. 画布可滚：.flow-svg-wrap { overflow:auto; max-height:72vh }。svg 写死 width + viewBox，窄屏横向滚，不重排。
  12. 箭头 id 隔离：每张 SVG 独立 marker id（如 flow-arrow-1），同页复用同一 id 会串箭头。
  13. 虚线旁路：可选、汇总、异步旁路用 stroke-dasharray="4 3"。
  14. 深链：?tab=flow；仅多图时再加 &flow=1|2|3。
  15. 规则抽屉只指向：写「见页内业务流程 Tab」，不在抽屉里复述文字版全流程，也不嵌第二份图。

硬限制（做不到 / 不要做）

  1. 手写绝对坐标，无布局引擎。移动或加高一个节点，必须重算所有相连折线与通道；改一处容易漏改边。
  2. 无自动避让。折线不会绕开节点，线穿框是最高频事故。先定节点框，再对端点。
  3. 菱形是写死 polygon。改文案不能只改 height，必须重算四个顶点，否则字溢出。
  4. SVG 文本不自动折行。超长必须手写 tspan，不会像 HTML 那样 wrap。
  5. viewBox 写死。加节点必须同步加大 width / height / viewBox，否则节点被裁切。
  6. 不做响应式重排。窄屏只横向滚动，不会像 Grid 那样回流节点。
  7. 静态图，不交互。节点不能点、不能高亮当前态、不跟 Demo 表数据联动。
  8. 拆图是例外，不是默认。优先扩画布、走外侧回环，把同一条业务画闭环。只有确认无法在一张图内闭环（互不汇合的第二条主链，或闭环后必然线穿框 / 通道打架）才拆流程 2。禁止因为「节点有点多」就先拆。
  9. 不表达并发与时序。并行、等待、超时只能靠橙色节点或虚线示意，没有泳道 / 甘特。
  10. 色值写死 hex。未接 CSS 变量，也没有暗色主题适配。
  11. 禁用 Mermaid / 流程图库。颜色、正交通道、分层渲染、图例对不齐，视觉不可控。
  12. 不进抽屉、不进规则正文。第二份图会和页内 Tab 漂移。
  13. 不接真实状态机。图是研发说明，不驱动后台表状态，也不做权限 / 持久化。
新增或改流程图时：先改节点框，再对折线端点；有驳回 / 失败必须画回环并接到起点边。改完用 ?tab=flow 目视检查：无线穿框、无悬空端点、无贴边假断线。
新 FR 从本页复制结构与色板，不要另起 Mermaid 或自定义连线样式。完整写入约定见 ITERATION-FR-GUIDE.md 第四节。
