关键词状态查询流程

配置关闭时不展示入口；后端校验覆盖状态、单次数量、更新次数、每日额度与并发重复请求。

开发说明

一、入口与布局

  1. 读取后台「是否可查询关键词」配置，为是时展示入口，为否时隐藏。
  2. 查询词状态、排序、筛选与全收起同一行，不遮挡原有操作。
  3. 卡片右上角保留置顶、收起；更新标签放在卡片底部。

二、选择与提交

  1. 根据后端返回的可操作状态展示勾选项，底部展示已选数量、取消、更新；未选择时更新禁用。按接口返回的当日剩余额度限制勾选，超出部分禁止勾选，取消已选项后可改选。
  2. 取消清空本次选择；更新提交关键词标识，等待后端返回。
  3. 前端不展示每词次数、每日额度、上限规则或限制配置，不自行承担业务限制校验。
  4. 按接口逐词展示受理结果，未受理项保留此前的更新状态；更新中重复操作显示「关键词正在更新中，为避免数据异常请勿操作」。

三、状态与字段

  1. 原关键词状态完整保留六种状态。
  2. 更新状态独立展示更新中、更新成功、更新失败，由接口结果驱动。
  3. 成功展示接口返回的更新时间，不用客户端提交时间代替。

一、项目配置

  1. 编辑项目新增「是否可查询关键词：是 / 否」；持久化并提供给前端，默认为空，仅配置为「是」时展示入口。
  2. 接口必须校验用户权限与项目配置，防止绕过入口提交。

二、业务限制

  1. 仅允许审核成功待发布、已发布的关键词。
  2. 单次最多 20 个关键词。
  3. 单个关键词最多更新 3 次，达到上限禁止更新。
  4. 单个用户每天最多更新查询 50 个关键词，跨项目合计。
  5. 更新中不接受重复请求，返回规定提示。
  6. 计次、每日额度和更新中状态须原子校验与写入，防止并发超限；重复提交需幂等处理。

三、异步结果与接口内容

  1. 提交返回受理结果或拒绝原因；列表提供入口配置、可操作状态、更新状态与成功更新时间。
  2. 接收接口推送结果，更新成功 / 失败；成功保存接口时间戳。
  3. 重复或乱序回调按本次请求标识幂等处理，避免覆盖较新的结果。

四、计次与批量结果

  1. 每发生一次已受理的更新计 1 次，更新失败仍计次。同词更新 3 次计 3 次，提交未受理不计次。
  2. 每日额度在 23:59:59 重置，单词累计次数不随每日额度重置。
  3. 批量提交按接口逐词返回结果，可部分受理、部分拒绝。额度不足时返回原因及受理、未受理数量；额度已用完时提示额度重置后再试。仅受理项进入更新中。
  4. 配置默认为空，仅配置为是时展示入口。成功更新时间按接口时间戳展示为年月日和时分秒。
