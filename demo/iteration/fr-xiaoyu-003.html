开发说明

前端交互

  • 操作人员可一次选择单个或多个表单，在临时清单确认项目和文件后，通过一个「一键处理」入口提交全部表单。
  • 按文件名映射项目；无法映射时，操作人员可为单条表单从已有项目中单选项目。
  • 一键处理后每个表单在订单处理列表独立显示。处理中表示订单仍在校验，进度跟随后台校验结果更新。
  • 仅处理完成表单提供「一键审核分发」；审核成功后后台按项目分流。部分失败、处理失败可下载带逐行失败原因的表单并重传，重传进度和结果更新原记录。
  • 分发列表按每个审核成功表单组记录一行，展示分发成功或失败。成功行编辑为空，失败行提供重传并更新原组。
  • 若分发重传前校验发现订单审核未完成，先显示二次确认；取消不改变记录。

待确认

文件名映射规则、失败表单重传时成功订单的合并与去重策略、未审核重传确认的触发条件与权限文案。

需求单交互约定界面说明

后端职责

  • 校验文件、项目映射结果、项目权限和每个文件独立任务，保存源文件与上传审计。
  • 解析 CSV/XLS/XLSX，返回成功与失败数据、订单量、金额、失败原因及可查询的校验进度。
  • 部分失败、处理失败需区分上传失败与关键词归因校验异常，并为失败行返回可读原因。
  • 仅处理完成表单可进入一键审核分发；审核通过后按项目 ID 分流整组审核成功订单。
  • 分发列表按表单组记录一行，只有审核成功订单表单进入列表。审核状态与分发状态独立维护。
  • 接口报错或订单分流异常造成分发失败时支持重传，关联并更新原分发组，保证幂等。
  • 若重传校验发现审核未完成，后端返回状态供前端二次确认；服务端仍需重新校验权限和状态。

待研发评审

上传及任务接口、进度推送方式、文件解析规则、订单去重键、失败行格式、审核幂等、分发重试与审计字段。

规范状态

复用需求池组件示例中的按钮、状态标签、表格和弹窗模式。工作区未提供正式后台 UI 规范文件，视觉合规需在规范补齐后复核。
